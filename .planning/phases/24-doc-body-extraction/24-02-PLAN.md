<objective>
Wire the pure extraction core (Plan 01) into the live upload path so an uploaded
document's body is extracted, chunked, and embedded as linked memory_items — while
guaranteeing the upload itself is never affected.

Purpose: close DOCBODY-01's delivery half. `media.py` currently embeds only the
caption; this plan adds an `extract_and_ingest_body` service and calls it AFTER the
object + parent card item are committed (D-24-01), fire-and-forget, so the 201 stays
snappy and any extraction failure is invisible to the uploader. Body chunks inherit
the upload's team_scope + 7-field tagging (D-24-02) and back-link to the MinIO object.

Output: `doc_body_ingest.py` service + the media.py wiring + unit tests proving
linkage/inheritance/fail-soft against a fake provider. The real Postgres+Qdrant
keyless retrieval proof is Plan 03.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upload request (authed, team-scoped) → background ingest | The detached task carries the uploader's team_scope into every chunk write |
| chunk items → memory_items/Qdrant | Body chunks become first-class, retrievable brain items |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-06 | Information disclosure / Elevation | body chunk landing under the wrong team_scope | mitigate | Chunk team_scope is INHERITED verbatim from `team_scope` (the get_team_scope-enforced value on the upload); never derived, never defaulted. Unit test asserts every chunk item's team_scope == the upload's. provider.upsert filters retrieval by team_scope, so a mis-scoped write would be the only leak vector — closed at construction. |
| T-24-07 | Denial of Service | extraction latency / crash blocking the upload | mitigate | Body ingest runs in a detached `asyncio.create_task` AFTER the 201-path commits; `_run_body_ingest` and `extract_and_ingest_body` both never-raise (try/except). The object + card item are already stored — a failed/slow ingest cannot affect the upload response. |
| T-24-08 | Tampering | crafted doc drives unbounded upserts | mitigate | Chunk count is capped (`DOCBODY_MAX_CHUNKS`) and text is truncated (`DOCBODY_MAX_TOTAL_CHARS`) upstream in doc_extract; the loop cannot exceed the cap. |
| T-24-09 | Repudiation | silent no-text-layer swallow | mitigate | no_text_layer sets an explicit `no_text_layer:true` flag on the parent metadata (auditable) rather than a silent no-op; `media.body_ingest_failed` warnings are logged with structlog. |
| T-24-10 | Denial of Service / cost | new external call or embedding key required | accept (no-op) | No new external call: chunks embed via the SAME keyless local provider the upload already uses (get_memory_provider). Zero new key. |
</threat_model>
