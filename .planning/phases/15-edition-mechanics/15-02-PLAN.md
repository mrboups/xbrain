One image, two editions — plus the one bug this phase *creates*.

**Editions (EDIT-02):** add a validated `EDITION` flag to `Settings` and gate memory-api's routers on it
**additively and explicitly** (D-15-05): name the always-on core routers, name the SaaS-only ones, and
make a forgotten router a **test failure** rather than a silent leak.

**The bug this phase creates:** `memory.py` enqueues `neo4j_outbox` rows whenever a caller supplies
`metadata.entities`. Today Neo4j is always up, the drain loop empties the table, and nobody notices. The
moment OSS-light becomes the default, those rows are written and **nothing will ever drain them** —
unbounded Postgres growth, in the default install, silently. Close it by gating on the **live driver**,
which is the same signal the drainer uses.

Purpose: EDIT-02, and a Neo4j-less install that does not quietly grow a dead table forever.
Output: `create_app()` + a two-list router registry + the negative-case tests + the outbox guard.

**The governing fact:** locked decision **Q6 / D-15-01** dropped the paid tier, the Ed25519 license and
requirement EDIT-03. **Nothing in the product is paywalled.** The only closed surface is the *hosted
control plane* — billing, multi-tenant provisioning, trial caps. So the question is never "is this
feature premium?" (no feature is). It is only: **"is this router meaningless without the hosted control
plane?"** Almost nothing is.

**The default is CORE.** We fail *open* on features and never on data isolation: a self-hoster who loses
a capability they should have had is a silent product regression they cannot debug; a SaaS-only route
accidentally mounted in an OSS install is inert (no hosted backend, no billing table, no Resend key).
