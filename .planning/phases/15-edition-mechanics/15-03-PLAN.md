## The trap that governs this entire plan

**A service with no `profiles:` tag ALWAYS runs.** The OSS-light baseline is defined by the *absence*
of a tag, so **forgetting a service is not a no-op — it silently ships it.**

This is not hypothetical. Research applied an earlier, incomplete version of the table to the real file
and ran it through the real `docker compose` binary: the bare core came out at **15** services instead
of 10, silently booting `librechat-mongo`, `librechat-meili`, `librechat-bridge` and
`openwebui-pipeline` — most of the LibreChat/Open-WebUI machinery minus the two frontends themselves.

Therefore: **every one of the 32 services must be explicitly accounted for below.** Assert by *count
and by name*, never by eyeballing.

## Prerequisite from 15-01 (already landed — verify before starting)

`docker compose config -q` must exit 0 and Compose's resolved graph must show **zero** of these edges:
`memory-api→neo4j`, `brain-janitor→neo4j`, `xbrain-backup→librechat-mongo`. If any survives, adding
`profiles:` makes the whole file unparseable and every check below fails with
`depends on undefined service`. **Do not start until 15-01's acceptance passed.**
