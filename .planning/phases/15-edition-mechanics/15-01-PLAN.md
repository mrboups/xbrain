<objective>
Make the Compose dependency graph **profile-safe** and promote MinIO into the untagged core.

This is the Wave-0 prerequisite for the whole phase. Docker Compose forbids an enabled service from
`depends_on`-ing a service that is not enabled, and it does not fail softly: `docker compose config`
**aborts the entire project** (`service "X" depends on undefined service "Y": invalid compose project`).
Until every such edge is gone, applying `profiles:` in 15-03 makes the compose file **unparseable** —
`docker compose config --profiles` cannot even list the profile names, and nothing else in Phase 15
can be verified.

Purpose: unblock 15-03, and close the "promised-core capability with an opt-in backend" hole.
Output: a compose file whose `depends_on` graph is legal under the 15-03 profile table, and a single
core `minio` service serving both memory-api media/decks and (when `integrations` is on) Langfuse.
</objective>

# LibreChat lives in the `saas` compose profile (Phase 15). An OSS-light or `ops`-only install has
# no Mongo at all, so this step must SKIP rather than abort the whole backup (set -e would otherwise
# take the Postgres + Qdrant steps down with it). We retry first, so that a *deployed* Mongo that is

if [ -z "${LIBRECHAT_MONGO_URI:-}" ]; then
  echo "  → SKIP: LIBRECHAT_MONGO_URI unset (LibreChat not deployed)"
else
  MONGO_OK=0
  for attempt in 1 2 3; do
    if mongodump --uri="${LIBRECHAT_MONGO_URI}" --gzip --archive="${MONGO_ARCHIVE}"; then
      MONGO_OK=1
      break
    fi
    echo "  … mongodump attempt ${attempt}/3 failed; retrying in 10s"
    sleep 10
  done
  if [ "${MONGO_OK}" = "1" ]; then
    echo "  → $(du -h "${MONGO_ARCHIVE}" | cut -f1)"
  else
    rm -f "${MONGO_ARCHIVE}"

  fi
fi
