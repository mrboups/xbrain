## Section 1 — Goal

Wire the app-site `account/teams/` sign-in UI to the new install-flow UX from RESEARCH §Q8:
1. When `POST /v1/auth/github/signin` returns `install_required: true`, the page renders a yellow banner with a primary button "Install xbrain on `{org}`" linking to `install_url`.
2. After the user installs (clicking the button opens GitHub's install consent flow), GitHub redirects back to `https://example.com/account/teams/?installation_id=<id>&setup_action=install`. The page must detect these query params and:
   - Auto-retry the team-membership check (single GET to `/v1/me/teams` using the still-valid `xbt_` from the earlier sign-in response).
   - On success, dismiss the banner and proceed to the normal teams view.
   - On still-`install_required` (shouldn't happen but defensively): show a "retry" link.
3. Banner copy in English (per CLAUDE.md product-strings rule).

This plan touches ONLY frontend JS + HTML. No memory-api changes.

### Task 2 — Wire install banner in teams.js

**File(s):** `app-site/account/teams/teams.js`

**What:**

1. **Handle the sign-in response** — locate the existing block that parses `POST /v1/auth/github/signin` response (the response object). After successful sign-in (xbt_token stored), inspect `install_required` + `install_url` fields. If true:
   ```javascript
   function showInstallBanner({ installUrl, orgLogin }) {
       const banner = document.getElementById('install-banner');
       const button = document.getElementById('install-banner-button');
       const orgSpan = document.getElementById('install-banner-org');
       if (!banner || !button || !orgSpan) return;
       orgSpan.textContent = orgLogin || 'your organization';
       button.href = installUrl;
       banner.removeAttribute('hidden');
   }

   function hideInstallBanner() {
       const banner = document.getElementById('install-banner');
       if (banner) banner.setAttribute('hidden', '');
   }
   ```

   After the existing sign-in success path (where you set `localStorage.setItem('xbt_token', ...)`):
   ```javascript
   if (signinResponse.install_required && signinResponse.install_url) {
       // REVISION 2 (M-1 fix) — memory-api now returns the primary org name in
       // `org_login`. Plan 12-06's SigninGithubOut schema exposes:
       //   { install_required: bool, install_url: str|null, org_login: str|null, ... }
       showInstallBanner({
           installUrl: signinResponse.install_url,
           orgLogin: signinResponse.org_login,
       });
       // Do NOT redirect to the teams list — user must install first.
       return;
   }
   hideInstallBanner();
   ```

2. **Handle the post-install redirect** — at page load, BEFORE any sign-in button rendering, inspect `window.location.search` for `installation_id` + `setup_action=install`:
   ```javascript
   async function handlePostInstallRedirect() {
       const params = new URLSearchParams(window.location.search);
       if (params.get('setup_action') !== 'install') return false;
       const xbt = localStorage.getItem('xbt_token');
       if (!xbt) return false; // no prior signin — let the normal signin flow run

       // Retry team membership now that the install webhook should have populated installations row.
       // Note: the webhook is best-effort, but find_installation_for_org's hybrid lookup will backfill.
       try {
           const r = await fetch(`${MEMAPI_URL}/v1/me/teams`, {
               headers: { 'Authorization': `Bearer ${xbt}` },
           });
           if (r.ok) {
               // Clean up the install query params from the URL so a refresh doesn't re-trigger.
               const cleanUrl = window.location.pathname;
               window.history.replaceState({}, '', cleanUrl);
               hideInstallBanner();
               return true; // caller continues to render teams list
           }
       } catch (_e) { /* fall through to banner-still-visible */ }
       return false;
   }
   ```

   Call `await handlePostInstallRedirect()` at the top of the existing DOMContentLoaded handler (before the sign-in button wires up). If it returns `true`, skip the sign-in button rendering (the user is already signed in, just refresh the teams view).

## Section 4 — Risks + Mitigations

- **REVISION 2 (M-1 fix) — RESOLVED: `org_login` field now in SigninGithubOut.** Plan 12-06 adds `org_login: str | None` to the response. Plan 12-07 banner consumes it via `signinResponse.org_login`. If the field is null (org not install-required for some reason), the banner falls back to "your organization" via `orgLogin || 'your organization'` in `showInstallBanner`.
- **Risk: `URLSearchParams` not supported in older browsers.** Mitigation: app-site already requires modern browsers (LibreChat dependency). No polyfill needed.
- **Risk: `xbt_token` from the previous sign-in expired between sign-in and post-install redirect.** Mitigation: rare (xbt_ tokens are long-lived per Phase 5). If expired, `/v1/me/teams` returns 401 → handler returns false → normal sign-in flow re-runs. User sees the sign-in button again (acceptable edge case).
- **Risk: `localStorage.getItem('xbt_token')` returns null because the page was cleared between signin and install.** Mitigation: handler returns false → normal sign-in flow runs. User must sign in again — acceptable; install retry is a quality-of-life feature, not a correctness one.
- **Risk: install_url contains a malformed state.** Mitigation: state comes from memory-api which already validated it via the sign-in flow. Re-using it in install_url is safe (it's the same trust boundary). If GitHub rejects, the user sees GitHub's error and can retry sign-in.
- **Risk: banner DOM slot collides with an existing #install-banner ID.** Mitigation: grep first — `grep -c "install-banner" app-site/account/teams/index.html` should return 0 BEFORE edit. If non-zero, choose a different ID (e.g. `xbrain-install-banner`).
