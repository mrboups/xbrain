## Section 4 — Risks + Mitigations

- **Risk: operator pastes a malformed client_id (typo, trailing newline).** Mitigation: Section 0 + Task 1 acceptance both grep for the `^Iv23li\|^Ov23li` pattern. The browser will fail with `redirect_uri_mismatch` or `invalid_client` on sign-in if wrong.
- **Risk: stale browser cache serves the old teams.js with the old client_id.** Mitigation: app-site's deploy pipeline (Firebase hosting per recent commits) issues a new bundle hash on deploy; service worker / browser cache invalidates on hash change. Mention in 12-11 UAT: "test in Incognito to bypass cache".
- **Risk: legacy OAuth App `xbrain` still installed in user's `dejavudev` org's "Authorized OAuth Apps" list.** Mitigation: out of scope (operator revokes via github.com/settings/applications per Plan 12-10). Until revoked, the OAuth App stays valid but unused — no functional impact.
- **Risk: other files reference `Ov23liy7tZekl0uEztoj` (e.g. docs, KB, comments).** Mitigation: full-repo grep in the verify step. KB references can stay (they're historical); code references must be migrated.
- **Risk: teams.js source-map references the old value.** Mitigation: not a real risk for a non-bundled script (app-site/teams.js is served as-is). If a future bundler is added, regenerate after this change.
- **REVISION 2 (B-4 + MINOR-4) — Risk: executor reads "Execute Plan 12-11 first" wording and halts.** Mitigation: Section 0 no longer references Plan 12-11 as a wave-prerequisite; the operator pre-step (export env var) is the actual gate. Verified format check covers MINOR-4 (env-var ambiguity).
