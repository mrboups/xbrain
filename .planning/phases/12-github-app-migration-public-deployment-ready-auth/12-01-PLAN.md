**File(s):** `apps/memory-api/alembic/versions/0019_github_app_install.py`

In `upgrade()`:

1. **`installations` table — NEW** (source of truth for "which orgs have installed the xbrain GitHub App"; populated by webhook handler in Plan 12-05):
   - `installation_id BIGINT PRIMARY KEY` (GitHub's numeric installation id — fits in BIGINT comfortably; INT also fine but BIGINT is future-proof).
   - `github_org_login TEXT NOT NULL` — the org account login (e.g. `dejavudev`).
   - `github_account_type TEXT NOT NULL DEFAULT 'Organization'` — `'Organization'` or `'User'` (GitHub Apps can install on user accounts too; we always expect Organization for xbrain but capture it).
   - `installed_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
   - `installed_by_github_id BIGINT NULL` — the GitHub user id of the admin who clicked Install.
   - `permissions JSONB NOT NULL DEFAULT '{}'::jsonb` — snapshot of granted permissions from webhook payload.
   - `suspended_at TIMESTAMPTZ NULL` — set on `installation.suspend` webhook.
   - `revoked_at TIMESTAMPTZ NULL` — set on `installation.deleted` webhook (soft-delete; do not DROP row so historical refs survive).
   - `raw_payload JSONB NOT NULL DEFAULT '{}'::jsonb` — last webhook payload, for debugging.
   - `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
   - **Indexes:** `CREATE UNIQUE INDEX idx_installations_org_login_active ON installations (github_org_login) WHERE revoked_at IS NULL` (lookup by org with the active-only constraint).
   - **CHECK constraint:** `CHECK (github_account_type IN ('Organization', 'User'))` named `installations_account_type_check`.

2. **`users` table — ADD 4 columns** (encrypted user tokens for user-to-server flow):
   - `github_access_token_enc TEXT NULL` — Fernet-encrypted `ghu_…` user-to-server token.
   - `github_refresh_token_enc TEXT NULL` — Fernet-encrypted `ghr_…` refresh token.
   - `github_token_expires_at TIMESTAMPTZ NULL` — when the access token expires (now + 8h on issue).
   - `github_refresh_expires_at TIMESTAMPTZ NULL` — when the refresh token expires (now + ~6mo on issue).
   - **Index:** none — looked up by `id` PK or `github_id` (already indexed); the columns are read on a per-user basis.
   - **Why encrypted (`_enc` suffix):** per RESEARCH §Security V8 — Fernet-encrypted at rest using the same `FERNET_KEY` env that drive-sync already uses (Phase 4). Plan 12-06 implements encrypt/decrypt helpers.
   - **Naming:** the `_enc` suffix is mandatory so future readers can tell at a glance the column is encrypted bytes (Fernet base64), not raw token text. Decrypted plaintext is never stored at rest.

In `downgrade()`:
- Reverse order: `DROP TABLE installations CASCADE`; then `ALTER TABLE users DROP COLUMN github_refresh_expires_at`, `..._expires_at`, `..._refresh_token_enc`, `..._access_token_enc`.

**REVISION 2 NOTE:** Plan 12-06 Task 1b extends this `upgrade()` with `github_access_token_hash` column + partial index, and the corresponding drops in `downgrade()`. The diff is small and localized to the `users` ALTER block — see Plan 12-06 for exact edits.

**Why:** GHAPP-03 (installations table) + GHAPP-05 (user token storage). Encrypted-at-rest per V8 ASVS. The `WHERE revoked_at IS NULL` partial unique index enforces "only one active install per org" — matches GitHub's behavior (re-installs delete-then-create with a new installation_id; the old row remains as audit).

```python
"""Installation ORM — one row per GitHub App installation (per org).

Source of truth is GitHub; this table is populated and updated via the
/v1/webhooks/github/installation handler (Plan 12-05). Reads are scoped
by github_org_login or by installation_id.

The row is NEVER hard-deleted: installation.deleted webhooks set revoked_at
so historical references (audit, FK from users etc. future) survive.
"""
from datetime import datetime
from typing import Any

from sqlalchemy import BigInteger, CheckConstraint, Index, String, func
from sqlalchemy.dialects.postgresql import JSONB, TIMESTAMP
from sqlalchemy.orm import Mapped, mapped_column

from app.db.base import Base


class Installation(Base):
    __tablename__ = "installations"
    __table_args__ = (
        CheckConstraint(
            "github_account_type IN ('Organization', 'User')",
            name="installations_account_type_check",
        ),
        Index(
            "idx_installations_org_login_active",
            "github_org_login",
            unique=True,
            postgresql_where="revoked_at IS NULL",
        ),
    )

    installation_id: Mapped[int] = mapped_column(BigInteger, primary_key=True, autoincrement=False)
    github_org_login: Mapped[str] = mapped_column(String(256), nullable=False)
    github_account_type: Mapped[str] = mapped_column(String(32), nullable=False, default="Organization", server_default="Organization")
    installed_at: Mapped[datetime] = mapped_column(TIMESTAMP(timezone=True), server_default=func.now(), nullable=False)
    installed_by_github_id: Mapped[int | None] = mapped_column(BigInteger, nullable=True)
    permissions: Mapped[dict[str, Any]] = mapped_column(JSONB, nullable=False, default=dict, server_default="{}")
    suspended_at: Mapped[datetime | None] = mapped_column(TIMESTAMP(timezone=True), nullable=True)
    revoked_at: Mapped[datetime | None] = mapped_column(TIMESTAMP(timezone=True), nullable=True)
    raw_payload: Mapped[dict[str, Any]] = mapped_column(JSONB, nullable=False, default=dict, server_default="{}")
    updated_at: Mapped[datetime] = mapped_column(TIMESTAMP(timezone=True), server_default=func.now(), nullable=False)
```

## Section 4 — Risks + Mitigations

- **Risk: `GITHUB_API_PAT` removed from config.py before Plan 12-04 runs.** Mitigation: this plan KEEPS the setting declared (deprecated comment only). Removal is Plan 12-04's task — clearly assigned in the comment.
- **Risk: existing `.env` files on the VM use `GITHUB_ORG_PAT` (not `GITHUB_API_PAT`).** Mitigation: `.env.example` comment instructs operators to migrate the value to `GITHUB_API_PAT` before Plan 12-04 ships. Plan 12-11 (verify script) double-checks the VM `.env` parses cleanly.
- **Risk: Fernet key (`FERNET_KEY`) is not configured on the VM.** Mitigation: the encryption helper itself is added in Plan 12-06; this plan only declares the columns as nullable so a missing Fernet key cannot break the migration. Plan 12-06's pre-flight checks `settings.FERNET_KEY` and raises a clear error before the first encrypt.
- **Risk: BIGINT for `installation_id` mismatches GitHub's actual type.** Mitigation: GitHub returns installation ids as JSON numbers fitting in INT32 today, but BIGINT is safe and matches `github_id` (already BIGINT in users — migration 0014). Round-trip via `int()` in Python is lossless.
- **Risk: partial unique index syntax differs across Postgres versions.** Mitigation: project pins PG 17 (per docker-compose.yml + STACK.md); `WHERE` clause on `CREATE UNIQUE INDEX` is supported since PG 7.2. No version branch needed.
- **Risk: ORM model file naming collides with `app/services/github_installation.py` planned in 12-03.** Mitigation: the model is at `app/models/installation.py` (singular) — different directory. No collision.
- **REVISION 2 (M-3) — Risk: user.py drifts and DateTime import disappears.** Mitigation: pre-task gate fails hard before edit; acceptance check fails hard after edit.
- **REVISION 2 (forward-dep) — Risk: 0019 deployed to VM between Plan 12-01 and Plan 12-06.** Mitigation: Plan 12-06 Section 0 has fallback to migration 0020 (additive) if 0019 is already applied.
