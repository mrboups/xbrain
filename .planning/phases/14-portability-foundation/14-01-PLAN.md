<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env → memory-api/mcp-brain Settings | `.env`-supplied OAUTH_ISSUER_URL / OAUTH_RESOURCE_URL cross into token-minting (issuer) and audience-check (resource) logic |
| memory-api (Authorization Server) → mcp-brain (Protected Resource) | issued `oat_` tokens carry an `aud` bound to OAUTH_RESOURCE_URL; mcp-brain independently checks it (RFC 8707) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Spoofing | OAUTH_ISSUER_URL / OAUTH_RESOURCE_URL empty-default | mitigate | Unconditional `field_validator` on BOTH Settings classes raises at `Settings()` construction (boot) — no silent wrong-issuer/wrong-audience. Block-on: high. |
| T-14-02 | Tampering | mcp-brain `_PROTECTED_RESOURCE_METADATA_URL` (module-import-time `urlparse("")`) | mitigate | Validator runs at config import (before main.py imports the constant) → the malformed `"://.well-known/..."` string is never constructed; boot crashes instead. |
| T-14-03 | Information Disclosure | notifications.py email footer / dashboard link leaking `grooveos.app` to other operators' users | mitigate | Footer + link sourced from `settings.SMTP_FROM` / `settings.APP_PUBLIC_URL`; neutral defaults reveal only the operator's own configured domain. |
| T-14-04 | Elevation of Privilege | RFC 8707 `aud` binding weakened if OAUTH_RESOURCE_URL is empty-but-tolerated | accept (defense-in-depth) | `oauth_verify.py` already fails closed on `aud` mismatch; the new validator makes empty impossible at boot. Documented as defense-in-depth, not a new control (14-RESEARCH.md Security Domain). Cross-service consistency (both services' env) enforced in Plan 14-03. |
</threat_model>
