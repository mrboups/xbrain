<objective>
Build the server side of push-a-link: a single endpoint that lets one team member
nudge another member of the SAME team to open a URL, by publishing a targeted
`open_url` event to the target's existing `user:<source_user_id>` Centrifugo channel.

This is the security core of the phase (SC#1 + SC#2). The endpoint validates that
BOTH sender and target are members of the same team, validates the URL scheme
server-side, rate-limits per sender, and only then publishes. It NEVER server-side
fetches or expands the URL (no SSRF), and NEVER derives the target channel from a
client-supplied channel name — the channel is keyed by the target's
`source_user_id` resolved server-side from a verified membership.

Purpose: without a validated, same-team-only publish path, the whole feature is a
notification-spam / cross-team-leak vector. This plan closes that.
Output: `POST /v1/teams/{team_id}/nudge-open`, a pure URL guard, and a REAL-Postgres
gate test that captures the publish (SKIP=FAIL).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension/browser → memory-api | Untrusted request body crosses here: `target_user_id`, `url`. Neither may steer the publish channel or scheme. |
| memory-api → Centrifugo | Server publishes to a channel it derives server-side; the client subscribes under a server-enforced channels claim. |
| sender's message → target's channel | A message from user A must only reach a user B who shares a team with A. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Tampering/Elevation | nudge-open route channel selection | mitigate | Channel is `user:<target.source_user_id>` resolved via get_user_by_id + get_membership; the request body never names a channel. Client-supplied channel names are structurally impossible. |
| T-22-02 | Information disclosure/Elevation | target authorization | mitigate | get_membership(target.id, team.slug) is None for non-members AND for a different team's member → 403, publish never scheduled. |
| T-22-03 | Injection (script/URI) | url field | mitigate | is_safe_nudge_url rejects javascript:/data:/file:/mailto:/malformed → 422 before any publish. |
| T-22-04 | Info disclosure (SSRF) | url handling | mitigate | Purely lexical validation; NO server-side fetch/DNS/shortener-expansion (D-22-03). url_safety.py imports no network client (grep-asserted). |
| T-22-05 | Denial of Service (notification spam) | per-sender flood | mitigate | check_rate(NUDGE_RATE_LIMIT, "nudge", sender_sub) → 429; bucket keyed by sender sub, not IP. |
| T-22-06 | Repudiation | who sent the nudge | mitigate | Event carries from.display_name + from.sub so the recipient (and the notification) shows the real sender. |
| T-22-07 | DoS (in-process limiter is 2x under --workers 2) | rate_limit backing store | accept | Documented in rate_limit.py; spray-blunting only. A hosted multi-replica deployment would need Redis; out of scope for this OSS-default phase. |
</threat_model>
