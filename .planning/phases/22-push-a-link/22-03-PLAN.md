<objective>
Wire the two halves together and add the send affordance (SC#3 delivery half, SC#4
doc, D-22-05). The popup subscribes to its own `user:<sub>` channel (already granted
by the centrifugo-token endpoint) and hands every `open_url` event to Plan 02's
`handleOpenUrl`. The notification's CLICK — an explicit user gesture — is what opens
the tab, handled in the background service worker so it survives popup teardown. A
small "send link to a member" control in the chat popup lets a member target a
teammate + URL and POST the Plan 01 endpoint.

Purpose: close the loop end-to-end while keeping the consent gate intact — the tab
only ever opens from a click, never from the incoming event itself.
Output: popup user-channel routing, background click→tab handler, the send affordance,
and docs/push-a-link.md (including the offline residual).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| incoming open_url event → tab open | The gap between "notification shown" and "tab opened" must require an explicit human click. |
| popup send affordance → memory-api | The affordance is just a client of the Plan-01 endpoint; all authorization/validation is server-side (target membership, scheme, rate limit). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-12 | Elevation (silent navigation) | notification → tab | mitigate | tabs.create lives ONLY inside chrome.notifications.onClicked; the popup routing never opens a tab. The click is both the consent gate and the browser-required user gesture (grep-asserted: no tabs.create in the popup nudge path). |
| T-22-13 | Tampering (bypass server checks) | send affordance | mitigate | The affordance sends only {target_user_id, url}; the server re-resolves membership + re-validates the scheme + rate-limits (Plan 01). Client isSafeHttpUrl is UX-only, not the security boundary. |
| T-22-14 | Info disclosure (stale pending url) | chrome.storage.session nudge_<id> | mitigate | The key is removed immediately after the tab opens (and session storage is cleared when the browser session ends); no long-lived url store. |
| T-22-15 | Availability (closed browser) | live-only delivery | accept | Documented residual (D-22-06): Centrifugo is live-only; offline delivery is a named follow-up, not promised this phase. |
</threat_model>
