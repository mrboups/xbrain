<objective>
Build the extension's RECEIVE path for push-a-link as a pure, node-testable module,
plus the recipient opt-out toggle. This is the consent core on the client (SC#3
handler half + SC#4 opt-out).

The handler `handleOpenUrl(data, deps)` deliberately has NO access to
`chrome.tabs` — it can only create a notification. That makes "never auto-open a
tab from another user's message" (D-22-02) a structural guarantee, not a
convention: the code that could open a tab is not even reachable from the event
handler. The actual tab-open is wired to an explicit notification CLICK in Plan 03.

Purpose: prove — in a plain `node` test, no jsdom — that an incoming nudge shows a
notification with the real URL and opens nothing, and that the recipient's opt-out
suppresses it entirely.
Output: `nudge_open.js`, the `allowOpenLinkRequests` setting (default ON), and two
node tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Centrifugo `user:<sub>` event → extension | Incoming event data is attacker-influenced (the sender chose the url + display text). |
| incoming nudge → recipient's browser | Must not move the recipient's browser (open a tab) without an explicit gesture. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-08 | Elevation (unwanted navigation) | handleOpenUrl | mitigate | The handler has no tabs capability at all (grep-asserted absence of "tabs"); it can only create a notification. Auto-open is structurally impossible. |
| T-22-09 | Tampering (unsafe scheme reaches user) | isSafeHttpUrl guard | mitigate | Client re-validates http/https via `new URL`; a javascript:/data:/file: event is dropped with no notification (defense-in-depth over the server check). |
| T-22-10 | Repudiation / social-engineering | notification content | mitigate | Notification shows the sender (from.display_name/sub) as title and the FULL literal url as message — the recipient sees exactly who and exactly where before deciding. |
| T-22-11 | Nuisance / consent withdrawal | recipient opt-out | mitigate | allowOpenLinkRequests OFF makes the handler return before notifying; the recipient's own extension enforces it (client-only for v1, per D-22-04 discretion — noted in SUMMARY). |
</threat_model>
