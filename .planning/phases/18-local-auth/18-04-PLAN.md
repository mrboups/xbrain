Recommended endpoint shape (18-RESEARCH.md Open Question 3 — one endpoint that branches):
```python
class SetPasswordBody(BaseModel):
    new_password: str = Field(min_length=settings.LOCAL_AUTH_MIN_PASSWORD_LENGTH, max_length=1024)
    old_password: str | None = None

async def set_password(body, principal=Depends(get_current_principal), session=Depends(get_session)):
    user = _require_user_any(principal)
    row = await local_credentials_repo.get_by_user_id(session, user.id)
    if row is None:                                   # FIRST ATTACH (GitHub/Google/local user, no pw yet)
        await local_credentials_repo.upsert(session, user_id=user.id, password_hash=hash_password(body.new_password))
    else:                                             # CHANGE — require + verify current password
        if not body.old_password or not verify_password(row.password_hash, body.old_password):
            raise HTTPException(400, "Current password is incorrect.")
        await local_credentials_repo.update_hash(session, user.id, hash_password(body.new_password))
    await session.commit()
    return {"status": "ok"}
```
Requiring old_password on CHANGE closes the "hijacked session silently locks out the real owner" gap
(18-RESEARCH.md OQ3). This endpoint lives in auth_local.py (Plan 03 created it) — hence wave 3, depends_on 18-03.
