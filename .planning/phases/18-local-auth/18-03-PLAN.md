Login decoy/lockout shape (18-RESEARCH.md Pattern 2):
```python
email = body.email.strip().lower()
row = await local_credentials_repo.get_by_email(session, email)
if row is None:                                      # absent account
    verify_decoy(body.password); raise HTTPException(401, "Invalid email or password.")
if row.locked_until and row.locked_until > utcnow(): # locked
    verify_decoy(body.password); raise HTTPException(401, "Invalid email or password.")
if not verify_password(row.password_hash, body.password):
    await local_credentials_repo.record_failure(session, row.user_id)
    await session.commit(); raise HTTPException(401, "Invalid email or password.")
await local_credentials_repo.reset_failures(session, row.user_id)
if needs_rehash(row.password_hash):
    await local_credentials_repo.update_hash(session, row.user_id, hash_password(body.password))
xbt = await mint_xbt_for_user(session, row.user_id, name="local-login")
await session.commit()
return {"xbt_token": xbt, "user": {...}}
```

that identity is a tested acceptance criterion, not prose. NEVER return a distinct status/message
for "locked" vs "wrong password" (that is a second enumeration oracle — 18-RESEARCH.md Anti-Pattern).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (untrusted) → POST /v1/auth/local/{register,login} | Untrusted email+password crosses here; the only anonymous write surface of the phase |
| register/login → get_current_principal (xbt_) | The minted token re-enters as a bearer credential on every later call; must be indistinguishable from a GitHub/Google-minted xbt_ |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-03-01 | Spoofing | account takeover via cold register on a victim's known email | mitigate | Existing-email register -> 409, no token, no row (D-18-05); convergence only via the authenticated set-password path (Plan 04) — proven by test_register_collision_409 |
| T-18-03-02 | Information Disclosure | user enumeration via response difference | mitigate | Byte-identical generic 401 for absent / wrong / locked; asserted by test_no_enumeration_oracle |
| T-18-03-03 | Information Disclosure | user enumeration via timing | mitigate | verify_decoy() argon2 verify on every short-circuit branch (Pattern 2) |
| T-18-03-04 | Elevation of Privilege | brute force / credential stuffing | mitigate | DB lockout after N failures (durable, cross-worker) + in-process per-IP rate limit (coarse); proven by test_lockout_then_recovery |
| T-18-03-05 | Tampering | partial writes if the multi-step register is not atomic | mitigate | Single transaction, ONE commit; create_team called DIRECTLY (never the self-committing HTTP route) |
| T-18-03-06 | Elevation of Privilege | a local xbt_ authorizing differently from a social xbt_ (route special-case) | mitigate | Zero changes to deps.py; the existing xbt_ branch resolves it; proven by test_local_xbt_authorizes_team_route hitting a real team route |
| T-18-03-07 | Information Disclosure | registration-endpoint enumeration (409 reveals the email exists) | accept | Industry-normal for registration flows (GitHub/Google/Slack all do it); low-value oracle, covered by the same rate limiter; locked by D-18-05 |
</threat_model>
