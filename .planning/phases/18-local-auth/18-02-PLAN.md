argon2-cffi API (18-RESEARCH.md Q1, https://argon2-cffi.readthedocs.io):
```python
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError, VerificationError, InvalidHashError
ph = PasswordHasher()                       # RFC_9106_LOW_MEMORY defaults — DO NOT override m/t/p
encoded = ph.hash("pw")                      # -> "$argon2id$v=19$m=65536,t=3,p=4$<salt>$<digest>"
ph.verify(encoded, "pw")                     # True, or raises VerifyMismatchError on wrong pw
ph.check_needs_rehash(encoded)               # bool
```

limits API (18-RESEARCH.md Q3 — LOW confidence on exact kwargs; spot-check against
limits.readthedocs.io before finalizing):
```python
from limits import parse
from limits.storage import MemoryStorage
from limits.strategies import MovingWindowRateLimiter
_storage = MemoryStorage()                   # pure-Python, no Redis/Memcached pulled in
_limiter = MovingWindowRateLimiter(_storage)
_limiter.hit(parse("10/minute"), "login", key)   # -> False when the budget for that key is exhausted
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plaintext password (in memory) → argon2 hash | The only place a plaintext password is handled; it must never leave this boundary as anything but an argon2id hash |
| client IP → rate limiter | Untrusted, spoofable behind a proxy; a coarse-but-cheap first line, not the durable control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-02-01 | Information Disclosure | password hashing | mitigate | argon2id via argon2-cffi shipped defaults (memory-hard, timing-safe verify, self-describing) — never a bare SHA, never hand-rolled (D-18-04) |
| T-18-02-02 | Information Disclosure | login timing side-channel | mitigate | `verify_decoy()` burns comparable argon2 CPU on the account-absent branch (Pattern 2); consumed by the login route in Plan 03 |
| T-18-02-03 | Elevation of Privilege | brute force via per-process limiter bypass under `--workers 2` | accept (documented) | In-process limiter is a coarse first line; the durable defense is the DB lockout (Plan 01). Redis is out of scope (D-18-06). Caveat documented in rate_limit.py |
| T-18-02-04 | Spoofing | reusing the hardcoded 'github-signin' token name for local tokens | mitigate | Parameterized `name` ('local-register'/'local-login') so audit/telemetry can distinguish origin |
