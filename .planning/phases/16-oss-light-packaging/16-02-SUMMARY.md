- Fixed the Phase-15 `.env.example` drift (D-16-05): four explicit sections — `[REQUIRED — core boot]`, `[OPTIONAL — one LLM key]`, `[OPTIONAL — integrations profile]`, `[OPTIONAL — saas profile]` — so an operator reading the file literally fills only the core secrets to boot the 10-service OSS-light core.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Single-quoted CORS_ALLOWED_ORIGIN_REGEX so a generated zero-key .env passes env-check**
- **Found during:** Task 3 (behavioral env-check test)
- **Issue:** The plan's oss-init spec emits `CORS_ALLOWED_ORIGIN_REGEX=(chrome-extension://.*|http://localhost(:\d+)?)` unquoted. `env-check` runs `source .env`, and bash reads `VAR=(...)` as an **array assignment** — the leading `(` triggers `syntax error near unexpected token '|'` and the var ends up empty. A freshly generated zero-key `.env` therefore FALSELY failed `env-check` on CORS (rc=1), directly defeating the plan's own behavioral acceptance ("COMPOSE_PROFILES= make env-check exits 0").
- **Fix:** Emit the value single-quoted in both `oss-init.sh` and `.env.example` (`CORS_ALLOWED_ORIGIN_REGEX='(...)'`). Verified: bash `source` now reads the value intact, and `docker compose --env-file` strips the quotes on interpolation (10 core services still resolve; the regex reaches memory-api unquoted and correct).
- **Files modified:** infrastructure/scripts/oss-init.sh, .env.example
- **Verification:** `source`-then-check of the generated env → `COMPOSE_PROFILES=` exits 0; `COMPOSE_PROFILES=saas` exits 1 naming GOOGLE_CLIENT_ID. `docker compose config` shows `CORS_ALLOWED_ORIGIN_REGEX: (chrome-extension://.*|http://localhost(:\d+)?)`.
- **Committed in:** `9507ac3` (Task 3 commit)

## Issues Encountered
- **`make` not installed in the dev Git-Bash environment.** The Task-3 behavioral acceptance calls for `COMPOSE_PROFILES= make env-check` / `COMPOSE_PROFILES=saas make env-check`. `make`/`mingw32-make`/`gmake` are absent on this host, so the behavioral check was run by executing the recipe's make-expanded shell body directly (`$(COMPOSE_PROFILES)` substituted with the command-line literal, `$$`→`$`) — byte-identical to what `make` runs, but without the `make` binary. The structural acceptance (grep-based) passed against the real `Makefile`. Plan 04's `verify-phase16.sh` is the designated non-destructive gate for the real `make env-check` path.
- **Pre-existing:** sourcing a FULLY saas-populated `.env` in bash would also trip on other unquoted special-char values (`CENTRIFUGO_ALLOWED_ORIGINS` has a space, `WAITLIST_FROM` has `<...>`). These are in the optional saas/integrations sections, out of this plan's env-check path (a core install does not set them), and pre-existing — logged here, not fixed (SCOPE BOUNDARY). A future hardening could quote them or switch env-check to a non-sourcing parser.
