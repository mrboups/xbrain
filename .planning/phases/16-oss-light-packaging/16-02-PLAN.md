<objective>
Fix the Phase-15 `.env.example` drift (D-16-05) so an operator reading the file literally can
boot the OSS-light core with zero external keys and never hit a silent core-service crashloop.

Two verified defects (16-RESEARCH.md Pitfalls 3-4): (a) MinIO was promoted to the untagged core
in Phase 15 but its credential block still sits under a stale `=== SaaS-only / not part of
OSS-light ===` header with `MINIO_ROOT_PASSWORD` tagged `[optional]` — yet the `minio` core
container refuses to start with a root password under 8 chars, so "[optional] = leave blank"
crashloops it; (b) the "Required — minimal boot" section conflates the 10-service core with
LibreChat/Open WebUI `saas`-only secrets (MEILI/JWT/CREDS/MONGO/PIPELINE...), so an operator
fills 15+ vars they don't need.

Restructure `.env.example` IN PLACE into clear sections and add `oss-init.sh` — the lowest-friction
"docs alone" secret-generation bootstrap that emits a bootable zero-key `.env`.

Purpose: SC#1/SC#2 — the OSS-light core must boot from the shipped template with no source reading.
Output: A correctly-sectioned `.env.example`, a `make oss-init` generator, both consumed by the
install docs (Plan 03) and the clean-install gate (Plan 04).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator filesystem → generated .env | secrets minted here become every container's identity |
| .env → container environment | crashloop / weak-secret exposure crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-02-01 | Tampering / Elevation | generated secrets | mitigate | `oss-init.sh` uses `openssl rand` (CSPRNG) + Fernet.generate_key for every secret — never fixed or `__FILL__` placeholder values; Plan 04's gate asserts generated values differ from placeholders |
| T-16-02-02 | Denial of Service (crashloop) | MINIO_ROOT_PASSWORD | mitigate | generate 32 hex chars (>> MinIO's 8-char floor) and document `[required]` in the core-boot section — prevents the silent `minio` crashloop from an empty/short value |
| T-16-02-03 | Information Disclosure | .env in VCS | accept | `.env` is already gitignored; oss-init writes `.env`/target only, never commits; docs warn |
| T-16-02-04 | Spoofing (CORS) | CORS_ALLOWED_ORIGIN_REGEX | mitigate | oss-init emits the anchored localhost/chrome-extension default (never `.*`); `app/config.py::_reject_wildcard_cors` blocks a wildcard at boot as defense-in-depth |
</threat_model>
