<objective>
Fix the connector OAuth-Authorization-Server zero-key blocker (D-16-02). Today
`GET /oauth/authorize` (`oauth_authorize.py:128-138`) unconditionally redirects the
ChatGPT-web / Claude.ai connector sign-in into GitHub OAuth using
`settings.GITHUB_APP_CLIENT_ID`. On a zero-external-key install that value is empty, so
the connector's sign-in leg 302s to `https://github.com/login/oauth/authorize?client_id=&...`
which GitHub rejects — the exact gap `docs/local-auth-recovery.md` flagged as D-18-07 and
Phase 16 SC#3 requires closing.

Add a local-auth branch: when GitHub is not configured, render a local email/password login
form and verify it against the Phase-18 credential store, converging into the SAME
`_finalize_consent()` the GitHub leg already uses. Keep the GitHub path byte-unchanged when a
GitHub App IS configured.

Purpose: SC#3 requires "connects via the ChatGPT-web connector" with zero external keys.
Output: A local-auth sign-in leg for the OAuth 2.1 AS, fully reusing Phase 18's argon2id
verification and the existing signed-state / PKCE code-issuance machinery — wiring, not new crypto.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → GET /oauth/authorize | untrusted connector sign-in entry (client_id, redirect_uri, PKCE) |
| browser → POST /oauth/authorize/local | untrusted email/password + signed state — the new authN surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01-01 | Spoofing | POST /oauth/authorize/local | mitigate | `verify_password` (argon2id) against `local_credentials`; honor `locked_until`; no code minted before credential proof — no auth bypass |
| T-16-01-02 | Information Disclosure | local login error path | mitigate | single generic "Invalid email or password." for absent/locked/wrong + `verify_decoy` timing equalizer — no user-enumeration oracle (mirrors auth_local.py T-18-03-02) |
| T-16-01-03 | Tampering (CSRF) | POST /oauth/authorize/local | mitigate | require + `_verify_state` the HS256 `state` (stage=pre_github, 10-min TTL, iss check) carried as a hidden field; reject absent/expired/foreign |
| T-16-01-04 | Spoofing (open redirect) | 302 after consent | mitigate | redirect_uri read ONLY from the signed state, never the form; `is_redirect_uri_registered` re-checked in `_finalize_consent` before the 302 |
| T-16-01-05 | Elevation (horizontal) | team binding | mitigate | user_id comes from the credential lookup, never the form; `_finalize_consent` `get_membership` enforces membership; auth code bound to (user_id, team_scope); multi-team fork mints NO code until the consent page selects one team |
| T-16-01-06 | Elevation (brute force) | POST /oauth/authorize/local | mitigate | reuse `enforce_rate_limit(LOCAL_AUTH_RATE_LIMIT)` + `record_failure`/lockout — same 5-attempt lockout as login |
| T-16-01-07 | Tampering (regression) | GitHub redirect path | accept | branch is `if not settings.GITHUB_APP_CLIENT_ID`; when set, the GitHub 302 is byte-unchanged (test asserts) — additive, not a replacement |
</threat_model>
