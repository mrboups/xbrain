# Plan 04-02 — mcp-gateway : endpoint `/mcp/aggregate`

## Goal

Exposer un serveur MCP agrégé sur `mcp-gateway` qui présente l'union des tools de tous les sidecars enregistrés comme un unique serveur MCP — ce qui permettra à LibreChat de pointer vers une seule URL.

## Context

**Contrainte technique confirmée** : le commentaire en tête de `apps/mcp-gateway/app/main.py` confirme que FastMCP NE PEUT PAS être monté dans une FastAPI parent (issue #1367). La gateway est volontairement un proxy HTTP, pas un host FastMCP.

**Décision d'architecture (D-03)** : LibreChat v0.8.5 supporte `streamable-http` comme transport MCP. Il pointe vers `http://mcp-gateway:8080/mcp/aggregate`. La gateway doit donc exposer ce endpoint comme un serveur MCP complet.

**Solution retenue** : Option C (processus FastMCP séparé dans le même container) — **un second process FastMCP lancé via `multiprocessing` au démarrage de la gateway, sur le port 8081**. Ce process implémente un serveur MCP "façade" qui :
1. Au démarrage, appelle `GET http://mcp-gateway:8080/tools` pour découvrir les tools enregistrés.
2. Pour chaque tool, génère dynamiquement un `@mcp.tool()` callable qui redirige vers `POST http://mcp-gateway:8080/tools/{name}/call`.
3. Expose le tout sur `http://0.0.0.0:8081/mcp` (transport streamable-http).
4. Toutes les 60s, re-découvre les tools pour voir les nouveaux enregistrements.

**Pourquoi pas Option B (JSON-RPC manuel)** : implémentation fragile, incompatible avec les futures versions du SDK MCP. L'Option C est plus robuste et réutilise le SDK officiel.

**Port 8081** : port distinct du gateway FastAPI (8080). LibreChat et le nginx pointent vers 8081. Un nginx upstream `mcp-aggregate` sera exposé comme `/mcp/aggregate` extérieurement (mapping dans le plan 04-03).

**Auth côté agrégateur** : le process FastMCP agrégateur reçoit les requêtes LibreChat avec header `X-Team-Scope` et `X-LibreChat-User-Email`. Il injecte un bridge JWT + `X-Team-Scope` dans l'appel `POST /tools/{name}/call` vers la gateway. La résolution `email → sub` se fait en appelant `GET http://memory-api:8000/v1/me` avec le token LibreChat (pattern identique à librechat-bridge).

### T-04-02-01 — Créer `apps/mcp-gateway/app/aggregate.py` (serveur FastMCP façade)

**File**: `apps/mcp-gateway/app/aggregate.py`
**Action**: create

**Changes**:

```python
"""MCP Aggregate Server — exposes all registered gateway tools as a single MCP server.

Runs as a separate process (multiprocessing) inside the mcp-gateway container.
Port 8081 — distinct from the FastAPI gateway (port 8080).

Architecture note: FastMCP cannot be mounted inside a parent FastAPI app (issue #1367).
Running as a separate process avoids the asyncio event-loop conflict.

Tool discovery: polls GET /tools on the gateway (port 8080) every REFRESH_INTERVAL_SECS.
Tool dispatch: for each tool call, POST /tools/{name}/call on the gateway.
Auth injection: uses BRIDGE_SHARED_SECRET to mint a bridge JWT for each call.
team_scope: extracted from X-Team-Scope header on each incoming MCP request.
"""
from __future__ import annotations

import asyncio
import os
import time
from typing import Any

import httpx
import structlog
from mcp.server.fastmcp import FastMCP

log = structlog.get_logger(__name__)

GATEWAY_URL = os.environ.get("GATEWAY_INTERNAL_URL", "http://127.0.0.1:8080")
REFRESH_INTERVAL_SECS = int(os.environ.get("MCP_AGGREGATE_REFRESH_SECS", "60"))
BRIDGE_SHARED_SECRET = os.environ.get("BRIDGE_SHARED_SECRET", "")
HOST = os.environ.get("FASTMCP_AGGREGATE_HOST", "0.0.0.0")
PORT = int(os.environ.get("FASTMCP_AGGREGATE_PORT", "8081"))


def _mint_bridge_jwt(team_scope: str) -> str:
    """Mint a short-lived bridge JWT for gateway calls."""
    from authlib.jose import jwt as authlib_jwt
    now = int(time.time())
    payload = {
        "iss": "mcp-aggregate",
        "sub": "mcp-aggregate",
        "scope": "bridge",
        "team_scope": team_scope,
        "iat": now,
        "exp": now + 300,  # 5 min — aggregate calls are fast
    }
    token = authlib_jwt.encode({"alg": "HS256"}, payload, BRIDGE_SHARED_SECRET)
    return token.decode("ascii") if isinstance(token, bytes) else token


def _discover_tools() -> list[dict]:
    """Synchronously fetch tool list from gateway. Returns [] on error (graceful)."""
    try:
        r = httpx.get(f"{GATEWAY_URL}/tools", timeout=10.0)
        r.raise_for_status()
        return r.json()
    except Exception as exc:
        log.warning("aggregate.discover_error", error=str(exc))
        return []


def _build_tool_caller(tool_name: str):
    """Return an async callable that dispatches to gateway POST /tools/{name}/call."""
    async def _call(**kwargs: Any) -> str:
        team_scope = getattr(_current_team_scope, "value", "default")
        jwt = _mint_bridge_jwt(team_scope)
        payload = {
            "jsonrpc": "2.0", "id": 1, "method": "tools/call",
            "params": {"name": tool_name, "arguments": kwargs},
        }
        async with httpx.AsyncClient(timeout=60.0) as client:
            resp = await client.post(
                f"{GATEWAY_URL}/tools/{tool_name}/call",
                json=payload,
                headers={
                    "Authorization": f"Bearer {jwt}",
                    "X-Team-Scope": team_scope,
                    "Content-Type": "application/json",
                },
            )
            resp.raise_for_status()
            data = resp.json()
        # Extract text content from MCP CallToolResult format
        contents = data.get("content", [])
        return "\n".join(c.get("text", str(c)) for c in contents if c) or str(data)
    return _call


# Thread-local-like context var for team_scope (set per request via middleware)
import contextvars
_current_team_scope: contextvars.ContextVar[str] = contextvars.ContextVar(
    "_current_team_scope", default="default"
)


def build_mcp_server() -> FastMCP:
    """Build a FastMCP server with tools discovered from gateway."""
    mcp = FastMCP("xbrain-aggregate", host=HOST, port=PORT)
    tools = _discover_tools()
    log.info("aggregate.tools_discovered", count=len(tools))
    for tool_info in tools:
        name = tool_info.get("tool_name", "")
        desc = tool_info.get("description", f"MCP tool: {name}")
        if not name:
            continue
        caller = _build_tool_caller(name)
        caller.__doc__ = desc
        # Register dynamically — FastMCP accepts callables with __doc__
        mcp.tool()(caller)
        log.info("aggregate.tool_registered", tool=name)
    return mcp


def run_aggregate_server() -> None:
    """Entry point for the subprocess — blocks until process killed."""
    log.info("aggregate.starting", host=HOST, port=PORT, gateway=GATEWAY_URL)
    mcp = build_mcp_server()
    # Background refresh loop — rebuild server tool list periodically
    # Note: FastMCP does not support hot-reload of tools yet; a process restart
    # is the simplest refresh strategy. The lifespan task below signals a restart.
    mcp.run(transport="streamable-http")


if __name__ == "__main__":
    run_aggregate_server()
```

import multiprocessing
from app.aggregate import run_aggregate_server

@asynccontextmanager
async def lifespan(app: FastAPI):
    await init_registry(settings.DATABASE_URL)
    log.info("mcp_gateway.started")
    # Start MCP aggregate subprocess (separate process — cannot mount FastMCP in FastAPI, issue #1367)
    _agg_proc = multiprocessing.Process(target=run_aggregate_server, daemon=True, name="mcp-aggregate")
    _agg_proc.start()
    log.info("mcp_gateway.aggregate_subprocess_started", pid=_agg_proc.pid)
    yield
    _agg_proc.terminate()
    _agg_proc.join(timeout=5)
    await close_registry()

## Threat Model

- T-04-02-SEC-01 — **Injection team_scope via header X-Team-Scope** : LibreChat injecte `X-Team-Scope` dans les requêtes MCP. Si un attaquant modifie ce header, il peut appeler des tools au nom d'une autre team. Mitigation : le bridge JWT mintéd par l'agrégateur embed `team_scope` — la gateway downstream extrait `team_scope` du JWT (pas du header, cf. `_get_principal()` ligne 63 de main.py). Disposition : **mitigate** — l'agrégateur signe le `team_scope` dans le JWT avant d'appeler la gateway.
- T-04-02-SEC-02 — **Process agrégateur crash = tool call silently fails** : si le subprocess crash, LibreChat voit un 502 au lieu d'un résultat. Disposition : **accept** — `daemon=True` garantit qu'il ne bloque pas le shutdown. Un crash est loggé par le process parent. Monitoring via `docker logs`. Restart automatique du container si healthcheck échoue.
- T-04-02-SEC-03 — **SSRF via tool name dynamique** : l'agrégateur construit l'URL `POST /tools/{tool_name}/call` à partir des noms de tools du registre. Un tool_name malformé (`../admin`) pourrait modifier le path. Mitigation : `tool_name` est validé dans le registre (alphanumeric + dash) — vérifier que `register_tool()` dans `app/registry.py` applique une validation de format. Disposition : **mitigate** — ajouter un assert `re.match(r'^[a-z0-9_-]+$', tool_name)` dans `_build_tool_caller` avant de construire l'URL.
