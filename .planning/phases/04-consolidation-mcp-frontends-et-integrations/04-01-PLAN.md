# Plan 04-01 — memory-api : upsert silencieux conversations

## Goal

Corriger le trou résiduel Phase 2 : `POST /v1/messages` avec un `conversation_id` inconnu crée silencieusement la conversation (upsert idempotent) au lieu de retourner 404 — ce qui permet à la pipeline Open WebUI de logger correctement sans double round-trip.

## Context

**Problème confirmé** : `apps/memory-api/app/routes/messages.py` ligne 71–73 fait un `conv_repo.get_conversation()` et retourne 404 si la row n'existe pas. La pipeline Open WebUI (`apps/openwebui-pipeline/app/pipelines/xbrain_logger.py`) calcule un UUID v5 déterministe via `_make_conversation_id(sub, messages)` et appelle directement `POST /v1/messages` sans jamais créer la conversation au préalable. Résultat : tous les chats OWUI génèrent des 404 dans memory-api.

**Décision locked (D-02)** : upsert silencieux côté memory-api — si `conversation_id` n'existe pas, INSERT avec `ON CONFLICT (id) DO NOTHING` + `title=null, source=<tagging.source>, owner=<sub jwt>`. Le flux LibreChat (bridge Mongo qui crée explicitement la conversation) est inchangé — l'upsert est un no-op pour lui.

**Pattern `conv_repo.create_conversation`** : voir `apps/memory-api/app/routes/conversations.py` lignes 56–62 pour l'appel exact. Pour les bridge calls (kind != "user"), la résolution `sub -> user` se fait via `get_or_create_user(session, source_user_id=sub, email=f"{sub}@bridged.local")` (pattern existant lignes 47–51 de conversations.py).

**UUID v5 déterministe** : la pipeline génère un UUID fixe pour la même paire (sub, messages). Deux upserts simultanés sur le même `conversation_id` → 1 row via `INSERT ... ON CONFLICT (id) DO NOTHING` + `RETURNING id`.

### T-04-01-01 — Modifier `create_message` pour upsert silencieux de la conversation

```python
conv = await conv_repo.get_conversation(session, conversation_id=body.conversation_id, team_scope=team_scope)
if conv is None:
    # Upsert silencieux (Décision 4-D-02) — pipeline OWUI ne crée jamais la conversation au préalable.
    # ON CONFLICT (id) DO NOTHING garantit l'idempotence sur UUID v5 déterministe.
    # Le bridge LibreChat crée explicitement la conversation avant d'envoyer des messages
    # — pour lui cet upsert est un no-op (la row existe déjà).
    if principal["kind"] == "user":
        owner_id = principal["user"].id
    else:
        from app.repos.users import get_or_create_user
        _user = await get_or_create_user(
            session,
            source_user_id=principal["sub"],
            email=f"{principal['sub']}@bridged.local",
            display_name=None,
        )
        owner_id = _user.id
    await conv_repo.upsert_conversation_silent(
        session,
        conversation_id=body.conversation_id,
        team_scope=team_scope,
        owner_user_id=owner_id,
        source=body.tagging.source,
        project_scope=body.tagging.project_scope,
    )
```

### T-04-01-02 — Ajouter `upsert_conversation_silent` dans le repo conversations

**File**: `apps/memory-api/app/repos/conversations.py`
**Action**: modify (ajout d'une fonction en bas du fichier, sans modifier les fonctions existantes)

**Changes**:

Ajouter la fonction suivante à la fin du fichier :
```python
async def upsert_conversation_silent(
    session: AsyncSession,
    *,
    conversation_id: UUID,
    team_scope: str,
    owner_user_id: UUID,
    source: str,
    project_scope: str | None = None,
) -> None:
    """INSERT conversation row silently — ON CONFLICT (id) DO NOTHING.

    Called by POST /v1/messages when conversation_id is unknown (pipeline OWUI pattern).
    Idempotent: concurrent upserts with the same UUID v5 result in exactly one row.
    title is intentionally NULL — the pipeline does not know the conversation title
    at message-send time. Admin or LLM summary can backfill later.
    """
    await session.execute(
        sa.text(
            """
            INSERT INTO conversations (id, team_scope, project_scope, owner_user_id, source, title, created_at)
            VALUES (:id, :team_scope, :project_scope, :owner_user_id, :source, NULL, now())
            ON CONFLICT (id) DO NOTHING
            """
        ),
        {
            "id": conversation_id,
            "team_scope": team_scope,
            "project_scope": project_scope,
            "owner_user_id": owner_user_id,
            "source": source,
        },
    )
```

Ajouter l'import `import sqlalchemy as sa` en tête de fichier si absent (vérifier d'abord).
Ajouter l'import `from uuid import UUID` si absent.

## Threat Model

- T-04-01-SEC-01 — **Elevation of privilege via conversation_id forgery** : un attaquant forge un UUID v5 appartenant à une autre team pour injecter un message dans leur conversation. Mitigation : l'upsert silencieux utilise le `team_scope` du JWT requérant (pas du body). Un message inséré dans une conversation d'une autre team est impossible : la contrainte FK `conversations.team_scope` rejetterait l'INSERT, et `get_conversation` filtre par `team_scope`. Disposition : **mitigate** — le filtre `team_scope` sur la conversation est maintenu.
- T-04-01-SEC-02 — **DoS par flood de faux conversation_ids** : un attaquant authentifié crée des milliers de conversations fantômes. Disposition : **accept** — limité par la RAM Postgres (192m) et le rate-limiting nginx ; les rows créées sont légères (8 colonnes, pas de vecteur). Seuil à surveiller via `SELECT count(*) FROM conversations WHERE title IS NULL` dans Langfuse dashboard.
