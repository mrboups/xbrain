# Plan 04-03 — LibreChat config `mcpServers` + smoke test E2E

## Goal

Configurer LibreChat pour pointer vers le serveur MCP agrégé de la gateway (plan 04-02), puis valider que les tools apparaissent dans l'UI et qu'un appel E2E fonctionne.

## Context

**Dépendance** : nécessite que plan 04-02 soit exécuté (endpoint `http://mcp-gateway:8081/mcp` up).

**Décision locked (D-03)** : bloc `mcpServers` dans `infrastructure/librechat/librechat.yaml` avec transport `streamable-http` pointant vers `http://mcp-gateway:8081/mcp`. LibreChat v0.8.5 supporte ce transport depuis Q4 2025.

**Fichier cible** : `infrastructure/librechat/librechat.yaml` est monté en `:ro` dans le container LibreChat (voir docker-compose.yml ligne 274 : `./librechat/librechat.yaml:/app/librechat.yaml:ro`). Un `docker compose restart librechat` recharge la config.

**Variables d'environnement** : LibreChat injecte les env vars dans librechat.yaml via la syntaxe `${VAR_NAME}`. `LIBRECHAT_DEFAULT_TEAM_SCOPE` doit être ajouté à l'env du service `librechat` dans docker-compose.yml.

**Auth** : D-03 prévoit `X-LibreChat-User-Email: "{{LIBRECHAT_USER_EMAIL}}"` — cette variable template est injectée par LibreChat depuis le profil user connecté. Le process agrégateur utilise ce header pour résoudre `email → sub` via memory-api `/v1/me` dans les futures itérations. En Phase 4 : le team_scope est fixé à `${LIBRECHAT_DEFAULT_TEAM_SCOPE}` (variable d'env). Le header `X-LibreChat-User-Email` est passé mais pas encore consommé par l'agrégateur (Phase 5).

**Syntaxe librechat.yaml pour MCP** : basée sur la doc LibreChat v0.8.5, le bloc est :
```yaml
mcpServers:
  xbrain:
    type: streamable-http
    url: http://mcp-gateway:8081/mcp
    headers:
      X-Team-Scope: "${LIBRECHAT_DEFAULT_TEAM_SCOPE}"
```

## Tasks

### T-04-03-01 — Ajouter `mcpServers` dans `infrastructure/librechat/librechat.yaml`

**File**: `infrastructure/librechat/librechat.yaml`
**Action**: modify

**Changes**:

Lire le fichier existant. Ajouter le bloc `mcpServers` au niveau racine (même indentation que `endpoints`, `rateLimits`, etc.) :

```yaml
mcpServers:
  xbrain:
    # MCP aggregate endpoint — presents all registered xbrain tools as a single MCP server.
    # Requires mcp-gateway:8081 to be running (Phase 4, plan 04-02).
    # Transport: streamable-http (LibreChat v0.8.5+, supported since Q4 2025).
    type: streamable-http
    url: http://mcp-gateway:8081/mcp
    headers:
      X-Team-Scope: "${LIBRECHAT_DEFAULT_TEAM_SCOPE}"
```

Ne pas modifier les blocs `endpoints`, `interface`, `modelSpecs` ou autres sections existantes — ajout pur.

---

### T-04-03-02 — Ajouter `LIBRECHAT_DEFAULT_TEAM_SCOPE` au service `librechat` dans docker-compose.yml

**File**: `infrastructure/docker-compose.yml`
**Action**: modify

**Changes**:

Dans le service `librechat` (section `environment`, environ ligne 249), ajouter :

```yaml
      LIBRECHAT_DEFAULT_TEAM_SCOPE: ${LIBRECHAT_DEFAULT_TEAM_SCOPE:-default}
```

Cela permet de surcharger le team_scope par défaut dans `.env` sans changer le yaml. La valeur par défaut est `default` (cohérent avec le reste du projet).

## Threat Model

- T-04-03-SEC-01 — **Exposition des tools à tous les users LibreChat** : tous les utilisateurs LibreChat (pas seulement les admins) auront accès aux MCP tools. Disposition : **accept** — en Phase 4, l'accès est limité par le `team_scope` injecté dans le JWT de gateway. Un utilisateur ne peut appeler des tools qu'avec son propre `team_scope`. Un affinement par rôle RBAC est prévu Phase 5.
- T-04-03-SEC-02 — **Absence de validation TLS entre LibreChat et mcp-gateway** : la communication est en HTTP clair sur le réseau Docker interne (`xbrain_net`). Disposition : **accept** — réseau Docker bridge interne, pas exposé à Internet. Même pattern que les autres services inter-container (memory-api, agent-runtime). TLS interne hors scope.
