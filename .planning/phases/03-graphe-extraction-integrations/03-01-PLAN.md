  <action>
Lire le fichier complet infrastructure/docker-compose.yml, puis ajouter :

1. Dans la section `volumes:` (avec les autres volumes en haut du fichier), ajouter :
   ```yaml
     neo4j_data: { name: neo4j_data }
   ```

2. Dans la section `services:`, ajouter le service `neo4j` après les services Langfuse existants :
   ```yaml
     # === Neo4j Community (plan 03-01) — graph store for entity/fact relationships ===
     neo4j:
       image: neo4j:2026.04.0-community
       container_name: xbrain-neo4j
       restart: unless-stopped
       environment:
         NEO4J_server_memory_heap_initial__size: 512m
         NEO4J_server_memory_heap_max__size: 512m
         NEO4J_server_memory_pagecache_size: 256m
         NEO4J_AUTH: neo4j/${NEO4J_PASSWORD}
         NEO4J_PLUGINS: "[]"
       volumes:
         - neo4j_data:/data
       networks: [xbrain_net]
       mem_limit: 1024m
       healthcheck:
         test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:7474 2>/dev/null | grep -q neo4j || exit 1"]
         interval: 30s
         timeout: 10s
         retries: 10
         start_period: 60s
   ```

Règles :
- Utiliser `127.0.0.1` (pas `localhost`) dans le healthcheck test — cohérent avec le pattern existant des autres services (évite résolution IPv6).
- `start_period: 60s` est obligatoire : Neo4j Community prend 20-40s pour booter (JVM + graph store open). Sans ce délai, le container passe `unhealthy` trop tôt et bloque les dépendants.
- `NEO4J_AUTH: neo4j/${NEO4J_PASSWORD}` : format Bolt/HTTP auth. Pas de user séparé en Community Edition — user fixe `neo4j`, password depuis env.
- `NEO4J_PLUGINS: "[]"` : désactiver le téléchargement de plugins au démarrage (Community Edition, pas besoin APOC pour Phase 3).
- Ne PAS exposer les ports 7474/7687 sur l'hôte — accès interne uniquement via xbrain_net.
