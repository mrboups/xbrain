# Phase 5 Plan 05: projects.dejavu.cat dashboard

## Goal

Créer le site statique `projects.dejavu.cat` listé sur Firebase Hosting : un dashboard généré par GitHub Actions qui affiche tous les projets xbrain déployés, filtrables par member et par projet.

## Tasks

### Task 1 — Script Python generate_dashboard.py

**What:** Script Python (~120 lignes) qui génère `public/index.html` en interrogeant (1) l'API GitHub Org pour les repos et collaborateurs, et (2) `GET /v1/admin/projects` de memory-api pour les URLs et métadonnées. Le résultat est un fichier HTML statique auto-suffisant.

**Files:**
- `projects-dashboard/scripts/generate_dashboard.py`

**How:**

1. **Sources de données** (deux appels HTTP) :
   - `GET https://api.github.com/orgs/{GITHUB_ORG}/repos?per_page=100` → liste des repos publics et privés (avec PAT `GITHUB_API_PAT`).
   - Pour chaque repo : `GET https://api.github.com/repos/{GITHUB_ORG}/{repo}/collaborators` → liste des membres (avec PAT).
   - `GET https://api.dejavu.cat/v1/admin/projects?team_scope=acme` → liste des projets enregistrés dans xbrain (avec `XBRAIN_BRIDGE_JWT`).

2. **Jointure** : mapper les projets xbrain (par `slug`) avec les repos GitHub (par nom). Un repo sans brain.yaml peut apparaître dans la liste GitHub mais pas dans xbrain — l'afficher avec statut "non-indexé".

3. **HTML généré** — page HTML+CSS vanilla avec :
   - En-tête : "xbrain Projects" + date de génération.
   - Filtres JavaScript : deux `<input>` (filter by member, filter by project) avec `onkeyup` qui filtre les cards dynamiquement.
   - Grille de cards : une card par projet avec :
     - Nom du projet (lien vers l'URL déployée si disponible).
     - Badge deploy target : `Firebase` (bleu) | `Cloud Run` (vert) | `VM` (gris).
     - Statut : "live" (vert) | "non-indexé" (gris).
     - Membres : avatars GitHub (img src `https://github.com/{username}.png?size=24`) ou liste de usernames.
     - `project_scope` / `team_scope` en sous-texte.
   - Footer : "Généré le {date} — xbrain v5".
   - CSS inline dans `<style>` (pas de framework externe — la page doit fonctionner offline) : font-family system-ui, grid 3 colonnes, cards avec border-radius, couleurs sobres.

4. **Variables d'env requises** (passées par GitHub Actions) :
   - `GITHUB_ORG` (défaut `your-github-org`)
   - `GITHUB_API_PAT` (Fine-grained PAT read:org read:repo)
   - `XBRAIN_MEMORY_API_URL` (défaut `https://api.dejavu.cat`)
   - `XBRAIN_BRIDGE_JWT`

5. **Error handling** : si GitHub API échoue (rate limit, réseau), générer la page avec les données disponibles + note "données partielles". Script exit 0 toujours.

### Task 2 — Firebase Hosting config + GitHub Actions deploy

**What:** Configurer Firebase Hosting pour `projects-dashboard/` et créer le workflow GitHub Actions qui génère et déploie le dashboard automatiquement à chaque push dans l'org.

**Files:**
- `projects-dashboard/firebase.json`
- `projects-dashboard/.firebaserc`
- `projects-dashboard/public/.gitkeep`
- `projects-dashboard/.github/workflows/deploy-dashboard.yml`

**How:**

1. **firebase.json** — configuration minimale Firebase Hosting (RESEARCH.md Q5) :
   ```json
   {
     "hosting": {
       "public": "public",
       "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
       "rewrites": [],
       "headers": [
         {
           "source": "**",
           "headers": [
             {"key": "Cache-Control", "value": "no-cache, must-revalidate"},
             {"key": "X-Frame-Options", "value": "DENY"}
           ]
         }
       ]
     }
   }
   ```
   Note : `Cache-Control: no-cache` car le dashboard est regeneré régulièrement et doit toujours afficher les données fraîches.

2. **.firebaserc** :
   ```json
   {
     "projects": {
       "default": "xbrain-495115"
     }
   }
   ```

3. **public/.gitkeep** — fichier vide pour committer le répertoire `public/` (il sera rempli par le script de génération dans CI).

4. **deploy-dashboard.yml** — workflow GitHub Actions qui s'exécute :
   - Sur push sur `main` dans le repo `xbrain` (le repo du stack).
   - En `workflow_dispatch` (déclenchement manuel).
   - Sur schedule `cron: '0 */6 * * *'` (toutes les 6h pour rafraîchir les données GitHub).
   
   Steps :
   ```yaml
   - uses: actions/checkout@v4
   - name: Set up Python
     uses: actions/setup-python@v5
     with: { python-version: "3.12" }
   - name: Install dependencies
     run: pip install requests pyyaml
   - name: Generate dashboard
     env:
       GITHUB_ORG: ${{ vars.GITHUB_ORG || 'your-github-org' }}
       GITHUB_API_PAT: ${{ secrets.GITHUB_API_PAT }}
       XBRAIN_BRIDGE_JWT: ${{ secrets.XBRAIN_BRIDGE_JWT }}
       XBRAIN_MEMORY_API_URL: https://api.dejavu.cat
     run: |
       cd projects-dashboard
       python3 scripts/generate_dashboard.py
   - uses: FirebaseExtended/action-hosting-deploy@v0
     with:
       repoToken: ${{ secrets.GITHUB_TOKEN }}
       firebaseServiceAccount: ${{ secrets.FIREBASE_SERVICE_ACCOUNT_XBRAIN }}
       projectId: xbrain-495115
       channelId: live
       entryPoint: ./projects-dashboard
   ```
   
   Note : `entryPoint: ./projects-dashboard` indique à l'action Firebase où trouver `firebase.json`.

### Task 3 — nginx vhost fallback 30-projects.conf

**What:** Ajouter un vhost nginx de fallback pour `projects.dejavu.cat` sur la VM. Normalement, le trafic va vers Firebase Hosting (via CNAME DNS). Ce vhost sert de fallback redirect vers Firebase si le DNS change, ou si l'admin veut temporairement servir depuis la VM.

**Files:**
- `infrastructure/nginx/conf.d/30-projects.conf`

**How:**

Copier `infrastructure/nginx/conf.d/20-api.conf` intégralement et adapter. Structure à créer :

```nginx
# 30-projects.conf — vhost fallback pour projects.dejavu.cat
# Normalement, le DNS pointe vers Firebase Hosting (CNAME).
# Ce vhost est un fallback redirect si le DNS est temporairement sur la VM.

resolver 127.0.0.11 valid=30s ipv6=off;

server {
    listen 80;
    server_name projects.dejavu.cat;

    # Headers Cloudflare pour les logs IP réels (copier depuis 10-xbrain.conf)
    real_ip_header CF-Connecting-IP;

    # Option A : Redirect permanent vers Firebase Hosting
    return 301 https://xbrain-495115.web.app$request_uri;

    # Option B (si on veut servir en local) : commenter le return ci-dessus et décommenter :
    # root /var/www/projects;
    # try_files $uri $uri/ /index.html;
    # add_header X-Frame-Options "DENY";

    location /nginx-health {
        return 200 "ok\n";
        access_log off;
    }
}
```

Note : le redirect permanent `301` vers Firebase est le comportement par défaut. Si le DNS Cloudflare est en mode Proxied (orange cloud) avec CNAME vers Firebase, nginx ne verra jamais le trafic `projects.dejavu.cat` — ce fichier est purement un fallback de sécurité.

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloudflare Access → Firebase Hosting | Tout trafic vers projects.dejavu.cat passe par Cloudflare Access (plan 05-06) avant d'atteindre Firebase |
| GitHub Actions → GitHub API | PAT Fine-grained stocké dans GitHub Secrets — accès read-only aux repos/membres |
| GitHub Actions → api.dejavu.cat | Bridge JWT dans GitHub Secrets — lecture des projets enregistrés |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Information Disclosure | Dashboard liste membres GitHub + URLs projets — information sensible | mitigate | Dashboard protégé par Cloudflare Access (plan 05-06) — seuls les emails whitelistés y accèdent. |
| T-05-05-02 | Information Disclosure | GITHUB_API_PAT dans GitHub Actions Secrets — visible aux admins du repo | accept | Risque accepté — admin repo = membre de confiance. PAT read-only (read:org, read:repo). |
| T-05-05-03 | Denial of Service | GitHub API rate limit (5000 req/h) atteint par la génération toutes les 6h | accept | 1 génération = ~N+1 appels API où N = nombre de repos. Pour une petite org (<50 repos), ~60 appels max. Très en dessous du rate limit. |
| T-05-05-04 | Tampering | HTML généré injecte du contenu non-échappé depuis les noms de repos GitHub | mitigate | Utiliser `html.escape()` Python sur tous les champs issus de l'API GitHub avant insertion dans le HTML. |
