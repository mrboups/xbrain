# Phase 5 Plan 04: Extension Chrome web clipper

## Goal

Créer l'extension Chrome Manifest V3 qui permet à un membre de l'équipe de clipper du contenu web directement dans le brain xbrain, avec sélection du truth_level, depuis n'importe quelle page.

## Tasks

### Task 1 — Structure extension Manifest V3 + auth Google OAuth

**What:** Créer la structure complète de l'extension Chrome MV3 : manifest.json, background service worker (auth), popup HTML+JS, content script (web clipper). L'auth utilise `launchWebAuthFlow` avec `response_type=id_token` pour obtenir un ID token JWT compatible avec `verify_google_id_token` de memory-api (RESEARCH.md Q6 — Solution A).

**Files:**
- `chrome-extension/manifest.json`
- `chrome-extension/background.js`
- `chrome-extension/icon48.png` (placeholder PNG 48x48 — générer un carré bleu/blanc simple en base64)
- `chrome-extension/icon128.png` (placeholder PNG 128x128)

**How:**

1. **manifest.json** — structure Manifest V3 complète (RESEARCH.md Q6) :
   ```json
   {
     "manifest_version": 3,
     "name": "xbrain Web Clipper",
     "version": "1.0.0",
     "description": "Envoyez du contenu web dans le brain xbrain de votre équipe",
     "permissions": ["identity", "activeTab", "storage"],
     "background": {
       "service_worker": "background.js"
     },
     "action": {
       "default_popup": "popup.html",
       "default_icon": {
         "48": "icon48.png",
         "128": "icon128.png"
       }
     },
     "content_scripts": [
       {
         "matches": ["<all_urls>"],
         "js": ["content.js"]
       }
     ],
     "oauth2": {
       "client_id": "__GOOGLE_CLIENT_ID__",
       "scopes": ["openid", "email", "profile"]
     },
     "host_permissions": [
       "https://api.dejavu.cat/*"
     ]
   }
   ```
   Note : `__GOOGLE_CLIENT_ID__` est un placeholder — remplacer par la valeur réelle lors de l'installation. Le même `GOOGLE_CLIENT_ID` que LibreChat (credentials Google OAuth existants). Il faut ajouter `https://<chrome-extension-id>.chromiumapp.org/` aux Authorized redirect URIs dans la console Google Cloud.

2. **background.js** — service worker qui expose deux fonctions via `chrome.runtime.onMessage` :
   - `{type: "GET_ID_TOKEN"}` → appelle `getGoogleIdToken()` (code exact de RESEARCH.md Q6 Solution A) et retourne le token.
   - `{type: "SEND_TO_BRAIN", payload}` → appelle `sendToBrain(idToken, payload)` (code de RESEARCH.md Q6 "Appel vers memory-api").
   - Stocker le ID token dans `chrome.storage.session` avec TTL de 3600s (éviter de re-authentifier à chaque clip).
   - `getGoogleIdToken()` : utiliser `chrome.identity.launchWebAuthFlow` avec `response_type=id_token`, `nonce` aléatoire, `redirect_uri = https://${chrome.runtime.id}.chromiumapp.org/`. Extraire le token du fragment `#id_token=...` de l'URL de retour.
   - Target API URL : `https://api.dejavu.cat/v1/memory/upsert` (hardcodé — l'extension est dédiée à xbrain).

3. **icon48.png** et **icon128.png** — créer avec le code Python suivant (images PNG minimales bleu/blanc) :
   ```python
   # Script à exécuter pour générer les icônes placeholder
   import base64
   # PNG 48x48 bleu plein (bytes minimaux)
   # Utiliser une image PNG en base64 codée en dur dans le script Python
   ```
   Alternativement : créer des fichiers SVG convertis en PNG, ou utiliser `python3 -c "from PIL import Image; img = Image.new('RGB', (48,48), color=(59, 130, 246)); img.save('chrome-extension/icon48.png')"`. Si PIL n'est pas disponible, créer des fichiers 1x1 pixel valides (l'icône importe peu fonctionnellement).

**Test:** `python3 -c "import json; d=json.load(open('chrome-extension/manifest.json')); assert d['manifest_version']==3; print('manifest OK')"`. Le dossier `chrome-extension/` peut être chargé dans Chrome via `chrome://extensions/ > Load unpacked`.

### Task 2 — Popup UI + content script

**What:** Créer le popup HTML (4 champs + bouton Send) et le content script qui extrait le texte sélectionné + l'URL de la page courante et les injecte dans le popup.

**Files:**
- `chrome-extension/popup.html`
- `chrome-extension/popup.js`
- `chrome-extension/content.js`

**How:**

1. **popup.html** — interface minimaliste (~60 lignes HTML) :
   - Titre "xbrain Web Clipper".
   - Select `team_scope` : options hardcodées `acme` (seule team en v1, extensible via `chrome.storage.sync` si besoin).
   - Input text `project_scope` (optionnel, placeholder "ex: fundraising").
   - Radio group `truth_level` : EPHEMERAL (défaut), WORKING, VALIDATED, CANONICAL (4 boutons radio).
   - Textarea `content` (pre-rempli avec le texte sélectionné, 6 lignes).
   - Bouton "Envoyer au brain" (bleu).
   - Div `status` pour afficher "Envoyé !" ou messages d'erreur.
   - Style CSS inline minimal : font-family system-ui, largeur 320px, padding 12px, couleurs sobres.

2. **popup.js** — logique du popup :
   - Au chargement : envoyer `{type: "GET_SELECTION"}` au content script via `chrome.tabs.sendMessage` pour récupérer le texte sélectionné + URL. Remplir le textarea `content` avec le texte sélectionné si non vide.
   - Sur click "Envoyer au brain" :
     a. Envoyer `{type: "GET_ID_TOKEN"}` au background service worker.
     b. Construire le payload avec les valeurs du formulaire (content, team_scope, project_scope, truth_level, source = `chrome:<hostname de l'URL>`, visibility = "team", confidence = 1.0, validation_status = "pending").
     c. Envoyer `{type: "SEND_TO_BRAIN", payload}` au background.
     d. Afficher "Envoyé !" en vert ou le message d'erreur en rouge.
   - Gérer les erreurs : token expired (re-demander), réseau (message d'erreur), auth refusée.

3. **content.js** — script léger injecté dans toutes les pages :
   - Écoute `chrome.runtime.onMessage` pour `{type: "GET_SELECTION"}`.
   - Retourne `{selectedText: window.getSelection().toString(), url: window.location.href, title: document.title}`.
   - Pas d'autre logique — pas de DOM scraping automatique.

**Test:**

```
4. L'extension apparaît sans erreur dans la liste
5. Sur n'importe quelle page : sélectionner du texte, ouvrir le popup
6. Le textarea est pré-rempli avec le texte sélectionné
```

### Task 3 — CORS middleware dans memory-api pour chrome-extension://

**What:** Ajouter `CORSMiddleware` dans memory-api FastAPI pour autoriser les requêtes depuis les extensions Chrome. Sans ce middleware, toutes les requêtes de l'extension vers `api.dejavu.cat` échouent avec une erreur CORS (pitfall RESEARCH.md Q6).

**Files:**
- `apps/memory-api/app/main.py`

**How:**

Dans `apps/memory-api/app/main.py`, après `app = FastAPI(...)` et avant les includes de routers, ajouter :

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "chrome-extension://*",    # toutes les extensions Chrome (dev + prod)
    ],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"],
    allow_headers=["Authorization", "X-Team-Scope", "Content-Type", "Accept"],
)
```

Note : `chrome-extension://*` utilise un wildcard. Si Chrome ne supporte pas ce pattern dans `Access-Control-Allow-Origin` (certaines versions retournent l'ID exact), il faudra soit stocker l'ID de l'extension en config et l'injecter ici, soit utiliser `allow_origins=["*"]` (moins restrictif mais acceptable car l'auth est faite via Bearer token). Commencer avec `chrome-extension://*` — si ça échoue au test, utiliser `["*"]` temporairement.

Vérifier que ce middleware n'entre pas en conflit avec un CORSMiddleware éventuellement déjà présent dans main.py (grep pour `CORSMiddleware` dans le fichier avant de modifier).

**Test:**
```bash
# Vérifier que memory-api retourne des headers CORS pour une requête OPTIONS
curl -X OPTIONS https://api.dejavu.cat/v1/memory/upsert \
  -H "Origin: chrome-extension://abcdefg" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: Authorization, X-Team-Scope" \
  -v 2>&1 | grep -i "access-control"
# Attendu : Access-Control-Allow-Origin header présent dans la réponse
```

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Extension Chrome → api.dejavu.cat | Appel HTTPS externe avec ID token Google — même flow que LibreChat |
| Browser (Google OAuth) → Extension | launchWebAuthFlow ouvre une popup gérée par Chrome — pas d'accès aux credentials Google |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Spoofing | ID token Google forgé envoyé à memory-api depuis l'extension | mitigate | `verify_google_id_token` dans auth.py valide la signature avec les clés publiques Google JWKs. Impossible de forger sans la clé privée Google. |
| T-05-04-02 | Information Disclosure | ID token stocké dans chrome.storage.session accessible par d'autres extensions | accept | chrome.storage.session est isolé par extension. Risque résiduel faible. TTL 3600s réduit la fenêtre d'exposition. |
| T-05-04-03 | Elevation of Privilege | CORS `chrome-extension://*` trop permissif — n'importe quelle extension peut appeler memory-api | accept | L'auth Bearer token (Google ID token) est le vrai contrôle d'accès. Le CORS est juste une protection browser. Sans token valide, l'appel retourne 401. |
| T-05-04-04 | Repudiation | Clips envoyés sans traçabilité de l'URL source | mitigate | `source: "chrome:<hostname>"` inclus dans le payload. `validation_status: "pending"` permet de retrouver et auditer les clips. |
| T-05-04-05 | Tampering | Content script injecté dans `<all_urls>` peut accéder au DOM de pages sensibles | accept | content.js est minimal (3 lignes) — écoute seulement `GET_SELECTION`, retourne la sélection utilisateur. Pas de lecture automatique du DOM, pas d'envoi spontané. |

- L'extension se charge dans Chrome sans erreur (`chrome://extensions/ > Load unpacked`).

- `curl -X OPTIONS https://api.dejavu.cat/v1/memory/upsert -H "Origin: chrome-extension://test" -v` retourne des headers CORS.
