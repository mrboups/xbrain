# Phase 5 Plan 01: graphiti-service container

## Goal

Créer le container `graphiti-service` (FastAPI wrappant graphiti-core) branché sur Neo4j, avec 3 endpoints REST, et l'ajouter à docker-compose.yml.

## Tasks

### Task 1 — Créer apps/graphiti-service (Dockerfile, pyproject.toml, app/main.py)

**What:** Nouveau service FastAPI minimaliste (~80 lignes) qui encapsule graphiti-core. Le service expose 3 endpoints sur le port 8300 et utilise le pattern `lifespan` FastAPI pour éviter les conflits d'event loop avec la bibliothèque async graphiti-core.

**Files:**
- `apps/graphiti-service/Dockerfile`
- `apps/graphiti-service/pyproject.toml`
- `apps/graphiti-service/app/__init__.py` (vide)
- `apps/graphiti-service/app/main.py`

**How:**

1. **Dockerfile** — copier depuis `apps/mcp-deck/Dockerfile` et adapter. Utiliser `python:3.12-slim`, ajouter `libxml2-dev libxslt1-dev` (dépendance graphiti-core via lxml), `EXPOSE 8300`, commande `uvicorn app.main:app --host 0.0.0.0 --port 8300`.

2. **pyproject.toml** — copier depuis `apps/mcp-deck/pyproject.toml` et adapter avec ces dépendances exactes :
   ```toml
   [project]
   name = "graphiti-service"
   version = "0.1.0"
   requires-python = ">=3.12"
   dependencies = [
       "graphiti-core[anthropic]>=0.29.0",
       "fastapi>=0.111",
       "uvicorn[standard]>=0.29",
       "httpx>=0.27",
       "structlog>=24.0",
       "pydantic>=2.0",
   ]
   ```

3. **app/main.py** — implémenter le squelette complet fourni dans RESEARCH.md section "Code Examples > graphiti-service/app/main.py". Points critiques :
   - `graphiti_client` initialisé UNIQUEMENT dans `@asynccontextmanager async def lifespan(app: FastAPI)` — jamais au niveau module (pitfall event loop, RESEARCH.md Q1).
   - `SEMAPHORE_LIMIT=3` passé comme env var optionnel, défaut 3 (RESEARCH.md Assumption A5 — Anthropic Haiku Tier 1 = 50 req/min).
   - POST `/v1/ingest` retourne 202 Accepted et crée une asyncio.Task (non bloquant — `add_episode` prend 3-10s).
   - POST `/v1/search` retourne synchroniquement la liste des faits.
   - GET `/v1/healthz` retourne `{"status": "ok", "graphiti": true/false}`.
   - LLM config : `AnthropicClient` avec `claude-haiku-4-5-20251001`, `OpenAIEmbedder` avec `text-embedding-3-small`, `OpenAIRerankerClient` avec `gpt-4.1-nano` (fallback `gpt-4o-mini` si 4.1-nano indisponible).
   - Fermeture propre dans `yield` du lifespan : `await graphiti_client.close()`.
   - Variables d'env : `NEO4J_URI`, `NEO4J_USER`, `NEO4J_PASSWORD`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `LLM_MODEL` (défaut `claude-haiku-4-5-20251001`).

**Test:** `docker build -t xbrain/graphiti-service:test apps/graphiti-service/` se termine sans erreur.

### Task 2 — Ajouter graphiti-service à docker-compose.yml

**What:** Ajouter le bloc service `graphiti-service` dans `infrastructure/docker-compose.yml`, après le bloc `mcp-deck` (ligne ~651). Ajouter `OPENAI_API_KEY` dans l'environnement du service (clé obligatoire pour les embeddings même si Anthropic est le LLM principal — pitfall critique RESEARCH.md Q1).

**Files:**
- `infrastructure/docker-compose.yml`

**How:**

Ajouter le bloc suivant après le service `mcp-deck` (actuellement lignes 622-651) :

```yaml
  # === graphiti-service (plan 05-01) — temporal fact extraction + contradiction detection ===
  graphiti-service:
    build:
      context: ../apps/graphiti-service
      dockerfile: Dockerfile
    image: xbrain/graphiti-service:phase5
    container_name: xbrain-graphiti-service
    restart: unless-stopped
    environment:
      NEO4J_URI: bolt://neo4j:7687
      NEO4J_USER: neo4j
      NEO4J_PASSWORD: ${NEO4J_PASSWORD}
      ANTHROPIC_API_KEY: ${ANTHROPIC_API_KEY:-}
      OPENAI_API_KEY: ${OPENAI_API_KEY:-}
      LLM_MODEL: ${GRAPHITI_LLM_MODEL:-claude-haiku-4-5-20251001}
      LOG_LEVEL: ${LOG_LEVEL:-INFO}
    networks: [xbrain_net]
    mem_limit: 512m
    depends_on:
      neo4j: { condition: service_healthy }
      memory-api: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8300/v1/healthz 2>/dev/null | grep -q ok"]
      interval: 30s
      timeout: 10s
      retries: 5
      start_period: 60s
```

Note : `start_period: 60s` est obligatoire — Neo4j prend ~45s à démarrer et `build_indices_and_constraints()` ne peut pas s'exécuter avant (pitfall RESEARCH.md Q1 "Neo4j startup race").

**Test:** `docker compose config` ne retourne pas d'erreur de syntaxe YAML. Le service `graphiti-service` apparaît dans la liste des services.

### Task 3 — Appel fail-soft depuis memory-api vers graphiti-service

**What:** Ajouter dans `apps/memory-api/app/routes/facts.py` (ou le route handler d'ingestion de faits) un appel HTTP optionnel vers `graphiti-service` après chaque extraction de faits. Si graphiti-service est down ou retourne une erreur, l'opération memory-api continue normalement (fail-soft).

**Files:**
- `apps/memory-api/app/routes/facts.py` (ou le fichier qui gère POST /v1/facts — à identifier avec grep)

**How:**

1. Identifier le fichier de route qui gère la création de faits : `grep -r "POST.*facts\|/v1/facts" apps/memory-api/app/routes/ --include="*.py" -l`

2. Ajouter une fonction helper `_enrich_with_graphiti(content: str, group_id: str) -> None` :
   ```python
   import os
   import httpx
   import structlog

   log = structlog.get_logger(__name__)
   _GRAPHITI_URL = os.environ.get("GRAPHITI_SERVICE_URL", "http://graphiti-service:8300")

   async def _enrich_with_graphiti(content: str, group_id: str) -> None:
       """Appel optionnel vers graphiti-service — fail-soft si indisponible."""
       try:
           async with httpx.AsyncClient(timeout=5.0) as client:
               r = await client.post(
                   f"{_GRAPHITI_URL}/v1/ingest",
                   json={"content": content, "group_id": group_id, "source": "memory-api"},
               )
               r.raise_for_status()
       except Exception as exc:
           log.warning("graphiti.enrich_skipped", error=str(exc), group_id=group_id)
   ```

3. Appeler `asyncio.create_task(_enrich_with_graphiti(fact.content, fact.team_scope))` après la sauvegarde réussie du fait en base. Ne pas `await` directement pour ne pas bloquer la réponse HTTP.

4. Ajouter `GRAPHITI_SERVICE_URL: ${GRAPHITI_SERVICE_URL:-http://graphiti-service:8300}` dans le bloc environment de `memory-api` dans `docker-compose.yml`.

**Test:** `curl -X POST http://localhost:8000/v1/facts -d '{"content":"test"}' -H "Authorization: Bearer ..."` retourne 201 même si graphiti-service est arrêté (`docker stop xbrain-graphiti-service` avant le test).

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| memory-api → graphiti-service | Appel HTTP interne Docker network — pas de credentials nécessaires (réseau privé) |
| graphiti-service → Neo4j | Connexion bolt:// interne — password via env var |
| graphiti-service → OpenAI/Anthropic APIs | Appels HTTPS externes avec API keys en env vars |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Information Disclosure | OPENAI_API_KEY en env var Docker | mitigate | Clé chargée depuis .env sur VM, jamais committée. Rotation si exposition. |
| T-05-01-02 | Denial of Service | POST /v1/ingest sans auth (réseau interne) | accept | Port 8300 non exposé publiquement (pas de `ports:` dans docker-compose). Réseau xbrain_net interne uniquement. |
| T-05-01-03 | Denial of Service | add_episode CPU+IO bound → saturation event loop | mitigate | asyncio.create_task isole l'appel. SEMAPHORE_LIMIT=3 évite la saturation Anthropic API. |
| T-05-01-04 | Tampering | group_id non validé dans /v1/ingest | accept | graphiti-service est interne uniquement. Le group_id est fourni par memory-api (source de confiance). |

## Success Criteria

- `GET http://graphiti-service:8300/v1/healthz` retourne `{"status": "ok", "graphiti": true}` depuis memory-api.
- `POST /v1/ingest` avec `{"content": "...", "group_id": "acme"}` retourne 202 en moins de 500ms.
- `POST /v1/search` retourne une liste `facts` (peut être vide si add_episode n'a pas encore terminé).
- `docker compose up -d graphiti-service` démarre sans erreur après `docker compose up -d neo4j`.
- Si graphiti-service est stoppé, `POST /v1/facts` dans memory-api continue de retourner 201 (fail-soft confirmé).
