<objective>
Bake the local embedding model into the memory-api image so a zero-network OSS install works, make the
uvicorn worker count configurable so the model isn't duplicated in RAM under `--workers 2`, and expose the
new knobs through docker-compose and the `.env.example` templates.

This delivers the D-19-01 (offline/keyless) and D-19-04 (both-arch + RAM budget) halves of EMBED-01. The
Python engine (Plan 01) reads `settings.EMBEDDING_CACHE_DIR` and lazily loads the model only when
`EMBEDDINGS_PROVIDER=local`; this plan makes that path work with the network cut and within the e2-medium
budget.

Purpose: prove the "in-container, keyless, no external call" guarantee and the RAM fit (SC#2/SC#4).
Output: a memory-api image with weights baked at `/app/model_cache`, `HF_HUB_OFFLINE=1`, a configurable
worker count, and compose/env wiring for OSS-light (provider=local, workers=1).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| image build → HuggingFace Hub | model weights are fetched once at `docker build` time (network available), never at runtime |
| running container → external network | at inference the local embedder must make zero outbound calls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04 | Tampering/supply-chain (weights integrity) | Dockerfile builder bake step | mitigate | Weights for `BAAI/bge-small-en-v1.5` (MIT, public HF repo) are baked into an image layer at build time; `HF_HUB_OFFLINE=1` at runtime forces cache-only. No user-supplied input selects the model/weights (operator env only), and no runtime trust decision is made about downloaded content. |
| T-19-05 | Info disclosure / SSRF (outbound network) | local_embedder inference path | mitigate | Baking + `HF_HUB_OFFLINE=1` means the embedder issues zero outbound calls per embed — proven authoritatively by `docker run --network none` producing a 384-dim vector (Task 3). Removes the new outbound-network surface an API-based embedder would add. The opt-in `openai_embedder` path (one HTTP call per embed) is unchanged and off by default. |
| T-19-06 | Denial of Service (resource exhaustion / OOM) | uvicorn workers × in-process model | mitigate | The model loads lazily only when `EMBEDDINGS_PROVIDER=local`; OSS-light runs `UVICORN_WORKERS=1` so it loads once (~256-366 MB) instead of being duplicated under `--workers 2`, keeping memory-api within the e2-medium `mem_limit`. SaaS keeps 2 workers but uses `openai` (model never loads). Real-amd64 RSS to be measured once on the prod VM before finalizing mem_limit (RESEARCH A2). |
</threat_model>
