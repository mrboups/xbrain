# Phase 3.5 — MCP Gateway Fix + Corrections Phase 3 — CONTEXT

## Locked Decisions

### Bug 1 (CRITICAL) — mcp-gateway : réécriture client MCP stateful

**Problème** : `POST /tools/{tool_name}/call` retourne 400 Bad Request depuis les sidecars MCP.
La gateway fait du proxy HTTP brut — elle POST le corps de la requête directement vers `{sidecar_url}/mcp`.
Mais MCP `streamable-http` exige :
1. Un handshake JSON-RPC `initialize` AVANT tout `tools/call`
2. Une session persistante par client (le serveur associe les calls à une session ouverte)
3. Le header `Mcp-Session-Id` doit être propagé entre `initialize` → `tools/call`

Le fix du header `Accept: application/json, text/event-stream` (commit `8161b41`) a changé 406→400 mais n'a pas résolu le fond.

**Décision** : Réécrire `call_tool()` dans `apps/mcp-gateway/app/main.py` pour utiliser le SDK officiel `mcp` Python comme client stateful.
- Pattern : `streamablehttp_client(url)` → `ClientSession` → `session.initialize()` → `session.call_tool(name, args)` → close
- Maintenir un **pool de sessions** par sidecar (une session idle réutilisée, pas de nouveau handshake à chaque appel)
  - Pool simple : dict `{sidecar_url: asyncio.Queue[ClientSession]}` avec max 2 sessions par sidecar
  - Si pool vide → créer nouvelle session ; si session fermée → recréer
- Propagation des headers `X-Team-Scope` et `X-User-Sub` via les `httpx.AsyncClient` headers dans `streamablehttp_client`
- Timeout de session : fermer les sessions idle depuis > 30s (évite accumulation mémoire)
- L'audit reste intact : `log_tool_call()` fire-and-forget après chaque call réussi ou échoué

**Lib à ajouter** : `mcp>=1.0.0` dans `apps/mcp-gateway/requirements.txt` (le SDK Python officiel MCP d'Anthropic).
Import : `from mcp.client.streamable_http import streamablehttp_client` + `from mcp import ClientSession`.

**Ne pas changer** :
- L'interface HTTP de la gateway (`POST /tools/{tool_name}/call` reste identique)
- L'auth (`_get_principal` reste inchangé)
- Le registre (`registry.py` reste inchangé)
- L'audit (`audit.py` reste inchangé)

### Bug 2 (cosmetic) — verify-phase3.sh : parser container health

**Problème** : Test 1 "Phase 3 container health" retourne `0/6 healthy` alors que tous les 6 containers Phase 3 sont vraiment healthy.
Même bug que verify-phase2.sh : le `awk`/`grep` sur `docker compose ps` ne parse pas correctement le format `(healthy)` dans la sortie.

**Décision** : Réécrire le parser pour utiliser `docker inspect --format '{{.State.Health.Status}}'` par container, au lieu de regex sur la sortie de `docker compose ps`.
- Liste fixe des 6 containers Phase 3 : `neo4j mcp-gateway mcp-scraper mcp-drive-read mcp-calendar drive-sync`
- Compter ceux dont `docker inspect` retourne `healthy`
- Même fix à appliquer aussi à verify-phase2.sh si on passe par là (optionnel, hors scope principal)
