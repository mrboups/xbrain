# Plan 03.5-01 — mcp-gateway : réécriture call_tool() via MCP Python SDK

## Objectif

Remplacer le proxy HTTP brut de `call_tool()` par un client MCP stateful utilisant le SDK officiel Python (`mcp`).
Le proxy HTTP brut échoue avec 400 Bad Request car MCP streamable-http exige un handshake `initialize` avant tout `tools/call`.

## Fichiers modifiés

1. `apps/mcp-gateway/pyproject.toml` — ajouter `mcp>=1.0.0` dans dependencies
2. `apps/mcp-gateway/app/main.py` — réécrire `call_tool()` avec `streamablehttp_client` + `ClientSession`

## Changements

### pyproject.toml
- Ajouter `"mcp>=1.0.0",` dans la liste `dependencies`

### main.py
- Ajouter imports : `from mcp import ClientSession` + `from mcp.client.streamable_http import streamablehttp_client`
- Retirer `import httpx` (plus utilisé après réécriture)
- Retirer `import json as _json` (plus utilisé)
- Réécrire `call_tool()` pour utiliser le pattern stateful :
  `streamablehttp_client` → `ClientSession` → `session.initialize()` → `session.call_tool(name, args)`
- Retirer les variables `_rpc_method` et `_body_json` (plus utilisées)
- Conserver intact : auth, registry, /tools GET, /admin/register, audit

## Vérification

Container rebuild réussi + test E2E `POST /tools/scraper/call` retourne HTTP 200 avec content.
