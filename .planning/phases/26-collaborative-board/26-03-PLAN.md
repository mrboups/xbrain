<objective>
Build the Yjs server: a single-process `xbrain-hocuspocus` container running
`@hocuspocus/server@4.4.0` whose `onAuthenticate` hook is the phase's load-bearing security
boundary — it verifies the HS256 board token minted by memory-api and asserts
`claims.board_id === documentName`. Without that one comparison, a legitimately-minted token
for one board is a valid token for EVERY board, and since boards belong to teams, that is a
cross-team leak.

It must be its own process: memory-api runs `UVICORN_WORKERS=2` by default
(docker-compose.yml:134), so an in-FastAPI Y.Doc would exist twice and two clients would
silently never sync. It must hold no database credentials: persistence goes through
memory-api's bridge-authenticated internal doc endpoints, so team-scope decisions stay in the
one component that knows team membership.

Purpose: this is the component an attacker reaches directly. It is a NEW internet-facing
surface, so its DoS ceilings (`maxPendingDocuments`, `maxPayload`, the unauthenticated queue
caps, the idle timeout) are part of the deliverable, not tuning.

Output: `apps/hocuspocus/` — pinned deps, a multi-stage `node:22-alpine` Dockerfile with a
`gate` target the 26-07 gate runs from, the auth module, the persistence module, the server,
and a Node test proving the rejection matrix against the REAL verifier.
</objective>

         import { jwtVerify } from "jose";
         const enc = new TextEncoder();
         export class BoardAuthError extends Error {}
         // ONE message for every failure mode. A verbose error is an oracle: it would tell a
         // prober whether a board id exists, whether their token was merely expired, or which
         // claim was wrong. Log the detail server-side, return this to the client.
         const DENY = "Not authorized!";

         export async function verifyBoardToken(token, documentName, secret) {
           if (!token || typeof token !== "string") throw new BoardAuthError(DENY);
           if (!documentName || typeof documentName !== "string") throw new BoardAuthError(DENY);
           if (!secret) throw new BoardAuthError(DENY);   // never verify against an empty secret
           let payload;
           try {
             // algorithms is pinned: without it a token with alg "none" or an asymmetric alg
             // could be accepted (algorithm-confusion). jose validates exp/nbf here too.
             ({ payload } = await jwtVerify(token, enc.encode(secret), { algorithms: ["HS256"] }));
           } catch { throw new BoardAuthError(DENY); }
           if (payload.scope !== "board")            throw new BoardAuthError(DENY);
           // *** THE TEAM-SCOPE BOUNDARY ***
           // A token is valid for exactly the document it names. Without this comparison a
           // token minted for team A's board opens team B's board. Do not "optimise" it away.
           if (payload.board_id !== documentName)    throw new BoardAuthError(DENY);
           if (!payload.team_scope)                  throw new BoardAuthError(DENY);
           return payload;
         }

       team_scope is READ FROM THE VERIFIED CLAIM and never from a query parameter, a header,
       or the document name — state that in a comment. It is the only cross-team leak vector.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → hocuspocus WebSocket | A NEW internet-facing surface. Everything before `onAuthenticate` returns is attacker-controlled: the token, the document name, the message stream, the payload size |
| hocuspocus → memory-api internal doc endpoints | Service-to-service. Compromise here must not become database access — the container holds no DB credentials |
| hocuspocus → the Y.Doc of every connected board | One process holds several teams' documents in memory simultaneously; the only thing keeping them apart is the claim-vs-document match |
