<objective>
Build the memory-api half of the board: the schema, the team-scope gates, and the token
whose claims the Hocuspocus server will enforce on the socket. This is the contract plan —
26-03 (the Yjs server) and 26-04 (the SPA) both consume what is defined here, so the token
claim set and the internal doc endpoint shape are specified byte-exactly below and must not
be improvised.

Three independent gates make up the phase's load-bearing invariant (a member of team B can
never open team A's board), and TWO of them live in this plan: board create/list is
membership-checked, and token minting RE-CHECKS membership at mint time. The third
(`claims.board_id === documentName`) is 26-03's.

Purpose: memory-api is the only component that knows team membership, so it is the only
component allowed to say who may open which board. The board server holds no database
credentials and derives no team scope of its own — team_scope arrives as a signed claim or
not at all. That is the exact discipline `doc_body_ingest.py` documents as "the only
cross-team leak vector, so it is closed at construction".

Output: migration 0028 (`boards` + `board_docs`), `Board`/`BoardDoc` models, a boards repo,
`board_helpers.mint_board_token` / `verify_board_token`, the `boards` router registered in
`CORE_ROUTERS`, four config knobs, and a unit test of the token.
</objective>
