<objective>
Build the page a team member actually sees: a Vite + React SPA hosting
`@excalidraw/excalidraw@0.18.1`, bound to a Yjs document over `@hocuspocus/provider@4.4.0`,
served as static files by nginx out of a multi-stage image where Node exists only at build
time (D-26-01).

Two details carry the weight. First, the token: it arrives in the URL **fragment**, is
stripped with `history.replaceState` before any network call, and is then handed to the
provider through its **async token supplier** — so it travels inside the Hocuspocus Auth
message and never appears as a WebSocket query parameter (which would put it in nginx access
logs). Second, remote updates: every binding-driven `updateScene` for a remote change must
pass `CaptureUpdateAction.NEVER`, or a teammate's edit lands in YOUR Ctrl+Z history and undo
starts deleting other people's work.

Images stay Excalidraw-native (base64 in the document) for 26a — that is D-26-06, a bounded
and documented decision, not an omission. Do NOT build MinIO routing, an asset map, or a
media-token fetch here; that is 26b.

Purpose: this is the deliverable the user asked for — "a board where the team can really work
together, where I can write text and send photos". All of that is satisfied by mounting
Excalidraw correctly and wiring the CRDT.

Output: `src/main.tsx`, `src/Board.tsx`, `src/session.ts`, styles, a multi-stage Dockerfile
and the nginx config it ships.
</objective>

THE URL THIS PAGE IS OPENED WITH (built by memory-api, plan 26-02):
    {BOARD_PUBLIC_BASE_URL}/?b=<board_uuid>#t=<board_token>
  `?b=` is the board id and equals the Hocuspocus `documentName`.
  `#t=` is the short-lived board token. A fragment is NEVER transmitted to a server, so it
  cannot reach nginx access logs or a Referer header — that is why the handoff uses it. It
  MUST be stripped from the address bar before the first network call so it does not linger
  in browser history.

HOCUSPOCUS PROVIDER 4.4.0 (VERIFIED: dist/index.d.ts:319, :110):
    token?: string | (() => string) | (() => Promise<string>) | null
  The token is sent in the Hocuspocus **Auth message** (`OutgoingMessageArguments` includes
  `token`) — NOT in the connection URL. Never append it as a query parameter.
    new HocuspocusProvider({ url, name, document, token, onAuthenticationFailed, onStatus })
  `name` MUST be the board id — the server asserts `claims.board_id === documentName`.

EXCALIDRAW 0.18.1 (CITED: docs.excalidraw.com):
  - `import { Excalidraw, CaptureUpdateAction } from "@excalidraw/excalidraw";`
  - `import "@excalidraw/excalidraw/index.css";`  — the stylesheet is a SEPARATE package export.
  - No SSR. Render client-side only.
  - `excalidrawAPI` is obtained via the `excalidrawAPI={(api) => ...}` prop.
  - Remote updates: `updateScene({ elements, captureUpdate: CaptureUpdateAction.NEVER })`.
    `commitToHistory` no longer exists (Pitfall 4).
  - `BinaryFileData.dataURL` is a branded DataURL string; images live in a separate
    `BinaryFiles` map. In 26a they stay there, base64, untouched (D-26-06).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL/fragment → SPA | The board id and the access token arrive from an untrusted address bar. The token is a bearer secret for exactly one board |
| SPA → hocuspocus WebSocket | The client is fully attacker-controllable; the server, not this code, is the security decision point. Everything here is UX and leak-prevention |
| remote Y.Doc content → local canvas | Content authored by other team members is rendered locally |
| built static bundle → browser | What the nginx runtime stage serves is the whole client attack surface |
