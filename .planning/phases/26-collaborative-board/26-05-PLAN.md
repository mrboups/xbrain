<objective>
Give the chat the one affordance the phase is named for: a "board" action in the popup header
that opens the team's collaborative board in a browser tab. This is deliberately the smallest
possible surface — the extension has ZERO build tooling (no `package.json`, no bundler, no
`.tsx`, 13 hand-written `node *.mjs` contract tests), and Excalidraw is 2.76 MB of JS behind a
React peer. It cannot and must not go in a 400 px popup (D-26-01). The extension's whole job
here is: ask memory-api for the team's board, get back an `open_url`, and open it.

`chrome.tabs.create` is already used twice in this extension (`popup.js:166` opens LibreChat,
`background.js:1353` opens a teammate's nudged link), so no new permission is required — the
Phase-22 nudge path proves it works with the existing manifest.

Purpose: the board is reached from the chat, per the phase goal. Everything security-bearing
already happened server-side (26-02 checks membership and mints the token); this plan adds a
button, one fetch, and one URL-safety check.

Output: a `board` header button, a `wireBoard()` handler, and the popup contract test extended.
</objective>

         async function openTeamBoard() {
           if (!state.activeTeamId) return;                  // nothing to open yet
           const btn = document.getElementById("btn-board");
           if (btn) btn.disabled = true;                     // guard against a double click
                                                             // minting two boards' worth of calls
           try {
             const { xbt_token } = await chrome.storage.local.get(["xbt_token"]);
             const res = await fetch(
               `${MEMORY_API_BASE}/v1/teams/${state.activeTeamId}/boards`,
               { method: "POST",
                 headers: { Authorization: `Bearer ${xbt_token}`,
                            "Content-Type": "application/json" },
                 body: JSON.stringify({ title: "Team board" }) });
             if (!res.ok) throw new Error(`board ${res.status}`);
             const data = await res.json();
             // The server builds this URL and it carries a short-lived board token in its
             // fragment. Validate the scheme before handing it to the browser, and NEVER log
             // it — the fragment is a bearer secret for this one board.
             if (!data.open_url || !isSafeHttpUrl(data.open_url)) {
               throw new Error("board url rejected");
             }
             chrome.tabs.create({ url: data.open_url });
           } catch (err) {
             // Report the FAILURE, never the URL or the token.
             console.warn("open board failed", err && err.message);
             // Surface it the same way the neighbouring header actions surface a failure —
             // read how btn-send-link / btn-invite report errors and match it exactly.
           } finally {
             if (btn) btn.disabled = false;
           }
         }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| memory-api response → `chrome.tabs.create` | A URL from the API is handed straight to the browser. Even a same-trust-domain response should not be able to make the extension navigate to a `javascript:` or `data:` URL |
| popup runtime → console / storage | The `open_url` fragment is a short-lived bearer secret for one board |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-31 | Elevation of privilege | A non-http scheme (`javascript:`, `data:`) in the API-supplied `open_url` reaching `chrome.tabs.create` | mitigate | The existing `isSafeHttpUrl` from `nudge_open.js` — already imported by popup.js and already the guard on the Phase-22 nudge path — validates the URL before it is opened; a contract test asserts the call is present. |
| T-26-32 | Information disclosure | The board token (in the `open_url` fragment) written to the extension console or persisted to `chrome.storage` | mitigate | The handler logs only `err.message`, never the response body or the URL; a source-contract test asserts no `console.*open_url` / `console.*xbt_token` and the token is never stored. |
| T-26-33 | Spoofing | The extension building the board URL itself, and so being able to mint a link to a board id the server never authorised | mitigate | The URL is entirely server-built; the extension has no board-URL template. Contract tests assert the source contains no `#t=` and no `/?b=` construction. |
| T-26-34 | Denial of service | Double-clicking the button firing repeated board-creation calls | mitigate | The handler disables the button for the duration of the request and re-enables it in `finally`. |
| T-26-35 | Repudiation | A future popup.html edit silently dropping the button, leaving the phase's user-facing entry point gone but the suite green | mitigate | `btn-board` is added to `FROZEN_IDS`, and the executor must PROVE the guard fails when the button is removed before restoring it. |
</threat_model>
