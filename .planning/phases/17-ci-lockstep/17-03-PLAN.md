<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git push (main) → CI runner | A commit on main triggers the pipeline with access to `GITHUB_TOKEN` and repo secrets. |
| CI runner → GHCR | The build job pushes images (packages: write); publish retags. |
| CI runner → prod VM (SSH) | deploy-saas holds the SSH key and can mutate the running stack. |
| fork PR contributor → workflow | An untrusted contributor could try to run a workflow with secrets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-03-01 | Information Disclosure | GHCR/SSH secrets leaking into logs | mitigate | Use `secrets.GITHUB_TOKEN` for GHCR (no minted PAT); pass VM_SSH_KEY only via `secrets.*` (never `vars`, never echoed); no `echo "$SECRET" \| base64` debug lines. GitHub auto-redacts registered secret values. |
| T-17-03-02 | Elevation of Privilege | over-broad `GITHUB_TOKEN` | mitigate | Top-level `permissions: contents: read`; `packages: write` only on build/publish; `contents: write` only on publish (Release). No `write-all`. |
| T-17-03-03 | Elevation of Privilege | fork PR stealing secrets | mitigate | Trigger is `push: branches: [main]` + `workflow_dispatch` only — no `pull_request`/`pull_request_target`, so fork PRs never see repo secrets. |
| T-17-03-04 | Tampering | compromised third-party action | mitigate | Every `uses:` pinned to the researched exact release tag (docker/*, softprops, appleboy); no floating `@main`. Dependabot for controlled bumps noted in the residual doc. |
| T-17-03-05 | Tampering | deploy-saas rebuilds on the VM → untested image ships | mitigate | deploy PULLS the immutable `:${{ github.sha }}` images via the ci-images override; `make deploy` and `--build` are forbidden in the job (asserted). |
| T-17-03-06 | Elevation of Privilege | deploy fires against a stale/unowned VM | mitigate | Gated behind `vars.SAAS_DEPLOY_ENABLED` (defaults unset → off); the operator arms it only after confirming VM state (Plan 17-04 doc). |
| T-17-03-07 | Repudiation | which commit produced a deployed image is unclear | mitigate | Images tagged by immutable commit SHA (D-17-06); deploy pulls the SHA; `:latest` is a traceable pointer, not a rebuild. |
</threat_model>
