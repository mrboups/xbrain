### Task 1 — verify-phase11.sh (REVISION 1 — adds messages assertion)

**File(s):** `infrastructure/scripts/verify-phase11.sh`

**What:** Adopt the structure of `infrastructure/scripts/verify-phase7.sh` (helpers `run_psql`, `pass`, `fail`, `MEMAPI_HOST` env). 13 assertions (RESEARCH §Q10 has the body for 1-12 — paste lightly adapted; assertion 13 is new in REVISION 1; key checks summarized):

1. Alembic version ≥ `0018_brain_events_view`.
2. `tasks.truth_level`, `tasks.deleted_at`, `tasks.deleted_by` columns present.
3. All 6 target tables have `deleted_at` column (loop).
4. `v_brain_events` view exists (`to_regclass`).
5. `v_brain_events` returns ≥ 1 distinct entity_type for team `default`.
6. `GET /v1/brain/events` returns 200 with auth + X-Team-Scope.
7. PATCH `/v1/brain/events/task/$TEST_TASK_ID_OWNED` by owner → 200; by non-owner → 403.
8. DELETE → 204; row absent from default list; present with `include_deleted=true`.
9. POST `.../restore` → 200; `deleted_at IS NULL`.
10. `GET /v1/tasks` API count == `SELECT COUNT(*) FROM tasks WHERE team_scope='default' AND deleted_at IS NULL` (regression filter active).
11. `docker inspect xbrain-brain-janitor --format='{{.State.Status}}'` → `running`. Sentinel file `/tmp/brain-janitor-alive` mtime within last 25h.
12. Migration preservation: `SELECT COUNT(*) FROM memory_items WHERE truth_level NOT IN ('EPHEMERAL','WORKING','VALIDATED','CANONICAL','PUBLIC')` → 0 (Success Criterion 6).
13. **Messages soft-delete regression (REVISION 1 — closes B-3 audit trail):** seed 2 messages in a fixture conversation (`TEST_CONVERSATION_ID`), soft-delete one via direct DB UPDATE, then:
    ```bash
    # Assertion 13 body
    API_COUNT=$(curl -s -H "Authorization: Bearer $TEST_XBT" -H "X-Team-Scope: default" \
      "$MEMAPI_HOST/v1/messages?conversation_id=$TEST_CONVERSATION_ID" | jq '.items | length')
    DB_COUNT=$(run_psql -tA "SELECT COUNT(*) FROM messages WHERE conversation_id='$TEST_CONVERSATION_ID' AND deleted_at IS NULL")
    if [ "$API_COUNT" = "$DB_COUNT" ] && [ "$API_COUNT" = "1" ]; then
      pass "13. GET /v1/messages excludes soft-deleted ($API_COUNT API == $DB_COUNT DB == expected 1)"
    else
      fail "13. messages list mismatch: API=$API_COUNT DB=$DB_COUNT expected=1"
    fi
    ```
    Adjust the endpoint path if `routes/messages.py` exposes a different shape (e.g., `/v1/conversations/{cid}/messages`). Discover from the running API: `curl -s "$MEMAPI_HOST/openapi.json" | jq '.paths | keys[] | select(contains("messages"))'`.

The script must emit `PASS: N / 13` at the end. Use existing `set -e` + trap pattern from verify-phase7.sh.

Test fixtures `TEST_TASK_ID_OWNED`, `TEST_TASK_ID_OTHER_USER`, `TEST_XBT`, `TEST_XBT_MEMBER`, `TEST_CONVERSATION_ID` are sourced from `infrastructure/.env.test` (operator-provided) — document this in the script header.

**Why:** Single command to confirm Phase 11 health. Success Criterion 7 demands this. Assertion 13 is the automated guard for B-3 (messages regression) — without it, a future regression that drops the `messages.deleted_at IS NULL` filter would not trip verify-phase11.sh.

**Acceptance:** After VM deploy: `bash infrastructure/scripts/verify-phase11.sh` returns `PASS: 13 / 13` (or documented skips for fixtures not provided, with `PASS: N / 13 (M skipped)`).

**Commit message:** `test(infra): verify-phase11.sh — 13 assertions for BMO-01..09 + messages regression`

### Task 3 — UAT script + SUMMARY template

**File(s):** `.planning/phases/11-brain-monitor-universal-truth-level-inspector-soft-delete/11-UAT.md`, `.planning/phases/11-brain-monitor-universal-truth-level-inspector-soft-delete/11-SUMMARY.md`

**What:**

`11-UAT.md` — 6-step manual UAT, each step has expected outcome:

1. **Load page** — Open `https://app.grooveos.app/account/teams/brain/?team=default`. Expected: page loads in <2s, table renders, filter sidebar visible.
2. **Filter** — Check "task" + "WORKING". Expected: list re-fetches, shows only tasks at truth_level=WORKING.
3. **Inline edit truth_level** — Click a row's dropdown, change to VALIDATED. Expected: PATCH fires, success toast, refresh confirms persistence in DB.
4. **Soft-delete + reappear with toggle** — Click delete on a task. Expected: confirmation modal warns 30-day purge; on confirm row disappears. Toggle "Show deleted" → row reappears faded with "Restore" button.
5. **Restore** — Click Restore on a faded row. Expected: row un-fades, deleted_at IS NULL in DB.
6. **Polling** — Open a second tab, insert a memory_item via API. Within 30s the new row appears at the top of the first tab without manual refresh; existing rows and scroll position preserved (REVISION 1 — locked semantics from 11-08 M-2).
7. **403 toast wording** — Sign in as a plain member (non-admin, non-author of any item). Attempt PATCH via DevTools (re-enable a disabled dropdown). Expected: toast shows the exact text `"You can only edit items you created. Contact a team admin to modify items created by others."` (REVISION 1 — locked from 11-08 M-5).

Optional: capture screenshots via playwright-mcp during UAT for the SUMMARY.
