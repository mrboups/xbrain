# Plan 11-07 — `apps/brain-janitor/` cron container + docker-compose integration

## Section 1 — Goal

Ship the `brain-janitor` service: a Python container modeled after `apps/granola-sync/` that runs daily at 03:00 UTC, hard-deletes Postgres rows where `deleted_at < now() - INTERVAL '30 days'`, removes corresponding Qdrant points (memory_items only — facts are stored as memory_items with `source='extracted'`), cleans Neo4j relations, and writes an `audit_log` row per purge batch. This completes BMO-08.

After this plan: `docker compose up -d brain-janitor` adds the service to the stack, it tags `/tmp/brain-janitor-alive` after each run, and 30-day-expired soft-deleted items are gone from PG + Qdrant + Neo4j the next day.

### Task 2 — Purger modules + main loop

**File(s):** `apps/brain-janitor/app/pg_purger.py`, `apps/brain-janitor/app/qdrant_purger.py`, `apps/brain-janitor/app/neo4j_purger.py`, `apps/brain-janitor/app/main.py`

**What:**

**`pg_purger.py`**: connect via `asyncpg.create_pool()` (strip `postgresql+asyncpg://` prefix like granola-sync line 370–373). The purge function:

```python
PURGE_TABLES = [
    ("memory_items", "team_scope"),
    ("conversations", "team_scope"),
    ("messages",     "team_scope"),
    ("team_messages","team_id"),
    ("tasks",        "team_scope"),
    ("contacts",     "team_scope"),
]

async def purge_pg(pool: asyncpg.Pool, retention_days: int) -> dict[str, list[UUID]]:
    """For each table, DELETE rows where deleted_at < now() - interval.
    Returns dict[table_name] -> list of UUIDs deleted, for downstream purgers."""
    purged: dict[str, list[UUID]] = {}
    async with pool.acquire() as conn:
        async with conn.transaction():
            for table, _scope_col in PURGE_TABLES:
                rows = await conn.fetch(
                    f"DELETE FROM {table} WHERE deleted_at < now() - $1::interval RETURNING id",
                    f"{retention_days} days",
                )
                purged[table] = [r["id"] for r in rows]
            # Write a single audit_log row summarizing the batch
            await conn.execute(
                """INSERT INTO audit_log (actor_user_id, action, entity_type, entity_id, team_scope, metadata)
                   VALUES (NULL, 'brain_janitor.purge', 'batch', gen_random_uuid(), 'system', $1::jsonb)""",
                json.dumps({t: len(v) for t, v in purged.items()}),
            )
    return purged
```

**`qdrant_purger.py`**: takes the list of `memory_items` UUIDs purged from PG and calls `qdrant_client.delete(collection_name=..., points_selector=PointIdsList(points=[str(u) for u in ids]))`. Wrap with try/except — log and continue on partial failure (PG already deleted; we tolerate Qdrant drift, the next run will retry by querying any orphan Qdrant points).

**`neo4j_purger.py`**: for each `memory_items` UUID, run `MATCH (n {external_id: $id}) DETACH DELETE n`. Use `neo4j>=6.1` async driver:

```python
from neo4j import AsyncGraphDatabase
async def purge_neo4j(uri, user, pwd, mem_ids):
    async with AsyncGraphDatabase.driver(uri, auth=(user, pwd)) as drv:
        async with drv.session() as sess:
            for mid in mem_ids:
                await sess.run("MATCH (n {external_id: $id}) DETACH DELETE n", id=str(mid))
```

If a `delete_node_by_external_id` helper already exists in `xbrain_memory` or memory-api (verify by `rg "external_id" packages/ apps/memory-api/app/db/`), import and reuse it — DO NOT duplicate Neo4j connection logic. If absent, the janitor owns its own driver instance (acceptable).

**`main.py`**: asyncio entry with the sleep-until-next-03:00 pattern:

```python
async def run_once(settings):
    pool = await asyncpg.create_pool(_pg_url(settings.DATABASE_URL))
    try:
        purged = await purge_pg(pool, settings.RETENTION_DAYS)
        if purged.get("memory_items"):
            await purge_qdrant(settings.QDRANT_URL, purged["memory_items"])
            await purge_neo4j(settings.NEO4J_URI, settings.NEO4J_USER, settings.NEO4J_PASSWORD, purged["memory_items"])
        Path("/tmp/brain-janitor-alive").touch()
        log.info("brain_janitor.run_complete", purged_counts={t: len(v) for t, v in purged.items()})
    finally:
        await pool.close()

async def main():
    settings = Settings()
    await run_once(settings)
    while True:
        now = datetime.now(tz=timezone.utc)
        next_run = (now + timedelta(days=1)).replace(hour=3, minute=0, second=0, microsecond=0)
        sleep_s = (next_run - now).total_seconds()
        log.info("brain_janitor.sleep", seconds=sleep_s)
        await asyncio.sleep(sleep_s)
        await run_once(settings)
```

**Why:** BMO-08. The boot-time `run_once` makes verify-phase11.sh easy to test (no need to wait for 03:00). The 24h sleep loop matches the granola-sync convention.

**Acceptance:** After `docker compose up -d brain-janitor`, `docker logs xbrain-brain-janitor | head -30` shows `brain_janitor.run_complete` within 10s. `docker exec xbrain-brain-janitor stat /tmp/brain-janitor-alive` shows recent mtime. Manually insert a fake-expired row: `psql -c "INSERT INTO tasks (id, team_scope, title, deleted_at) VALUES (gen_random_uuid(), 'default', 'expired', now() - INTERVAL '31 days')"`, restart the container, verify `psql -c "SELECT COUNT(*) FROM tasks WHERE title='expired'"` returns 0.

## Section 4 — Risks + Mitigations

- **Risk: hard-delete CASCADE blows away wanted data.** Mitigation: each table's `deleted_at` was set by an explicit user action (DELETE endpoint or migration backfill). DELETE statements use the `deleted_at` predicate, not the row primary key — only soft-deleted rows go. Test in Task 2 covers the round-trip.
- **Risk: Qdrant or Neo4j unavailable during purge → PG deleted but vector/graph stale.** Mitigation: try/except per service; log a warning and re-attempt next day. PG is source of truth; orphan Qdrant points cost storage but don't corrupt search (the soft-delete payload filter from 11-03 still hides them, even if the underlying PG row no longer exists).
- **Risk: Neo4j helper duplication.** Mitigation: check for existing helper first; if a clean reusable one exists in memory-api or xbrain_memory, import it. Otherwise duplicate the connection logic (small footprint, acceptable).
- **Risk: clock skew / DST.** Mitigation: schedule in UTC (`datetime.now(tz=timezone.utc)`). DST is irrelevant.
- **Risk: race with running migration.** Mitigation: brain-janitor `depends_on` `postgres: service_healthy` — won't start until DB is up. Migrations from 11-01 must be applied as part of the memory-api deploy before this service starts (operator's responsibility).
