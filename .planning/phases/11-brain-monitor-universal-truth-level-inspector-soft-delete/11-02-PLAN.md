# Plan 11-02 — Migration 0018: v_brain_events SQL view + composite indexes

## Section 1 — Goal

Create the `v_brain_events` SQL VIEW that UNIONs `memory_items`, `conversations`, `messages`, `team_messages`, `tasks`, and `contacts` into a single normalized event stream the brain monitor API queries. Also create the per-table `(team_scope/team_id, created_at DESC)` composite indexes that the view's predicate pushdown relies on for performance. This is a separate migration (0018) from 0017 because (a) the view references columns added in 0017 (logical dependency) and (b) a view-only migration is easy to drop/recreate when adding a new entity type later.

After this plan: `SELECT * FROM v_brain_events WHERE team_scope = 'default' ORDER BY created_at DESC LIMIT 50` returns a unified, normalized event feed at sub-50ms latency. BMO-02 is satisfied at the DB layer.

## Section 2 — Files touched

- `apps/memory-api/alembic/versions/0018_brain_events_view.py` — CREATE — Alembic migration with `CREATE OR REPLACE VIEW v_brain_events` and supporting indexes.
- `apps/memory-api/tests/test_migration_0018.py` — CREATE — assert the view exists and returns the 6 expected `entity_type` literals after inserting a fixture row per table.

## Section 3 — Tasks

### Task 1 — Create migration 0018_brain_events_view

**File(s):** `apps/memory-api/alembic/versions/0018_brain_events_view.py`

**What:** New Alembic file with `revision = "0018_brain_events_view"` and `down_revision = "0017_brain_monitor_base"`. The `upgrade()` body:

1. Create supporting composite indexes (idempotent — use `IF NOT EXISTS` via raw SQL since some may exist):
   - `CREATE INDEX IF NOT EXISTS idx_memory_team_created ON memory_items (team_scope, created_at DESC)`
   - `CREATE INDEX IF NOT EXISTS idx_conv_team_created ON conversations (team_scope, created_at DESC)`
   - `CREATE INDEX IF NOT EXISTS idx_msg_team_created ON messages (team_scope, created_at DESC)`
   - `CREATE INDEX IF NOT EXISTS idx_tasks_team_created ON tasks (team_scope, created_at DESC)`
   - `CREATE INDEX IF NOT EXISTS idx_contacts_team_created ON contacts (team_scope, created_at DESC)`
   - `idx_team_messages_team_created` already exists per migration 0015 — skip.
   - Optional partial index for performance: `CREATE INDEX IF NOT EXISTS idx_tasks_team_active ON tasks (team_scope, created_at DESC) WHERE deleted_at IS NULL` (repeat per table). Decide at planner discretion — for Phase 11 row counts these partial indexes are nice-to-have, not required.

2. `op.execute(sa.text("CREATE OR REPLACE VIEW v_brain_events AS ..."))` with the UNION ALL body from RESEARCH §Q2 (reproduced below):

```sql
CREATE OR REPLACE VIEW v_brain_events AS
SELECT
  CASE WHEN mi.source = 'granola' THEN 'granola_note' ELSE 'memory_item' END AS entity_type,
  mi.id           AS entity_id,
  t.id            AS team_id,
  mi.team_scope,
  mi.created_at,
  NULL::UUID      AS created_by,
  mi.truth_level,
  mi.deleted_at,
  mi.deleted_by,
  LEFT(mi.content, 200) AS preview,
  mi.source
FROM memory_items mi
JOIN teams t ON t.slug = mi.team_scope
UNION ALL
SELECT 'conversation', c.id, t.id, c.team_scope, c.created_at,
       c.owner_user_id, c.truth_level, c.deleted_at, c.deleted_by,
       LEFT(COALESCE(c.title, c.source), 200), c.source
FROM conversations c JOIN teams t ON t.slug = c.team_scope
UNION ALL
SELECT 'message', m.id, t.id, m.team_scope, m.created_at,
       NULL::UUID, m.truth_level, m.deleted_at, m.deleted_by,
       LEFT(m.content, 200), m.source
FROM messages m JOIN teams t ON t.slug = m.team_scope
UNION ALL
SELECT 'team_message', tm.id, tm.team_id, t.slug AS team_scope, tm.created_at,
       tm.author_user_id, tm.truth_level, tm.deleted_at, tm.deleted_by,
       LEFT(tm.content, 200), COALESCE(tm.routed_via, tm.kind)
FROM team_messages tm JOIN teams t ON t.id = tm.team_id
UNION ALL
SELECT 'task', tk.id, t.id, tk.team_scope, tk.created_at,
       tk.created_by, tk.truth_level, tk.deleted_at, tk.deleted_by,
       LEFT(tk.title, 200), tk.source
FROM tasks tk JOIN teams t ON t.slug = tk.team_scope
UNION ALL
SELECT 'contact', co.id, t.id, co.team_scope, co.created_at,
       NULL::UUID, co.truth_level, co.deleted_at, co.deleted_by,
       LEFT(COALESCE(co.full_name, co.email, '(unnamed)'), 200), co.source
FROM contacts co JOIN teams t ON t.slug = co.team_scope;
```

`downgrade()`: `op.execute("DROP VIEW IF EXISTS v_brain_events")`, then drop the new composite indexes in reverse order with `IF EXISTS`.

**Why:** BMO-02. Single SQL view = single query surface, predicate pushdown via per-table indexes keeps the UNION fast through 100k rows/team. Postgres recomputes the view per query (no materialization), so writes incur zero cost.

**Acceptance:** From the memory-api container: `alembic upgrade head` succeeds. Then `psql -c "SELECT entity_type, COUNT(*) FROM v_brain_events WHERE team_scope = 'default' GROUP BY entity_type"` returns 0 or more rows per `entity_type` without error. `psql -c "EXPLAIN ANALYZE SELECT * FROM v_brain_events WHERE team_scope='default' ORDER BY created_at DESC LIMIT 50"` shows Index Scan plans on each arm (not Seq Scan) on at least the largest tables.

**Commit message:** `feat(memory-api): migration 0018 — v_brain_events universal event view`

## Section 4 — Risks + Mitigations

- **Risk: Postgres view recompilation cost when adding columns later.** Mitigation: Postgres requires `DROP VIEW + CREATE VIEW` (no `ALTER VIEW ADD COLUMN`). Future migrations adding columns to v_brain_events MUST follow the drop-recreate pattern. Document this convention in the migration's leading docstring.
- **Risk: tables empty at upgrade time, view returns 0 rows.** Mitigation: that's expected; the view is a query template. Smoke test seeds rows itself.
- **Risk: `team_messages.routed_via` column may not exist (depends on Phase 9 deploy state).** Mitigation: check `information_schema.columns` for `team_messages.routed_via` before relying on it in the view. If missing, fall back to just `tm.kind AS source`. Document the check in the migration body.
- **Risk: predicate pushdown fails on UNION ALL.** Mitigation: Postgres ≥ 12 (we run 17) handles predicate pushdown through UNION ALL for filters on `team_scope`, `deleted_at`, and `created_at` when each arm exposes the same column. The 6 arms are designed to share these column names. Tested by the EXPLAIN check in Task 1 acceptance.
- **Risk: LEFT(content, 200) preserves only the start of long text — UX may want richer preview later.** Mitigation: out of scope for Phase 11; the UI shows 200 chars per the locked decision. A future iteration can swap to a smarter `regexp_replace` if needed.
