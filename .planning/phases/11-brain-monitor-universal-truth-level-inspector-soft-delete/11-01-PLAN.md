## Section 1 — Goal

Add the universal tagging contract columns (`truth_level` + `deleted_at` + `deleted_by`) to every entity table that lacks them, with CHECK constraints, defaults, and per-table indexes for retrieval performance. Also synchronize the SQLAlchemy ORM models so application code can read/write these columns through the typed model layer. This is the schema foundation for BMO-01 and is a prerequisite for every other Phase 11 plan.

After this plan: the DB head is `0017_brain_monitor_base`, all six target tables expose the three new columns (those that don't already have them), and ORM models stay in sync with the DDL. No view yet (that ships in 11-02) and no endpoint yet (11-04/05).

> **REVISION 1 (B-1):** `down_revision` is fixed to `0016_phase10_github_primary` (Phase 10's actual revision name, confirmed in `apps/memory-api/alembic/versions/0016_phase10_github_primary.py`). The previous draft incorrectly used `0015_team_messages`, which would skip the Phase 10 schema. This is no longer optional — see Section 0 Entry Gate.

In `upgrade()`:

1. **`memory_items`**: `op.add_column(sa.Column("deleted_at", sa.TIMESTAMP(timezone=True), nullable=True))` + `op.add_column(sa.Column("deleted_by", postgresql.UUID(as_uuid=True), sa.ForeignKey("users.id", ondelete="SET NULL"), nullable=True))` + `op.create_index("idx_memory_team_deleted", "memory_items", ["team_scope", "deleted_at"])`.
2. **`conversations`**: add `truth_level TEXT NOT NULL DEFAULT 'EPHEMERAL'` (server_default `"'EPHEMERAL'"`) + CHECK constraint `conversations_truth_level_check` allowing `('EPHEMERAL','WORKING','VALIDATED','CANONICAL','PUBLIC')` + same `deleted_at`/`deleted_by` columns + index `idx_conv_team_deleted`.
3. **`messages`**: add `deleted_at`/`deleted_by` + index `idx_msg_team_deleted`. **DO NOT** add `truth_level` (already present per migration 0001).
4. **`team_messages`**: add `truth_level TEXT NOT NULL DEFAULT 'WORKING'` + CHECK constraint `team_messages_truth_level_check` + `deleted_by` (deleted_at already exists per migration 0015) + index `idx_team_messages_deleted` on `(team_id, deleted_at)`.
5. **`tasks`**: add `truth_level TEXT NOT NULL DEFAULT 'WORKING'` + CHECK `tasks_truth_level_check` + `deleted_at`/`deleted_by` + index `idx_tasks_team_deleted`.
6. **`contacts`**: add `deleted_at`/`deleted_by` + index `idx_contacts_team_deleted`. **DO NOT** add `truth_level` (already present per migration 0009 with DEFAULT `'EPHEMERAL'` and its own CHECK).

In `downgrade()`: reverse-order drops — drop indexes, drop CHECK constraints by name, drop columns. Use `if_exists=True` where supported.

**Why:** BMO-01. Defaults are chosen per CONTEXT.md locked decisions: tasks/contacts/team_messages → `WORKING`, conversations → `EPHEMERAL`. `contacts.truth_level` keeps its existing `'EPHEMERAL'` default from 0009 — DO NOT redefine; the Pydantic body default is changed at the API layer if/when needed (out of scope here).

**Acceptance:** From the memory-api container: `alembic upgrade head` succeeds without error. Then `psql -c "SELECT column_name FROM information_schema.columns WHERE table_name IN ('conversations','tasks','team_messages','memory_items','contacts','messages') AND column_name IN ('truth_level','deleted_at','deleted_by') ORDER BY table_name, column_name"` shows the expected matrix (12 new column rows total). `alembic downgrade -1` then `alembic upgrade head` round-trips cleanly. After upgrade, `psql -c "SELECT version_num FROM alembic_version"` returns `0017_brain_monitor_base`.

**Commit message:** `feat(memory-api): migration 0017 — universal truth_level + soft-delete columns`

## Section 4 — Risks + Mitigations

- **Risk: Phase 10 is reverted after this plan ships (unlikely).** Mitigation: if `0016_phase10_github_primary` is ever rolled back, this migration is incompatible with the resulting DB state. Re-run `/gsd-plan-phase 11` to regenerate plans against the new schema head.
- **Risk: contacts.truth_level CHECK constraint name collision.** Mitigation: the migration MUST NOT touch the existing `contacts_truth_level_check` from 0009. Only add `deleted_at`/`deleted_by` columns and one new index on contacts.
- **Risk: server_default casing — `'WORKING'` literal vs Python `default="WORKING"`.** Mitigation: set BOTH `server_default="'WORKING'"` in Alembic AND `default="WORKING"` in the ORM model so INSERTs from either path get the right value.
- **Risk: index creation table lock blocks concurrent traffic.** Mitigation: current row counts are small (<10k/table per RESEARCH Q9); standard `CREATE INDEX` inside the transaction is acceptable. Document in the migration docstring: if ever re-run on a larger DB, switch to `op.create_index(..., postgresql_concurrently=True)` inside `with op.get_context().autocommit_block():`.
- **Risk: foreign key `deleted_by → users(id)` cascade.** Mitigation: use `ON DELETE SET NULL` (matches the existing `tasks.created_by` pattern from migration 0010). A purged user must not cascade-delete the brain item.
