# Plan 11-05 — PATCH truth_level + DELETE soft + POST restore on `/v1/brain/events/{entity_type}/{entity_id}`

## Section 1 — Goal

Add the three mutation endpoints on top of the brain router from 11-04: `PATCH` sets `truth_level`, `DELETE` soft-deletes (sets `deleted_at` + `deleted_by`, also flips Qdrant payload for memory_items via the 11-03 helper), and `POST .../restore` clears the soft-delete within the 30-day retention window. Every mutation writes a row to `audit_log`. Authorization uses `assert_can_edit_brain_event` from 11-04. This plan delivers BMO-04, BMO-05, BMO-06 end-to-end.

After this plan: `curl -X PATCH ... -d '{"truth_level":"VALIDATED"}'` updates the entity in-place; `curl -X DELETE ...` returns 204 and the row disappears from default list views; `curl -X POST .../restore` brings it back if within 30 days.

### Task 1 — Brain repo helper (REVISION 1 — fixes M-1)

```python
"""Phase 11 — brain repo: typed dispatch from (entity_type, entity_id) to underlying tables."""
from __future__ import annotations

from datetime import datetime, timezone
from typing import Mapping
from uuid import UUID

import sqlalchemy as sa
from fastapi import HTTPException
from sqlalchemy.ext.asyncio import AsyncSession

# Closed allowlist — keys are user-supplied via the URL path, values are hard-coded
# table names. Any unknown entity_type returns 400 at the route layer before this
# resolver runs, so the f-string substitution below is safe (no user-controlled
# table-name interpolation).
ENTITY_TABLE_MAP: dict[str, str] = {
    "memory_item": "memory_items",
    "granola_note": "memory_items",   # special: same table, identified via source='granola'
    "conversation": "conversations",
    "message": "messages",
    "team_message": "team_messages",
    "task": "tasks",
    "contact": "contacts",
}

ALLOWED_ENTITY_TYPES = frozenset(ENTITY_TABLE_MAP.keys())


def _resolve_table(entity_type: str) -> str:
    if entity_type not in ENTITY_TABLE_MAP:
        raise HTTPException(400, f"unknown entity_type: {entity_type}")
    return ENTITY_TABLE_MAP[entity_type]


async def fetch_event_row(
    session: AsyncSession,
    entity_type: str,
    entity_id: UUID,
    team_slug: str,
) -> Mapping | None:
    """Fetch a single brain event row by (entity_type, entity_id) scoped to team_slug.

    Returns the raw row from v_brain_events (uniform schema) or None.
    The team_slug scope is enforced by the v_brain_events view's WHERE.
    """
    sql = """
        SELECT * FROM v_brain_events
        WHERE entity_type = :et AND entity_id = :id AND team_scope = :ts
    """
    return (await session.execute(
        sa.text(sql), {"et": entity_type, "id": str(entity_id), "ts": team_slug}
    )).mappings().fetchone()


async def update_truth_level(
    session: AsyncSession,
    entity_type: str,
    entity_id: UUID,
    new_value: str,
) -> bool:
    """Set truth_level on the underlying table. Returns True if a row was updated.

    Caller is responsible for session.commit().
    """
    table = _resolve_table(entity_type)
    sql = f"UPDATE {table} SET truth_level = :tl WHERE id = :id RETURNING id"
    result = await session.execute(sa.text(sql), {"tl": new_value, "id": str(entity_id)})
    return result.first() is not None


async def soft_delete_entity(
    session: AsyncSession,
    entity_type: str,
    entity_id: UUID,
    deleted_by_user_id: UUID,
) -> datetime:
    """Set deleted_at = now() (Python clock) and deleted_by on the row.

    Returns the deleted_at timestamp so the caller can pass the same wall-clock
    value to NativeProvider.mark_deleted() for the Qdrant payload (RESEARCH §Q3:
    PG and Qdrant clocks must not drift on the soft-delete moment).

    Raises 404 if no row was updated (already deleted or wrong scope).
    Caller is responsible for session.commit().
    """
    table = _resolve_table(entity_type)
    now = datetime.now(tz=timezone.utc)
    sql = f"""
        UPDATE {table}
        SET deleted_at = :now, deleted_by = :uid
        WHERE id = :id AND deleted_at IS NULL
        RETURNING id
    """
    result = await session.execute(
        sa.text(sql),
        {"now": now, "uid": str(deleted_by_user_id), "id": str(entity_id)},
    )
    if result.first() is None:
        raise HTTPException(404, "entity not found or already deleted")
    return now


async def restore_entity(
    session: AsyncSession,
    entity_type: str,
    entity_id: UUID,
) -> bool:
    """Clear deleted_at + deleted_by IFF deleted_at > now() - 30 days (retention window).

    Returns True on successful restore. Raises 410 Gone if the row is outside the
    retention window (already purged or eligible for purge). Raises 404 if no
    soft-deleted row exists for this id.
    Caller is responsible for session.commit().
    """
    table = _resolve_table(entity_type)
    sql = f"""
        UPDATE {table}
        SET deleted_at = NULL, deleted_by = NULL
        WHERE id = :id
          AND deleted_at IS NOT NULL
          AND deleted_at > NOW() - INTERVAL '30 days'
        RETURNING id
    """
    result = await session.execute(sa.text(sql), {"id": str(entity_id)})
    if result.first() is None:
        # Distinguish "no soft-deleted row at all" (404) from "outside window" (410)
        check = await session.execute(
            sa.text(f"SELECT deleted_at FROM {table} WHERE id = :id"),
            {"id": str(entity_id)},
        )
        existing = check.scalar()
        if existing is None:
            raise HTTPException(404, "entity not found")
        if existing is not None:
            raise HTTPException(410, "retention window expired (>30 days since soft-delete)")
        return False
    return True
```

> **REVISION 1 (M-1):** `soft_delete_entity` and `restore_entity` are full implementations, not stubs. They return enough information for the route handler to (a) write the audit log row, (b) call Qdrant `mark_deleted` with the same wall-clock value PG used (no clock drift), (c) distinguish 404 vs 410 on restore.
>
> The `f"UPDATE {table} ..."` interpolation is SAFE because `_resolve_table()` accepts only keys from the closed `ENTITY_TABLE_MAP` allowlist — user input never reaches the f-string. Any unknown entity_type raises 400 before the SQL is built.

**Why:** Centralizes the per-entity dispatch and SQL. Keeps the router endpoint thin and makes the auth/audit/Qdrant-sync ordering explicit in the route, not buried in the repo.

**Acceptance:** Direct repo unit test (`test_brain_repo.py` — can be folded into Task 3's test file):

1. Insert a task. Call `soft_delete_entity(session, 'task', task_id, user_id)` → returns a `datetime`. SELECT shows `deleted_at IS NOT NULL`.
2. Calling it again → raises HTTPException 404.
3. Call `restore_entity(session, 'task', task_id)` → returns True. SELECT shows `deleted_at IS NULL`.
4. Manually set `deleted_at = now() - INTERVAL '31 days'` for another row. Call `restore_entity` → raises HTTPException 410.
5. Use `freezegun` (or equivalent time-travel helper) to fast-forward 31 days after soft-delete, then attempt restore → 410.

`python -c "from app.repos.brain import fetch_event_row, update_truth_level, soft_delete_entity, restore_entity; print('ok')"` resolves all imports.

```python
@router.patch("/events/{entity_type}/{entity_id}", response_model=BrainEventOut)
async def patch_truth_level(
    entity_type: str,
    entity_id: UUID,
    body: TruthLevelPatchBody,
    principal: dict = Depends(get_current_principal),
    session: AsyncSession = Depends(get_session),
    team_scope: str = Depends(get_team_scope),
):
    if entity_type not in ALLOWED_ENTITY_TYPES:
        raise HTTPException(400, f"unknown entity_type: {entity_type}")
    row = await fetch_event_row(session, entity_type, entity_id, team_scope)
    if row is None:
        raise HTTPException(404, "brain event not found in this team")
    await assert_can_edit_brain_event(
        principal, created_by=row["created_by"], team_slug=team_scope, session=session
    )
    updated = await update_truth_level(session, entity_type, entity_id, body.truth_level)
    if not updated:
        raise HTTPException(404, "brain event vanished mid-update")
    await session.execute(sa.text("""
        INSERT INTO audit_log (actor_user_id, action, entity_type, entity_id, team_scope, metadata)
        VALUES (:uid, 'brain.patch_truth_level', :et, :id, :ts, :meta::jsonb)
    """), {
        "uid": _user_id_from_principal(principal),
        "et": entity_type, "id": str(entity_id), "ts": team_scope,
        "meta": json.dumps({"new_truth_level": body.truth_level, "old_truth_level": row["truth_level"]}),
    })
    await session.commit()
    new_row = await fetch_event_row(session, entity_type, entity_id, team_scope)
    return BrainEventOut(**dict(new_row))


@router.delete("/events/{entity_type}/{entity_id}", status_code=204)
async def soft_delete_event(
    entity_type: str,
    entity_id: UUID,
    principal: dict = Depends(get_current_principal),
    session: AsyncSession = Depends(get_session),
    team_scope: str = Depends(get_team_scope),
):
    if entity_type not in ALLOWED_ENTITY_TYPES:
        raise HTTPException(400, f"unknown entity_type: {entity_type}")
    row = await fetch_event_row(session, entity_type, entity_id, team_scope)
    if row is None:
        raise HTTPException(404, "brain event not found in this team")
    await assert_can_edit_brain_event(
        principal, created_by=row["created_by"], team_slug=team_scope, session=session
    )
    user_id = _user_id_from_principal(principal)
    deleted_at = await soft_delete_entity(session, entity_type, entity_id, user_id)

    # Audit
    await session.execute(sa.text("""
        INSERT INTO audit_log (actor_user_id, action, entity_type, entity_id, team_scope, metadata)
        VALUES (:uid, 'brain.soft_delete', :et, :id, :ts, '{}'::jsonb)
    """), {"uid": user_id, "et": entity_type, "id": str(entity_id), "ts": team_scope})
    await session.commit()

    # Qdrant sync — best-effort. PG is source of truth.
    if entity_type in {"memory_item", "granola_note"}:
        try:
            await native_provider.mark_deleted(entity_id, deleted_at)
        except Exception as exc:
            logger.warning("qdrant mark_deleted failed for %s: %s — janitor will reconcile", entity_id, exc)


@router.post("/events/{entity_type}/{entity_id}/restore", response_model=BrainEventOut)
async def restore_event(
    entity_type: str,
    entity_id: UUID,
    principal: dict = Depends(get_current_principal),
    session: AsyncSession = Depends(get_session),
    team_scope: str = Depends(get_team_scope),
):
    if entity_type not in ALLOWED_ENTITY_TYPES:
        raise HTTPException(400, f"unknown entity_type: {entity_type}")
    # Fetch including deleted rows — restore needs to see soft-deleted state.
    row = (await session.execute(sa.text(
        "SELECT * FROM v_brain_events WHERE entity_type=:et AND entity_id=:id AND team_scope=:ts"
    ), {"et": entity_type, "id": str(entity_id), "ts": team_scope})).mappings().fetchone()
    # Note: v_brain_events does NOT filter deleted_at — it's the underlying tables that
    # may filter in 11-06. Confirm in 11-02 the view shows all rows including deleted.
    if row is None:
        raise HTTPException(404, "brain event not found in this team")
    await assert_can_edit_brain_event(
        principal, created_by=row["created_by"], team_slug=team_scope, session=session
    )
    user_id = _user_id_from_principal(principal)
    await restore_entity(session, entity_type, entity_id)   # raises 410 if outside window

    await session.execute(sa.text("""
        INSERT INTO audit_log (actor_user_id, action, entity_type, entity_id, team_scope, metadata)
        VALUES (:uid, 'brain.restore', :et, :id, :ts, '{}'::jsonb)
    """), {"uid": user_id, "et": entity_type, "id": str(entity_id), "ts": team_scope})
    await session.commit()

    if entity_type in {"memory_item", "granola_note"}:
        try:
            await native_provider.mark_restored(entity_id)
        except Exception as exc:
            logger.warning("qdrant mark_restored failed for %s: %s — janitor will reconcile", entity_id, exc)

    new_row = await fetch_event_row(session, entity_type, entity_id, team_scope)
    return BrainEventOut(**dict(new_row))
```

Helper `_user_id_from_principal(principal)` — handles the same 5 principal shapes documented in 11-04 Task 2: returns `principal['user'].id` for `kind='user'` or `kind='user_api_token'`; for `kind='bridge'` returns a sentinel `NIL_UUID` (or pulls from `claims['sub']` if available — implementer's choice, consistent with existing audit-log patterns in `tasks.py` / `crm.py`).

The Qdrant helper calls (`mark_deleted`/`mark_restored`) MUST be wrapped in a try/except — Qdrant failure must NOT roll back the Postgres soft-delete (log a warning and continue). RESEARCH §Q3 confirms this is the only way to keep PG and Qdrant from drifting under partial failure. The janitor (11-07) reconciles at 03:00 UTC daily.

**Why:** BMO-04 + BMO-05 + BMO-06. Audit log entries satisfy CONTEXT's "audit_log already captures it backend-side" promise. The wall-clock `deleted_at` returned from the repo flows directly into `mark_deleted` so the Qdrant payload epoch matches the PG column exactly.

**Acceptance:** `curl -X PATCH -H 'Authorization: Bearer $XBT' -H 'X-Team-Scope: default' -H 'Content-Type: application/json' -d '{"truth_level":"VALIDATED"}' "$MEMAPI_HOST/v1/brain/events/task/$TASK_ID"` returns 200 + the updated row. `curl -X DELETE ...` returns 204. `curl -X POST .../restore` returns 200. `psql -c "SELECT action, entity_type FROM audit_log WHERE entity_id='$TASK_ID' ORDER BY created_at DESC LIMIT 3"` shows the three audit rows.

## Section 4 — Risks + Mitigations

- **Risk: dual-write divergence between PG and Qdrant on partial failure.** Mitigation: PG is the source of truth. Qdrant `mark_deleted` failure logged but not propagated. Janitor (plan 11-07) re-syncs at 03:00 UTC daily by querying PG `WHERE deleted_at IS NOT NULL` and force-flipping every Qdrant point.
- **Risk: PATCH on `granola_note` writes to `memory_items` table — caller could craft `entity_type=granola_note` for a non-granola memory item.** Mitigation: in `fetch_event_row`, the view returns `entity_type='granola_note'` only when `source='granola'`. The `WHERE entity_type=:et AND entity_id=:id` filter on the view enforces this — a non-granola item returns NULL → 404.
- **Risk: `sa.func.now()` in Python comparison.** Mitigation: the repo uses `datetime.now(tz=timezone.utc)` for the value passed to BOTH PG (via bind param) and Qdrant (via the same returned datetime). No `sa.func.now()` anywhere in this plan.
- **Risk: audit_log JSONB cast.** Mitigation: use `:meta::jsonb` cast in SQL with `json.dumps(...)` Python-side. Verified pattern from existing routers (`crm.py`, `tasks.py`).
- **Risk: f-string SQL on table name.** Mitigation: `_resolve_table()` strictly enforces the closed `ENTITY_TABLE_MAP` allowlist. Unknown values raise 400 before the f-string runs. No user input reaches the table-name interpolation.
- **Risk: 11-04 and 11-05 both edit `routes/brain.py`.** Mitigation: 11-05 is wave 3c (sequential after 11-04 wave 3b). No parallel edit.
