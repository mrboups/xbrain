# Plan 11-11 — app-site `/account/admin/` superadmin dashboard UI

## Section 1 — Goal

Ship the superadmin-only dashboard at `https://app.grooveos.app/account/admin/`. A logged-in superadmin sees 4 sections — Brain Overview (counts × truth_level × entity_type matrix per team), Storage (PG rows + Qdrant points + MinIO bytes per team), Activity (30-day events/day sparkline per team), Top Sources (LibreChat/OWUI/Granola/agent/API breakdown per team). A "Drill down" button per team row routes to the existing Brain Monitor (`/account/teams/brain/?team=<slug>`) with a yellow banner reading "Viewing as superadmin — this access is logged." Non-superadmins hitting the page see a 403 message and a link back to `/account/teams/`. Satisfies BMO-12 + Success Criteria 8 & 9 (UI portion).

After this plan: a superadmin can open the page, see at least 2 teams, click drill-down on any team, and see the brain monitor with the superadmin banner. A non-superadmin sees the 403 page.

### Task 1 — Page shell + auth + superadmin detection + 403 fallback

**File(s):** `app-site/account/admin/index.html`, `app-site/account/admin/admin.js`, `app-site/account/admin/admin.css`

**What:**

`index.html`: Copy the `<head>` from `app-site/account/teams/index.html` (Google Fonts JetBrains Mono, viewport, CSS variables). Body:
- Header bar: "xbrain · superadmin dashboard" + user email + sign-out button (same as teams page).
- Main content `<main id="app">` with 4 placeholder sections, each `<section id="section-{overview|storage|activity|sources}">`. Each section has an `<h2>` title, a `<div class="section-content">` for the rendered table/sparkline, and a `<div class="section-loading">Loading…</div>` shown until data arrives.
- A hidden `<div id="forbidden-fallback">` with the 403 message (revealed if superadmin probe fails).

`admin.js` skeleton:
```js
const MEMORY_API_BASE = "https://api.grooveos.app";
const state = {
  xbt: localStorage.getItem("xbrain_xbt_token"),
  isSuperadmin: null,            // null = unknown, true/false after probe
  overview: null,
  storage: null,
  activity: null,
  sources: null,
};

async function probeSuperadmin() {
  // PROBE STRATEGY (decision: probe-and-403, not a new /v1/me field):
  // Hit GET /v1/admin/brain/overview. 200 → user is superadmin. 403 → not. Other → error.
  // Rationale: avoids a new memory-api endpoint and ships in 0 extra backend work.
  // Trade-off: the probe doubles as the first data load, so on success we cache the
  // overview response into state.overview and skip the second fetch in renderOverview().
  const resp = await fetch(`${MEMORY_API_BASE}/v1/admin/brain/overview`, {
    headers: { Authorization: `Bearer ${state.xbt}` },
  });
  if (resp.status === 200) {
    state.isSuperadmin = true;
    state.overview = await resp.json();      // cache probe response — reused by renderOverview
    return true;
  }
  if (resp.status === 403) {
    state.isSuperadmin = false;
    return false;
  }
  throw new Error(`probe failed: ${resp.status}`);
}

async function init() {
  if (!state.xbt) {
    // No token → redirect to teams page (existing auth gate handles sign-in)
    location.href = "/account/teams/";
    return;
  }
  try {
    const ok = await probeSuperadmin();
    if (!ok) {
      document.getElementById("forbidden-fallback").hidden = false;
      document.getElementById("app").hidden = true;
      return;
    }
    // Concurrent fetch for the remaining 3 sections (overview already cached from probe)
    await Promise.all([loadStorage(), loadActivity(), loadSources()]);
    renderOverview();
    renderStorage();
    renderActivity();
    renderSources();
  } catch (exc) {
    console.error("admin init failed", exc);
    document.getElementById("forbidden-fallback").hidden = false;
    document.getElementById("forbidden-fallback").querySelector(".reason").textContent =
      `Error loading dashboard: ${exc.message}`;
  }
}

document.addEventListener("DOMContentLoaded", init);
```

`#forbidden-fallback` HTML:
```html
<div id="forbidden-fallback" hidden class="forbidden">
  <h2>Access denied</h2>
  <p class="reason">You are not a superadmin. This page is restricted.</p>
  <a href="/account/teams/">← Back to teams</a>
</div>
```

`admin.css`: dark theme matching app-site, 4 section cards in a vertical stack (no tabs in v1 — simpler scroll), 16px padding, `.forbidden` styled as centered warning panel.

**Superadmin detection decision (resolves "probe vs /v1/me" ambiguity):** Use the probe-and-403 strategy. Rationale:
1. Zero backend change required (no new endpoint to plan/ship).
2. The probe IS the first data fetch — cached into `state.overview` so we save one round trip.
3. Failure mode is clear and isolated (403 → show fallback; other error → show error with reason).
4. If a future phase adds `/v1/me { is_superadmin: bool }`, the probe pattern still works as a fallback path. Document the decision in the file header comment.

**Why:** No data leaks to a non-superadmin (the 403 from the API is authoritative — UI just renders accordingly). Single auth path; no new endpoints.

**Acceptance:**
- Open page as a superadmin → 4 sections render with data.
- Open page as a non-superadmin → only the "Access denied" panel visible; no data fetched beyond the probe.
- Open page with no localStorage token → redirect to `/account/teams/`.
- Network panel confirms: superadmin sees 4 GET requests; non-superadmin sees 1 GET (the probe).

**Commit message:** `feat(app-site): superadmin dashboard shell + auth probe + 403 fallback`

### Task 2 — Brain Overview matrix section

**File(s):** `app-site/account/admin/admin.js` (extend), `app-site/account/admin/admin.css` (extend)

**What:**

`renderOverview()` consumes `state.overview` (already cached from probe):
- Build a table where rows = teams, columns = entity_types (7: memory_item, conversation, message, team_message, task, contact, granola_note).
- Each cell shows the sum of truth_level counts for that team × entity_type. Hover tooltip (title attribute or custom tooltip div) shows the per-truth_level breakdown, e.g.:
  ```
  EPHEMERAL: 5
  WORKING:   12
  VALIDATED: 3
  CANONICAL: 1
  PUBLIC:    0
  ```
- "Drill down" button at end of each team row → navigates to `/account/teams/brain/?team={team_slug}&as_superadmin=1`.
- Discover entity_types dynamically from the response (don't hardcode the list — if 11-02 view adds a new arm later, the matrix expands automatically).

Empty state: if `state.overview.length === 0`, render `<p class="empty">No teams found.</p>`.

```js
function renderOverview() {
  const root = document.querySelector("#section-overview .section-content");
  const data = state.overview;
  if (!data || data.length === 0) {
    root.innerHTML = `<p class="empty">No teams found.</p>`;
    return;
  }
  // Collect entity_types in stable order (sorted alphabetically)
  const entityTypes = Array.from(
    new Set(data.flatMap(t => Object.keys(t.counts)))
  ).sort();
  // Build header
  let html = `<table class="matrix"><thead><tr><th>Team</th>`;
  for (const et of entityTypes) html += `<th>${escapeHtml(et)}</th>`;
  html += `<th>Actions</th></tr></thead><tbody>`;
  for (const team of data) {
    html += `<tr><td class="team-name">${escapeHtml(team.team_slug)}</td>`;
    for (const et of entityTypes) {
      const truths = team.counts[et] || {};
      const total = Object.values(truths).reduce((a, b) => a + b, 0);
      const tooltip = Object.entries(truths)
        .map(([tl, c]) => `${tl}: ${c}`).join("\n");
      html += `<td class="count" title="${escapeHtml(tooltip)}">${total}</td>`;
    }
    html += `<td><button class="drill-down" data-team="${escapeHtml(team.team_slug)}">Drill down →</button></td></tr>`;
  }
  html += `</tbody></table>`;
  root.innerHTML = html;
  // Event delegation for drill-down
  root.querySelectorAll(".drill-down").forEach(btn => {
    btn.addEventListener("click", () => {
      const team = btn.dataset.team;
      location.href = `/account/teams/brain/?team=${encodeURIComponent(team)}&as_superadmin=1`;
    });
  });
}
```

`escapeHtml` is a 3-line helper that replaces `& < > " '` (same as `teams.js` if present, else inline).

**Why:** BMO-12 + Success Criterion 8 (matrix view). Discovering entity_types dynamically future-proofs against view changes. Hover tooltip avoids cluttering the cell.

**Acceptance:** With dev DB ≥2 teams: matrix renders with 7+ columns + a Drill-down button per row. Hover on a cell shows the truth_level breakdown. Click drill-down → navigates to the correct URL.

**Commit message:** `feat(app-site): superadmin overview matrix + drill-down navigation`

### Task 3 — Storage section

**File(s):** `app-site/account/admin/admin.js` (extend), `app-site/account/admin/admin.css` (extend)

**What:**

`loadStorage()` fetches `GET /v1/admin/brain/storage` → `state.storage`. `renderStorage()` builds a table:
- Rows: teams (one per team).
- Columns: Team | PG rows (sum across the 6 tables, with per-table breakdown in tooltip) | Qdrant points | MinIO bytes (human-readable via a `humanBytes(n)` helper) | Actions (Drill down).
- Total row at bottom (sum across all teams).
- `qdrant_points === null` → cell displays "N/A" (rare; only if Qdrant call failed).
- `minio_bytes === null` → cell displays "N/A" (common in dev/test when MINIO not configured).

```js
function humanBytes(n) {
  if (n === null || n === undefined) return "N/A";
  if (n === 0) return "0 B";
  const units = ["B", "KB", "MB", "GB", "TB"];
  const i = Math.min(units.length - 1, Math.floor(Math.log(n) / Math.log(1024)));
  return `${(n / Math.pow(1024, i)).toFixed(1)} ${units[i]}`;
}
```

Total row aggregates: sum of all teams' PG row totals + sum of `qdrant_points` (skipping nulls) + sum of `minio_bytes` (skipping nulls).

**Why:** BMO-12 Storage section. Human-readable byte formatting is essential UX.

**Acceptance:** Storage table renders with 4 data columns + 1 actions column. Total row at bottom. With `minio_bytes=null` (dev): cells display "N/A". With dev DB: `pg_rows` shows per-table breakdown on hover.

**Commit message:** `feat(app-site): superadmin storage table + human-byte formatting`

### Task 4 — Activity section (sparklines)

**File(s):** `app-site/account/admin/admin.js` (extend), `app-site/account/admin/sparkline.js` (CREATE), `app-site/account/admin/admin.css` (extend)

**What:**

`sparkline.js` — minimal inline SVG sparkline component:
```js
// 30-line vanilla SVG sparkline. No dependencies.
//   container: HTMLElement to render into.
//   dailyData: [{date: 'YYYY-MM-DD', events: int}, ...] — always 30 entries (zero-filled).
//   opts: { width?: 200, height?: 40, color?: 'currentColor' }
export function renderSparkline(container, dailyData, opts = {}) {
  const width = opts.width || 200;
  const height = opts.height || 40;
  const color = opts.color || "currentColor";
  const max = Math.max(1, ...dailyData.map(d => d.events));    // avoid div-by-zero
  const min = 0;
  const padding = 2;
  const stepX = (width - 2 * padding) / Math.max(1, dailyData.length - 1);
  const points = dailyData.map((d, i) => {
    const x = padding + i * stepX;
    const y = height - padding - ((d.events - min) / (max - min || 1)) * (height - 2 * padding);
    return `${x.toFixed(1)},${y.toFixed(1)}`;
  }).join(" ");
  const totalEvents = dailyData.reduce((a, b) => a + b.events, 0);
  const ariaLabel = `30-day events: ${totalEvents} total, peak ${max} on a single day`;
  // Build per-point hover circles for tooltip via <title>
  const circles = dailyData.map((d, i) => {
    const x = padding + i * stepX;
    const y = height - padding - ((d.events - min) / (max - min || 1)) * (height - 2 * padding);
    return `<circle cx="${x.toFixed(1)}" cy="${y.toFixed(1)}" r="2" fill="${color}" opacity="0.6"><title>${d.date}: ${d.events}</title></circle>`;
  }).join("");
  container.innerHTML = `<svg width="${width}" height="${height}" role="img" aria-label="${ariaLabel}" viewBox="0 0 ${width} ${height}">
    <polyline points="${points}" fill="none" stroke="${color}" stroke-width="1.5" />
    ${circles}
  </svg>`;
}
```

`loadActivity()` fetches `GET /v1/admin/brain/activity?days=30` → `state.activity`. `renderActivity()` builds a table:
- Rows: one per team. Columns: Team | 30-day sparkline | Total events | Actions.
- Per team row, create a `<div class="sparkline-cell">`, call `renderSparkline(div, team.daily)`.
- Tooltip on each point (already in the SVG `<title>` element) shows the date + count.

Accessibility: each `<svg>` has `role="img"` + `aria-label` summarizing total + peak — screen readers get a meaningful summary.

**Why:** BMO-12 Activity section. Inline SVG avoids a chart library dependency (CONTEXT lock). The accessibility annotation is a 2-line cost.

**Acceptance:** Activity section renders 1 sparkline per team. Hover on a sparkline point shows the date + count tooltip. Page contains no Chart.js / D3 / external script tags.

**Commit message:** `feat(app-site): superadmin activity sparklines (inline SVG, no deps)`

### Task 6 — Brain monitor banner + admin endpoint substitution (cross-plan tweak)

**File(s):**
- `app-site/account/teams/brain/brain.js` — MODIFY: detect `as_superadmin=1` query param, substitute admin endpoint, render banner
- `app-site/account/teams/brain/index.html` — MODIFY: add hidden banner element (default `style="display:none"`)

**What:**

1. **Query param detection.** On page load, `brain.js` reads `URLSearchParams(window.location.search)`. If `as_superadmin === '1'`, set a module-level flag `IS_SUPERADMIN_VIEW = true`.

2. **Banner.** When `IS_SUPERADMIN_VIEW` is true, render the banner element with text exactly: `"Viewing as superadmin — this access is logged."` Style: yellow background (`background: #fef3c7; color: #92400e; padding: 12px 16px; border-left: 4px solid #f59e0b;`), positioned at top of the page above the filters. Add `role="status"` and `aria-live="polite"` for accessibility.

3. **API endpoint substitution.** This is the critical part. Today `loadEvents()` and `pollForNewItems()` call:
   ```
   GET /v1/brain/events?<filters>
   Header: X-Team-Scope: <slug>
   Authorization: Bearer <xbt_>
   ```
   When `IS_SUPERADMIN_VIEW` is true, they MUST call instead:
   ```
   GET /v1/admin/brain/events?team_slug=<slug>&<filters>
   Authorization: Bearer <xbt_>
   (NO X-Team-Scope header — the admin endpoint bypasses team-scope guard)
   ```
   Implement a helper:
   ```javascript
   function buildBrainEventsRequest(filters, slug) {
     if (IS_SUPERADMIN_VIEW) {
       const qs = new URLSearchParams({ team_slug: slug, ...filters });
       return {
         url: `/v1/admin/brain/events?${qs}`,
         headers: { 'Authorization': `Bearer ${getXbtToken()}` },
       };
     }
     const qs = new URLSearchParams(filters);
     return {
       url: `/v1/brain/events?${qs}`,
       headers: {
         'Authorization': `Bearer ${getXbtToken()}`,
         'X-Team-Scope': slug,
       },
     };
   }
   ```
   `loadEvents()`, `pollForNewItems()`, AND every PATCH/DELETE/restore call must route through this helper (or analogous helpers for the write endpoints — note that PATCH/DELETE/restore endpoints from 11-04/11-05 are also team-scoped; the superadmin will get 403 on those unless we either (a) provide admin variants or (b) hide the edit/delete buttons in superadmin view). For Phase 11 v1, **hide edit/delete buttons when `IS_SUPERADMIN_VIEW` is true** — superadmins are read-only on drill-down. Edit actions are out of scope for this UX path. Document this decision in a 1-line comment in brain.js.

4. **Banner visibility.** Banner is hidden by default. Only shown when `IS_SUPERADMIN_VIEW === true`.

5. **Query param preservation in pagination/filters.** When the user changes filters or pages, the `as_superadmin=1` flag must persist in the URL — use `URLSearchParams.set('as_superadmin', '1')` whenever updating the URL.

**Why:**

- SC-9 (ROADMAP lock): every drill-down must write `audit_log`. Only `/v1/admin/brain/events` writes audit_log (per 11-10 Task 4). The team-scoped `/v1/brain/events` doesn't (and shouldn't — normal team members don't need to be audited reading their own team).
- `get_team_scope` in `deps.py:216-242` only bypasses for `kind='bridge'`. A `kind='user'` superadmin who isn't a member of the target team gets 403 on `/v1/brain/events`. The admin endpoint is the only path that works.
- Hiding edit buttons keeps Phase 11 simple — superadmin drill-down is read-only. Phase 12+ can ship admin variants of PATCH/DELETE/restore if needed.

**Acceptance:**

1. **Manual test:** open `/account/teams/brain/?team=other-team&as_superadmin=1` as a superadmin user → banner visible, list loads, Network tab shows `GET /v1/admin/brain/events?team_slug=other-team` (NOT `/v1/brain/events`), no `X-Team-Scope` header on that call.
2. **Audit verification (matches verify-phase11.sh assertion 15):** after 1 drill-down session = exactly 1 new row in `audit_log` with `action='superadmin_brain_access'` and `team_scope='other-team'`.
3. **403 path for non-superadmin:** open same URL as a non-superadmin → admin endpoint returns 403 → UI renders `"You are not a superadmin"` message (404-style page), banner not visible. Don't fall back to the team-scoped endpoint silently.
4. **Edit buttons hidden:** in superadmin drill-down view, no `truth_level` dropdown is editable and no Delete/Restore buttons appear.
5. **Polling preserves admin endpoint:** after 30s, `pollForNewItems()` issues another call to `/v1/admin/brain/events?team_slug=other-team&since=...` (NOT the team-scoped endpoint).

**Commit message:** `feat(app-site): superadmin drill-down banner + admin endpoint substitution in brain.js`

## Section 4 — Risks + Mitigations

- **Risk: SVG sparkline lacks accessibility.** Mitigation: each `<svg>` has `role="img"` + `aria-label` summarizing the 30-day total and peak. Per-point `<title>` elements expose the date + count to screen readers via hover.
- **Risk: Page might be opened by a non-superadmin who already knows the URL.** Mitigation: The probe (`GET /v1/admin/brain/overview`) gates ALL data rendering. A 403 from the API immediately surfaces the fallback panel; no other fetches fire. No data leakage path exists in the client because the API is the gate, not the client.
- **Risk: Cross-plan tweak to 11-08's `brain.js` introduces a merge conflict if 11-08 changed structure.** Mitigation: 11-08 ships in wave 4 (before this wave-5 plan). Task 6 explicitly instructs the executor to read 11-08's files first and confirm the `init()`, `loadEvents()`, `pollForNewItems()` and write-call sites exist. The substitution wraps existing call sites with a helper (no shared line edits with 11-08's tasks).
- **Risk: Top-sources truncation hides edge-case sources.** Mitigation: top-5 is dynamic per the full dataset; "other" lumps the rest with the count. Operator can drill down on a team to see the full source set via the team-scoped brain monitor.
- **Risk: Probe-and-403 strategy makes 2 round trips in the probe-success path (probe = overview + render = re-fetch).** Mitigation: Task 1 caches the probe response (`state.overview = await resp.json()`) and `renderOverview()` reads from cache. Only 3 additional fetches (storage / activity / sources) happen in parallel after the probe succeeds.
- **Risk: `as_superadmin=1` URL hint suggests CSRF-like abuse — a malicious link could trick a superadmin into navigating with the banner up.** Mitigation: the banner is purely informational; it does NOT grant elevated permissions or change behavior. All actual elevation goes through the `assert_is_superadmin`-gated API. The query param has no security impact.
- **Risk: `humanBytes` rounding loses precision.** Mitigation: 1-decimal precision is standard for dashboard UX; operator can drill into PG or MinIO directly for exact byte counts. Document on the dashboard footer if needed.
- **Risk: Executor wires 11-11 before 11-10 ships, breaking drill-down.** Mitigation: `depends_on: ["11-10", "11-08"]` enforces wave ordering. The admin endpoint `/v1/admin/brain/events` from 11-10 MUST be live before Task 6's substitution will work. Smoke test in Task 7 hits the live endpoint via the deployed UI.
