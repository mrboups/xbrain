### Task 2 — Auth helper `assert_can_edit_brain_event` (REVISION 1 — fixes B-2 + M-4)

**File(s):** `apps/memory-api/app/deps.py`

**What:** Append the helper at the end of `deps.py`. The helper MUST handle every principal shape that `get_current_principal` can return today (after Phase 10's auth-merge is live). Confirmed from `apps/memory-api/app/deps.py` lines 46-213:

| # | `kind` | `principal['user']` shape | Notes |
|---|--------|---------------------------|-------|
| 1 | `'user'` | ORM `User` row (Google OIDC ID token) | `.id` is UUID |
| 2 | `'user'` | ORM `User` row (Google access token, Chrome extension) | `.id` is UUID |
| 3 | `'user'` | ORM `User` row (GitHub `gho_` token) | `.id` is UUID — same shape as Google after Phase 10 auth-merge |
| 4 | `'user_api_token'` | `types.SimpleNamespace` (`xbt_` token, line 150) | `.id` is UUID |
| 5 | `'user'` | ORM `User` row (bridge JWT acting-user / LibreChat onboarding, lines 174-205) | `.id` is UUID |
| 6 | `'bridge'` | absent (`principal.get('user')` is None, line 206-211) | service trust; treat as admin |

The helper does NOT branch on the auth source — it branches only on `kind`. Phase 10 unified Google and GitHub identities under `kind='user'` with the same `principal['user']` shape, so a single code path covers both.

> **REVISION 1 (B-2):** The previous draft used `principal.get("user", {}).get("id")` which silently returned `None` for `kind='bridge'` (no user key) and caused every PATCH/DELETE/restore to 403 in that case. The new body branches explicitly on `kind`, with `bridge` short-circuiting to allow.

```python
async def assert_can_edit_brain_event(
    principal: dict[str, Any],
    *,
    created_by: UUID | None,
    team_slug: str,
    session: AsyncSession,
) -> None:
    """Raise 403 if principal is neither the author nor a team admin.

    Rules:
    - kind='bridge' → always allowed (service trust, matches the _is_admin pattern).
    - kind='user' or 'user_api_token' → must be a team admin OR (created_by is set AND
      matches principal.user.id).
    - created_by IS NULL (memory_items, contacts, messages, agent team_messages have no
      author column) → admin-only.

    After Phase 10 auth-merge, Google and GitHub identities both surface as kind='user'
    with the same principal['user'] ORM shape, so this helper does NOT branch on the
    auth source.
    """
    if principal["kind"] == "bridge":
        return

    user = principal.get("user")
    if user is None:
        raise HTTPException(403, "No user identity on principal")

    # Per-team admin check. NOTE: this is the per-team membership.role, NOT the
    # env-level admin sub list checked by _is_admin (which gates /v1/admin/*).
    from app.repos.teams import get_membership   # local import — avoid circular
    membership = await get_membership(session, user_id=user.id, team_slug=team_slug)
    if membership is not None and membership.role == "admin":
        return

    if created_by is not None and created_by == user.id:
        return

    raise HTTPException(
        403,
        "You can only edit items you created. Contact a team admin to modify items "
        "created by others.",
    )
```

**`get_team_scope` contract (REVISION 1 — fixes M-4):**

This helper relies on the upstream `get_team_scope` dependency, which is already defined at `apps/memory-api/app/deps.py:216-242` and is reused unchanged. For executor convenience the contract is documented here — no new code is needed:

- **Signature:** `async def get_team_scope(principal=Depends(get_current_principal), x_team_scope: str = Header(..., alias="X-Team-Scope"), session=Depends(get_session)) -> str`
- **What it does:** Validates that the requested `X-Team-Scope` slug matches a row in `team_members` for the principal's `user.id`. For `kind='bridge'`, validates the `team_scope` claim on the JWT matches the header. For `kind='user_api_token'`, validates the `api_token_team_scope` matches.
- **Tables queried:** `team_members` (via `repos.teams.get_membership`), `teams` (via the join in `get_membership`).
- **Returns:** the validated team slug (string), passed forward to the route handler.
- **Errors:** raises `HTTPException(403)` with descriptive detail for each mismatch case (bridge JWT scope mismatch, API-token scope mismatch, GitHub non-org-member, or no membership row).
- **Status:** existing — no new function to write; brain endpoints just `Depends(get_team_scope)`.

**Why:** Single source of truth for brain-event authorization. PATCH (BMO-04), DELETE (BMO-05), restore (BMO-06) all share the same rule set; duplicating this logic across three endpoints invites drift. The principal-shape audit above makes the previously-implicit "what does deps.py return" contract explicit so the executor doesn't have to re-derive it.

**Acceptance:** pytest in Task 4 covers a 5-principal-kinds × 6-scenario matrix — at least 12 test cases:

### Task 3 — `GET /v1/brain/events` router

**File(s):** `apps/memory-api/app/routes/brain.py` (CREATE), `apps/memory-api/app/main.py` (MODIFY)

**What:** New router (`router = APIRouter(prefix="/v1/brain", tags=["brain"])`) with a single endpoint for this plan:

```python
@router.get("/events", response_model=BrainEventListOut)
async def list_brain_events(
    session: AsyncSession = Depends(get_session),
    team_scope: str = Depends(get_team_scope),
    entity_type: list[str] | None = Query(None),
    truth_level: list[str] | None = Query(None),
    source: list[str] | None = Query(None),
    created_by: UUID | None = Query(None),
    q: str | None = Query(None, min_length=1, max_length=200),
    include_deleted: bool = Query(False),
    since: datetime | None = Query(None),
    cursor: str | None = Query(None),
    limit: int = Query(50, ge=1, le=200),
):
    ...
```

Inside:
1. Decode `cursor` (base64 JSON `{"ts": ISO, "et": str, "id": UUID-str}`) if present.
2. Build SQL against `v_brain_events`:
   ```sql
   SELECT * FROM v_brain_events
   WHERE team_scope = :ts
     [AND deleted_at IS NULL]   -- if NOT include_deleted
     [AND entity_type = ANY(:et_arr)]
     [AND truth_level = ANY(:tl_arr)]
     [AND source = ANY(:src_arr)]
     [AND created_by = :cb]
     [AND preview ILIKE :q_pattern]
     [AND created_at >= :since]
     [AND (created_at, entity_type, entity_id) < (:c_ts, :c_et, :c_id)]   -- tuple cursor tie-break
   ORDER BY created_at DESC, entity_type ASC, entity_id ASC
   LIMIT :limit_plus_one
   ```
3. Fetch `limit + 1` rows; if `limit+1` returned, build `next_cursor` from the `limit`-th row's `(created_at, entity_type, entity_id)`, base64-encoded JSON; trim to `limit`.
4. Return `BrainEventListOut(items=[BrainEventOut(**dict(r)) for r in rows], next_cursor=next_cursor)`.

Wire in `main.py`: add `from app.routes import brain` and `app.include_router(brain.router)` next to existing routers.

**Why:** BMO-02 (single read surface) + BMO-03 (cursor-paginated + filterable).

**Acceptance:** From the running memory-api:
```bash
curl -s -H "Authorization: Bearer $TEST_XBT" -H "X-Team-Scope: default" "$MEMAPI_HOST/v1/brain/events?limit=5" | jq '.items | length'
```
returns ≤ 5. With filter: `...?entity_type=task&truth_level=WORKING` returns only tasks. Pagination: capture `next_cursor` from response 1, pass as `?cursor=<value>` in response 2, assert no overlap. `?include_deleted=true` returns soft-deleted rows; default does not.

**Commit message:** `feat(memory-api): GET /v1/brain/events paginated list + filters`

**REVISION 1 — cursor tie-break test (M-3):**

7. **Identical-timestamp pagination.** Seed 3 rows in the SAME team with `created_at = '2026-05-14T12:00:00Z'` (exact same timestamp), each with a different `entity_type` (or different `entity_id` if same type). Page with `limit=2`. Page 1 returns rows 1+2 (ordered by `(entity_type ASC, entity_id ASC)` as secondary keys), captures `next_cursor`. Page 2 (with `cursor=<v>&limit=2`) returns row 3 ONLY — no duplicates, no skips. The union of page 1 + page 2 equals the 3 seeded rows.

## Section 4 — Risks + Mitigations

- **Risk: cursor decoding mismatched types.** Mitigation: define a tiny helper `_decode_cursor(s: str) -> tuple[datetime, str, UUID]` that base64-decodes + json.loads + casts each field. On decode failure return 400, not 500. Unit-test it.
- **Risk: ILIKE pattern injection via `q` parameter.** Mitigation: parameterize as `:q_pattern` with `f"%{q}%"` Python-side (so the SQL is `preview ILIKE :q_pattern`), never string-concat. The query already uses sa.text bind params.
- **Risk: large UNION ALL plan with no filters dominates query time.** Mitigation: default `limit=50` caps result rows. The composite indexes from 11-02 + DESC ordering ensure each arm reads only a small `created_at` prefix. EXPLAIN ANALYZE acceptance check in 11-02 confirms.
- **Risk: `since` filter performance.** Mitigation: the `(team_scope, created_at DESC)` index supports `WHERE team_scope = X AND created_at >= Y` efficiently.
- **Risk: `assert_can_edit_brain_event` adds a query per row.** Mitigation: this helper is NOT called in the list endpoint — only in PATCH/DELETE/restore (one call per request, not per row). The list endpoint is read-only.
- **Risk: future auth path adds a new `kind` value not handled by the helper.** Mitigation: the helper raises `HTTPException(403, "No user identity on principal")` if `principal.get("user")` returns None for a non-bridge kind. This is the safe default — a new auth source must be explicitly added with a test before production sees 200s.
