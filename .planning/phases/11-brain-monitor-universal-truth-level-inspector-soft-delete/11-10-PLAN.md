# Plan 11-10 — Superadmin endpoints: `/v1/admin/brain/*`

## Section 1 — Goal

Ship the cross-team superadmin read surface for the Brain Monitor. A principal whose `sub` is listed in `ADMIN_USER_SUBS` (or a bridge JWT) can hit five new endpoints under `/v1/admin/brain/*` to read counts × truth_level × entity_type matrix per team, storage size per team (Postgres rows + Qdrant points + MinIO bytes), 30-day activity series per team, top-sources breakdown per team, and a drill-down `events` endpoint that bypasses `X-Team-Scope` and writes one `audit_log` row per call. Delivers BMO-10 + BMO-11.

After this plan: `curl -H 'Authorization: Bearer <superadmin_xbt>' https://api.example.com/v1/admin/brain/overview` returns a JSON array of `{team_slug, team_id, counts: {entity_type: {truth_level: int}}}` covering ALL teams. The same call with a non-superadmin token returns 403. Drill-down `/v1/admin/brain/events?team_slug=your-github-org` writes one `audit_log` row with `action='superadmin_brain_access'` before returning the data.

### Task 1 — `assert_is_superadmin` dependency

**File(s):** `apps/memory-api/app/deps.py` (APPEND only — do not edit lines 1-285)

**What:** Append at the end of deps.py:

```python
async def assert_is_superadmin(
    principal: dict[str, Any] = Depends(get_current_principal),
) -> None:
    """FastAPI dependency that raises 403 if principal is not a superadmin.

    Wraps the existing _is_admin() predicate at deps.py:266-277. Reuses ADMIN_USER_SUBS
    env var as the authoritative list of superadmin subs. Bridge JWTs (kind='bridge' /
    kind='service') are also treated as superadmin — matches existing _is_admin pattern.

    Returns None on success (FastAPI dependency contract); raises HTTPException(403)
    with a non-leaky detail message on failure.

    Lockdown behavior: if ADMIN_USER_SUBS is empty (env unset or set to ''), no real-user
    principal can be a superadmin — _is_admin() returns False for kind='user' /
    kind='user_api_token' principals. Bridge JWTs still pass (service trust). Test in
    Task 6 covers this case.

    Bridge JWTs (kind='bridge') still pass — they inherit the trust model
    from _is_admin(). When a bridge JWT calls a superadmin endpoint, the
    audit_log entry has actor_user_id=None and the bridge service identity
    is captured in audit_log.payload.actor_sub (the JWT 'sub' claim).

    SECURITY NOTE: bridge JWTs accessing cross-team brain data is supported
    but the design intent is that bridges are emitted by internal trusted
    services (granola-sync, agent-runtime, librechat-bridge). If a bridge
    secret is compromised, an attacker could read cross-team brain content.
    Mitigation: rotate BRIDGE_SHARED_SECRET periodically and review
    audit_log entries where actor_user_id IS NULL.
    """
    if not _is_admin(principal):
        raise HTTPException(
            status_code=403,
            detail="superadmin access required",
        )
```

**Why:** Single FastAPI dependency that gates the new admin router cleanly. Keep `_is_admin()` as cheap bool predicate (existing — still used by `routes/admin_*` endpoints in Phases 5/8); the new helper raises so routes can declare it via `Depends(...)`. Reuse existing identity logic — no new env var, no new identity primitive (per CONTEXT.md "no new identity primitive needed").

**Acceptance:**
- `python -c "from app.deps import assert_is_superadmin; print(assert_is_superadmin)"` resolves.
- Pytest in Task 6 covers the 4-case matrix: superadmin sub → pass; non-admin user → 403; bridge JWT → pass; `ADMIN_USER_SUBS=""` lockdown → 403 even for a previously-admin user-sub.

### Task 2 — `repos/brain_metrics.py` aggregation queries

**File(s):** `apps/memory-api/app/repos/brain_metrics.py` (CREATE)

**What:** Four async functions, each issues a single SQL query (storage also issues a Qdrant + MinIO call per team).

**`get_overview_per_team(session: AsyncSession) -> list[dict]`**

Returns `[{team_slug, team_id, counts: {entity_type: {truth_level: int}}}, ...]`. Single SQL query against `v_brain_events` (created in 11-02):

```sql
SELECT
  v.team_scope                AS team_slug,
  v.team_id                   AS team_id,
  v.entity_type               AS entity_type,
  v.truth_level               AS truth_level,
  COUNT(*)                    AS cnt
FROM v_brain_events v
WHERE v.deleted_at IS NULL
GROUP BY v.team_scope, v.team_id, v.entity_type, v.truth_level
ORDER BY v.team_scope, v.entity_type, v.truth_level
```

Python-side: walk the flat result set and pivot into the nested `{team_slug, team_id, counts: {entity_type: {truth_level: int}}}` shape. Use a `defaultdict(lambda: defaultdict(dict))` keyed by team_slug → entity_type → truth_level. Convert to plain dicts before return so Pydantic serializes cleanly.

**`get_storage_per_team(session: AsyncSession, qdrant_client, minio_client) -> list[dict]`**

Returns `[{team_slug, team_id, pg_rows: {table: int}, qdrant_points: int | None, minio_bytes: int | None}, ...]`.

1. Discover team list via `SELECT id, slug FROM teams ORDER BY slug`. Iterate over teams.
2. Per team, for each of the 6 brain-target tables (`memory_items`, `conversations`, `messages`, `team_messages`, `tasks`, `contacts`), run a single SQL UNION ALL query that returns one row per table:
   ```sql
   SELECT 'memory_items' AS table_name, COUNT(*) AS cnt FROM memory_items WHERE team_scope = :slug AND deleted_at IS NULL
   UNION ALL SELECT 'conversations', COUNT(*) FROM conversations WHERE team_scope = :slug AND deleted_at IS NULL
   UNION ALL SELECT 'messages', COUNT(*) FROM messages WHERE team_scope = :slug AND deleted_at IS NULL
   UNION ALL SELECT 'team_messages', COUNT(*) FROM team_messages WHERE team_id = :team_id AND deleted_at IS NULL
   UNION ALL SELECT 'tasks', COUNT(*) FROM tasks WHERE team_scope = :slug AND deleted_at IS NULL
   UNION ALL SELECT 'contacts', COUNT(*) FROM contacts WHERE team_scope = :slug AND deleted_at IS NULL
   ```
   (`team_messages` uses `team_id` UUID, not slug — per Q1 of 11-RESEARCH. The PG queries also pre-filter soft-deleted to match what 11-06's regression filter exposes to other routes.)

3. Qdrant per team:
   ```python
   try:
       from qdrant_client.http.models import Filter, FieldCondition, MatchValue, Range
       qresp = qdrant_client.count(
           collection_name=settings.QDRANT_COLLECTION or "memory_items",
           count_filter=Filter(
               must=[FieldCondition(key="team_scope", match=MatchValue(value=team_slug))],
               must_not=[FieldCondition(key="deleted_at_ts", range=Range(gt=0.0))],  # exclude soft-deleted, payload from 11-03
           ),
           exact=False,  # approximate count is fine for a dashboard; avoids full scan
       )
       qdrant_points = qresp.count
   except Exception as exc:
       logger.warning("qdrant_count_failed", team=team_slug, error=str(exc))
       qdrant_points = None
   ```
   Fail-soft on Qdrant errors → return `None` for that team; do NOT propagate (the dashboard must still render the PG counts).

4. MinIO per team:
   ```python
   if minio_client is None:
       minio_bytes = None
   else:
       try:
           total = 0
           paginator = minio_client.get_paginator("list_objects_v2")
           for page in paginator.paginate(Bucket=settings.MINIO_BUCKET, Prefix=f"team/{team_slug}/"):
               for obj in page.get("Contents", []) or []:
                   total += int(obj["Size"])
           minio_bytes = total
       except Exception as exc:
           logger.warning("minio_size_failed", team=team_slug, error=str(exc))
           minio_bytes = None
   ```
   `minio_client` is `None` when settings are unset (fail-soft from `app/db/minio.py`) — the UI displays "N/A" for that column.

5. Assemble per-team dict with PG row dict + qdrant_points + minio_bytes.

**`get_activity_per_team(session: AsyncSession, days: int = 30) -> list[dict]`**

Returns `[{team_slug, team_id, daily: [{date: 'YYYY-MM-DD', events: int}, ...]}, ...]`. Each `daily` is exactly `days` entries (zero-fill missing).

```sql
SELECT
  v.team_scope               AS team_slug,
  v.team_id                  AS team_id,
  date_trunc('day', v.created_at AT TIME ZONE 'UTC')::date AS day,
  COUNT(*)                   AS events
FROM v_brain_events v
WHERE v.created_at >= now() - (:days || ' days')::interval
  AND v.deleted_at IS NULL
GROUP BY v.team_scope, v.team_id, day
ORDER BY v.team_scope, day
```

Python-side: for each team, build a `dict[date, int]` from rows then iterate a 30-day window from `now() - days` to `now()` (UTC), inserting `0` for missing days. The response `daily` is always exactly `days` entries in chronological order. This zero-fill is critical for the sparkline component in 11-11.

Document the response invariant in the function docstring: "`daily` is always exactly `days` entries, oldest first, with missing days zero-filled."

**`get_sources_per_team(session: AsyncSession, days: int = 30) -> list[dict]`**

Returns `[{team_slug, team_id, sources: {source_label: count, ...}}, ...]`.

```sql
SELECT
  v.team_scope               AS team_slug,
  v.team_id                  AS team_id,
  COALESCE(v.source, '(none)') AS source,
  COUNT(*)                   AS events
FROM v_brain_events v
WHERE v.created_at >= now() - (:days || ' days')::interval
  AND v.deleted_at IS NULL
GROUP BY v.team_scope, v.team_id, source
ORDER BY v.team_scope, events DESC
```

Python-side: pivot into `{team_slug, team_id, sources: dict}` per team. Don't truncate — return ALL sources (10 expected: librechat / openwebui / granola / agent / api / chrome-extension / drive-sync / etc.). The UI in 11-11 can choose to display top-N.

**Why:** All queries are read-only, run against the existing `v_brain_events` view (11-02) so the same definitions used by `/v1/brain/events` are reused. Single source of truth for aggregation logic; the route handlers (Task 3) are thin wrappers. Storage is the only function that has non-PG side-effects (Qdrant + MinIO) — both fail-soft.

**Acceptance:**
- `python -c "from app.repos.brain_metrics import get_overview_per_team, get_storage_per_team, get_activity_per_team, get_sources_per_team; print('ok')"` resolves.
- Smoke: `get_overview_per_team(session)` against a DB with ≥2 teams returns ≥2 entries; structure validates against `TeamOverviewOut`.
- Activity zero-fill verified by Task 6 test (synthesize a 30-day window, assert 30 entries returned even when most days have 0 events).

```python
"""MinIO/S3 client init — fail-soft if MinIO credentials not configured."""
from __future__ import annotations
from functools import lru_cache
import logging

from app.config import settings

logger = logging.getLogger(__name__)


@lru_cache(maxsize=1)
def get_minio_client():
    """Return an S3-compatible boto3 client or None if MinIO is not configured.

    Returns None when MINIO_URL or credentials are empty. Callers MUST handle the
    None case (fail-soft pattern: storage queries return minio_bytes=None for the UI
    to display 'N/A').
    """
    if not settings.MINIO_URL or not settings.MINIO_ACCESS_KEY or not settings.MINIO_SECRET_KEY:
        logger.info("minio_client_disabled: MINIO_URL or credentials empty")
        return None
    try:
        import boto3
        from botocore.config import Config as BotoConfig
        return boto3.client(
            "s3",
            endpoint_url=settings.MINIO_URL,
            aws_access_key_id=settings.MINIO_ACCESS_KEY,
            aws_secret_access_key=settings.MINIO_SECRET_KEY,
            config=BotoConfig(signature_version="s3v4"),
        )
    except Exception as exc:
        logger.warning("minio_client_init_failed", error=str(exc))
        return None
```

**Why:** Storage endpoint needs MinIO bytes. xbrain's MinIO is already deployed (Phase 3.5) — boto3 is in the SDK layer per CLAUDE.md. Lazy-init via `lru_cache` keeps memory-api startup fast and avoids a hard dependency when MinIO is not yet wired. The fail-soft contract is explicit: `None` → UI shows "N/A".

**Acceptance:**
- With empty env vars: `from app.db.minio import get_minio_client; print(get_minio_client())` → `None`.
- With dev env vars (`MINIO_URL=http://minio:9000`, `MINIO_ACCESS_KEY=...`, `MINIO_SECRET_KEY=...`): returns a usable boto3 client. `client.list_buckets()` succeeds against the dev MinIO.

```python
from uuid import UUID
from fastapi import APIRouter, Depends, HTTPException, Query, Request
from sqlalchemy.ext.asyncio import AsyncSession

from app.audit import write_audit
from app.db.minio import get_minio_client
from app.db.session import get_session
from app.deps import assert_is_superadmin, get_current_principal, _user_id_from_principal
from app.memory import get_qdrant_client   # existing helper used by 11-03 / native_provider
from app.repos.brain_metrics import (

@router.get("/events", response_model=BrainEventListOut)
async def events_drilldown(
    request: Request,
    team_slug: str = Query(..., min_length=1, max_length=64),   # REQUIRED — no default; 422 if absent
    # All the same filters as GET /v1/brain/events. Mirror the signature from 11-04
    # routes/brain.py:list_brain_events — entity_type[], truth_level[], source[], created_by,
    # q, include_deleted, since, cursor, limit. (Copy them verbatim here OR factor 11-04's
    # endpoint into a private helper `_query_brain_events(session, team_scope, **filters)` and
    # call it from both routes. Decide based on whichever is mergeable cleanly with the file
    # 11-04 already ships — coordinate via the executor reading routes/brain.py first.)
    session: AsyncSession = Depends(get_session),
    principal: dict[str, Any] = Depends(get_current_principal),
    _: None = Depends(assert_is_superadmin),
    entity_type: list[str] | None = Query(None),
    truth_level: list[str] | None = Query(None),
    source: list[str] | None = Query(None),
    created_by: UUID | None = Query(None),
    q: str | None = Query(None, min_length=1, max_length=200),
    include_deleted: bool = Query(False),
    since: str | None = Query(None),
    cursor: str | None = Query(None),
    limit: int = Query(50, ge=1, le=200),
):
    """Drill-down into any team's brain events. Bypasses X-Team-Scope guard.

    SYNCHRONOUS audit write BEFORE any data read:
    - audit_log row written + session.flush() called.
    - If the audit write or flush fails, raise 500 and DO NOT serve the data.

    This guarantees no superadmin content access is served without an audit trail.
    """
    # 1) Synchronous audit write FIRST — guarantees no read without an audit row.
    actor_user_id = _user_id_from_principal(principal)
    try:
        await write_audit(
            session,
            actor_user_id=actor_user_id,
            team_scope=team_slug,     # team_scope on audit_log = the TARGET team, not the actor's
            action="superadmin_brain_access",
            target_id=None,

                "actor_sub": principal.get("sub"),       # capture bridge service identity OR user sub (MAJOR-1 fix)
                "endpoint": "/v1/admin/brain/events",
                "query_params": dict(request.query_params),
                "target_team_slug": team_slug,
                "actor_kind": principal.get("kind"),
            },
        )
        await session.flush()   # surface DB errors NOW — before data read
    except Exception as exc:
        # Do not leak data without an audit row.
        await session.rollback()
        raise HTTPException(
            status_code=500,
            detail="audit log write failed; access denied",
        ) from exc

    # 2) Reuse 11-04's query path with team_slug as the effective team_scope.
    # The same _build_list_query helper that GET /v1/brain/events uses — passing team_slug

        session,
        team_scope=team_slug,
        entity_type=entity_type,
        truth_level=truth_level,
        source=source,
        created_by=created_by,
        q=q,
        include_deleted=include_deleted,
        since=since,
        cursor=cursor,
        limit=limit,
    )

    # 3) Commit audit row + return data.
    await session.commit()
    return BrainEventListOut(
        items=[BrainEventOut(**dict(r)) for r in items],
        next_cursor=next_cursor,
    )
```

**Drill-down audit semantics — non-negotiable invariants:**
1. `team_slug` is REQUIRED — FastAPI's `Query(..., min_length=1)` returns 422 if absent. Phase 11 verify assertion 14 confirms.
2. The audit row is written BEFORE the data query. `session.flush()` is awaited to surface DB errors immediately.
3. If audit write fails, the route raises 500 and rolls back; NO data is served.
4. The audit `payload` JSONB MUST capture `actor_sub` (from `principal.get("sub")`) — this is the bridge service identity when `kind='bridge'`, or the user OIDC sub when `kind='user'`. Without `actor_sub`, bridge JWT access is unauditable (since `actor_user_id` is NULL for bridges). Phase 11 verify assertion 15 confirms `payload->>'actor_sub'` is non-NULL.
5. Only the per-call `/v1/admin/brain/events` endpoint writes audit. Aggregate endpoints (`overview`, `storage`, `activity`, `sources`) do NOT write audit per call — they return cross-team aggregates that have no per-team content payload. (Decision documented; revisit in Phase 12 if aggregate access proves sensitive.)

**Why:** BMO-10 + BMO-11. The endpoints are thin wrappers over the repo functions (overview/storage/activity/sources) plus a synchronous-audit-then-reuse-existing-query pattern for events. Reusing 11-04's `_build_list_query` ensures filter semantics stay identical between team-scoped and superadmin reads — no copy-paste drift.

**Acceptance:**
- `curl -H 'Authorization: Bearer $SUPERADMIN_XBT' $MEMAPI_HOST/v1/admin/brain/overview | jq 'length'` ≥ 2 when DB has ≥2 teams.
- `curl -H 'Authorization: Bearer $NONADMIN_XBT' $MEMAPI_HOST/v1/admin/brain/overview -o /dev/null -w '%{http_code}'` returns `403`.
- `curl -H 'Authorization: Bearer $SUPERADMIN_XBT' $MEMAPI_HOST/v1/admin/brain/storage | jq '.[0] | keys'` includes `pg_rows`, `qdrant_points`, `minio_bytes`.

- `curl -X GET ... /v1/admin/brain/events` without `team_slug` query param returns 422.
- `curl ... /v1/admin/brain/events?team_slug=your-github-org` returns 200 + writes 1 row to `audit_log` where `action='superadmin_brain_access'` and `team_scope='your-github-org'`. ## Section 4 — Risks + Mitigations

- **Risk: MinIO unavailable in dev/test env.** Mitigation: `get_minio_client()` returns `None` on empty config or boto3 init failure. Storage endpoint surfaces `minio_bytes: None`; UI in 11-11 renders "N/A". Pytest case 3 covers this path.
- **Risk: Activity query with 30 days × 10 teams × full table scan is slow.** Mitigation: The 11-02 migration adds composite indices `(team_scope, created_at DESC)` per source table. The `WHERE created_at >= now() - interval` + `GROUP BY team_scope, day` query hits the index for each UNION arm. If `EXPLAIN ANALYZE` on the dev VM shows >500ms at production size, add a partial index `(team_scope, created_at DESC) WHERE deleted_at IS NULL` per table — call out as a Phase 12 task, not Phase 11.
- **Risk: Superadmin endpoints accidentally exposed if `ADMIN_USER_SUBS` misconfigured.** Mitigation: `_is_admin()` returns False when the env var is empty (lockdown default). Pytest case 10 enforces this. Operator runbook (in 11-09 docs) explicitly warns: "Onboarding a new superadmin requires explicit `ADMIN_USER_SUBS` edit + memory-api restart."
- **Risk: Drill-down audit_log write fails silently → privacy violation.** Mitigation: Task 4 writes audit synchronously BEFORE the data query, awaits `session.flush()`, and raises 500 on failure (no rollback-leak). Pytest case 8 enforces this. The audit row + the data fetch share one transaction; rollback on audit failure means data is also rolled back even if it had been queried.
- **Risk: Bridge JWT cross-team access is unauditable when actor_user_id is NULL.** Mitigation: `payload->>'actor_sub'` captures the bridge service identity (`granola-sync`, `agent-runtime`, `librechat-bridge`, etc.). Operator review query: `SELECT created_at, team_scope, payload->>'actor_sub' FROM audit_log WHERE action='superadmin_brain_access' AND actor_user_id IS NULL`. If a bridge secret is compromised, rotate `BRIDGE_SHARED_SECRET` and audit the actor_sub column to identify suspicious patterns. Pytest case 9 enforces the invariant.
- **Risk: MinIO client init pulls boto3 → memory-api startup time / image size increase.** Mitigation: `get_minio_client()` is lru_cached on first call (lazy). boto3 is small (~10 MB) and already in the `xbrain_memory` package dependencies per CLAUDE.md (used for asset storage). Confirm `boto3` is already in `apps/memory-api/pyproject.toml` before this plan ships; if not, add it.
- **Risk: `_build_list_query` not factored out of 11-04's routes/brain.py.** Mitigation: 11-04 (wave 3b) ships before this plan (wave 4). Executor of 11-10 reads `routes/brain.py` first and either (a) imports an existing helper if 11-04 already factored it, or (b) extracts the query-build block into a module-private function `_build_list_query` and updates the existing `list_brain_events` endpoint to call it. Either way, both endpoints share one implementation. Code review will reject duplicated query logic.
