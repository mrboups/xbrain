```js
/**
 * Connect to Centrifugo. THE URL IS NEVER A CONSTANT (D-27-03): the server owns it
 * and hands it back on POST /v1/me/centrifugo-token as `ws_url`, alongside the
 * signed client token. A hardcoded URL here would silently pin every surface to
 * one deployment; this module contains no scheme literal at all, and its test
 * asserts that.
 *
 * @param {{Centrifuge: Function, api: {centrifugoToken: () => Promise<{token,ws_url}>},
 *          getUserSub: () => string|null,
 *          onTeamPublication: (data:any) => void,
 *          onUserPublication: (data:any) => void,
 *          onPresenceChange?: () => void,
 *          onConnected?: () => void, onError?: (e:any) => void}} opts
 */
export async function connectRealtime(opts) {
  // 1. tokenInfo = await opts.api.centrifugoToken()
  // 2. new opts.Centrifuge(tokenInfo.ws_url, { token: tokenInfo.token })
  // 3. wire "connected" / "error"
  // 4. subscribe user:<getUserSub()> ONCE per connection (idempotent, survives team switches)
  // 5. connect()
  return {
    centrifuge,
    subscribeTeam(teamId),    // tears down any prior team sub, creates team:<id>,
                              // wires publication + (optional) join/leave/subscribed callbacks
    unsubscribeTeam(),
    disconnect(),
  };
}
```

    dropped so it is rebuilt on the fresh instance.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server message payload -> DOM | `content`, `agent_name`, `metadata.sources[].text` are attacker-influencable strings that reach the document |
| server token response -> websocket connect | `ws_url` decides which host the client opens a credentialed socket to |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-02-01 | Tampering | render.js message body | mitigate | Every message field is written with `textContent` / `createElement`; `innerHTML` is grep-asserted absent from render.js, and a dedicated XSS test asserts `<img onerror>` renders as text |
| T-27-02-02 | Spoofing | render.js sources disclosure | mitigate | Source rows render ONLY from `metadata.sources` the server actually sent; the truth-level chip is selected by `data-level` from the payload and never fabricated (behaviour carried over verbatim) |
| T-27-02-03 | Information Disclosure | realtime.js connection target | mitigate | The socket URL comes solely from the authenticated `POST /v1/me/centrifugo-token` response; no scheme literal may exist in the module (grep-asserted), so a compromised static file cannot silently redirect the socket |
| T-27-02-04 | Elevation of Privilege | realtime.js channel subscription | accept | Channel names are built client-side (`team:<id>`, `user:<sub>`) but Centrifugo enforces the `channels` claim in the server-signed token, so subscribing to a foreign channel is rejected server-side (team_chat.py:136-141) |
| T-27-02-05 | Denial of Service | render.js syncDaySeparators | accept | O(n) over rendered rows on every insert, unchanged from today's behaviour; history is capped at 50 rows per page |
</threat_model>
