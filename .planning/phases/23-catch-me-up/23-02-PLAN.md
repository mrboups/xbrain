<objective>
Wire the three team-chat endpoints and the ephemeral summarizer:
`POST /v1/teams/{id}/mark-read` (caller sets their OWN cursor), `GET
/v1/teams/{id}/unread-summary` (`{count, since, threshold}`), and `POST
/v1/teams/{id}/catch-me-up` (opt-in, rate-limited, capped). Catch-me-up reuses
the EXISTING `@agent` streaming path (brain bundle + `_stream_via_promax` /
`_stream_via_anthropic_api`) but streams to the caller's private `user:<sub>`
channel and NEVER inserts a `team_messages` row — the summary is ephemeral.

Purpose: SC#1 (mark-read sets the cursor; unread count excludes the caller's own)
and SC#3 (summary via the existing streaming path, brain-grounded, ephemeral,
never auto-run, rate-limited). All three endpoints are caller-membership-gated;
a non-member gets 403.

Output: 3 endpoints in team_chat.py, a `catch_me_up()` service function in
team_chat_agent.py, and 3 CATCHUP_* settings in config.py.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension client → memory-api | Untrusted caller crosses here; all three endpoints must independently prove team membership. |
| caller ↔ other members' data | A member may only touch THEIR OWN cursor and receive THEIR OWN summary — never another member's cursor, never another team's messages. |
| memory-api → LLM (Anthropic / bridge) | Every catch-me-up spend must be opt-in, rate-limited, and bounded by a capped window. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Elevation of privilege | all 3 endpoints | mitigate | `_resolve_team_and_check_membership` runs first in every handler → non-member 403 before any read/write/spend. |
| T-23-02 | Information disclosure | catch_me_up gather + brain bundle | mitigate | since-window query is bound to the resolved `team.id`; brain bundle is fetched with the resolved `team.slug` team_scope — a different team's messages/facts are structurally unreachable. Asserted by the isolation case in 23-03. |
| T-23-03 | Denial of service / LLM-cost abuse | POST /catch-me-up | mitigate | Per-caller `rate_limit.check_rate(CATCHUP_RATE_LIMIT, "catchup", sub)` → 429; window capped at CATCHUP_MAX_MESSAGES; never auto-run (opt-in POST only); 0-unread short-circuit skips the LLM entirely. |
| T-23-04 | Tampering / cursor spoof | POST /mark-read | mitigate | Cursor user_id is the authenticated `user.id`; there is no body and no target-user field — a caller cannot move another member's cursor. |
| T-23-05 | Information disclosure / new privacy surface | GET /unread-summary | mitigate | Returns only the caller's own {count, since}; no endpoint returns any other member's cursor → no "seen by" / read-receipt surface (D-23-05). |
| T-23-06 | Repudiation / unwanted persistence | catch_me_up | mitigate | Summary streams to `user:<caller_sub>` only and calls NO `insert_agent_message` → it is never a `team_messages` row everyone sees (ephemeral). grep gate + 23-03 assert no row is written. |
</threat_model>
