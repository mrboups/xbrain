**What is agent-runtime?**
"agent-runtime is a LangGraph-powered agent host running as a Docker container on port 9100. It provides stateful, interruptible agent graphs with persistent checkpoints, HITL approval workflows, and native MCP tool integration."

Table :
| Property | Value |
|----------|-------|
| Framework | LangGraph 1.1.0 (MIT) |
| Port | 9100 |
| Checkpointing | PostgresSaver (same PostgreSQL as xbrain) |
| Observability | Langfuse 3.x via CallbackHandler |
| MCP integration | mcp_gateway_client.py (Phase 4) |

**LangGraph Architecture**
"LangGraph builds agent workflows as directed graphs where each node is a function and edges define the flow. xbrain uses it for:"
- Document ingestion agents (PDF → structured facts)
- Truth-level promotion workflows (proposal → approval)
- RAG-enriched conversation agents (search → enrich → respond)
- Multi-step task agents with HITL checkpoints

Diagram ASCII :
```python
# Example: document ingestion agent graph
workflow = StateGraph(AgentState)

workflow.add_node("extract_text", extract_text_node)
workflow.add_node("identify_facts", identify_facts_node)
workflow.add_node("human_review", human_review_node)  # HITL interrupt
workflow.add_node("upsert_to_memory", upsert_node)

workflow.add_edge(START, "extract_text")
workflow.add_edge("extract_text", "identify_facts")
workflow.add_conditional_edges("identify_facts", check_confidence,
    {"high": "upsert_to_memory", "low": "human_review"})
workflow.add_edge("human_review", "upsert_to_memory")
workflow.add_edge("upsert_to_memory", END)
```

**Human-In-The-Loop (HITL)**
"When an agent reaches a low-confidence decision point, it pauses and waits for human approval:"

Code example :
```python
# Agent pauses here — state saved to PostgreSQL
await interrupt({
    "question": "Confidence is 0.4 — should I save this as WORKING or discard?",
    "extracted_fact": "Alice leads the fundraising team",
    "source": "doc/fundraising-brief.pdf"
})

# Admin approves in Open WebUI → agent resumes from checkpoint
# LangGraph resumes from exactly this point with admin's decision
```

"The checkpoint is stored in PostgreSQL via PostgresSaver. The agent can resume days later — the state is fully preserved."

**Resuming an Agent**
```python
# Resume with admin's decision
result = await graph.ainvoke(
    {"decision": "approved", "target_level": "WORKING"},
    config={"configurable": {"thread_id": "agent_thread_abc123"}}
)
```

Contenu (sections h2) :

**What is Graphiti?**
"graphiti-service is a FastAPI wrapper around graphiti-core that runs as a Docker container on port 8300. It extracts temporal facts from conversation content and stores them in the Neo4j temporal knowledge graph."

"Every memory upsert to memory-api triggers an async call to graphiti-service (fail-soft — if graphiti is down, the memory write still succeeds)."

**Why Temporal Facts?**
"Standard graph databases store 'Alice works at Acme'. Graphiti stores 'Alice joined Acme on 2024-01-15, became Tech Lead on 2025-06-01'. This temporal dimension lets you ask:'

- "Who was the tech lead in Q3 2025?"
- "What was our fundraising target before the pivot?"
- "Which decisions were made by Alice before she left?"

**Architecture**
Diagram :
```
memory-api upsert (POST /v1/memory/upsert)
       │
       │ asyncio.create_task (fail-soft)
       ▼
graphiti-service (port 8300)
  POST /v1/ingest
       │
       ▼
graphiti-core (Python library)
  - Extract entities + relationships
  - Detect temporal markers
  - Resolve contradictions
       │
       ▼
Neo4j (temporal graph)
  - Episode nodes (conversations)
  - Entity nodes (people, projects, concepts)
  - Temporal edges (WORKED_AT, MANAGED, DECIDED)
```

**Service API**

Health check :
```bash
curl http://graphiti-service:8300/v1/healthz
# {"status": "ok", "graphiti": true}
```

Ingest :
```bash
curl -X POST http://graphiti-service:8300/v1/ingest \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Alice confirmed the Q2 fundraising target is 2M€. Bob will lead the investor outreach.",
    "group_id": "acme",
    "source": "memory-api"
  }'
# → 202 Accepted (async processing)
```

**Configuration**
Table :
| Environment Variable | Required | Description |
|---------------------|----------|-------------|
| NEO4J_URI | Yes | bolt://neo4j:7687 |
| NEO4J_USER | Yes | neo4j (default) |
| NEO4J_PASSWORD | Yes | From .env |
| OPENAI_API_KEY | Yes | Required for embeddings (text-embedding-3-small) |
| ANTHROPIC_API_KEY | Yes | LLM for extraction (Claude Haiku) |
| SEMAPHORE_LIMIT | No | Concurrent requests (default: 3 for Tier 1 rate limit) |
| GRAPHITI_SERVICE_URL | No | URL for memory-api to call (default: http://graphiti-service:8300) |

Callout--warning : "OPENAI_API_KEY is required even if you use Anthropic as the LLM. graphiti-core uses text-embedding-3-small (OpenAI) for embeddings — Anthropic embeddings are not yet supported."

**Contradiction Detection**
"When graphiti-service encounters conflicting facts, it flags contradictions:"
```
Episode 1 (2025-01-15): "Alice is the Tech Lead"
Episode 2 (2025-06-01): "Bob is now the Tech Lead"
→ Graphiti creates temporal edges:
  Alice -[WAS_TECH_LEAD: 2025-01-15 to 2025-05-31]→ Acme
  Bob -[IS_TECH_LEAD: 2025-06-01 to present]→ Acme
```

**Querying the Graph**
"Query entities and their relationships via memory-api (not directly from Neo4j):"
```bash
curl "https://api.dejavu.cat/v1/graph/neighbors?entity=Alice&team_scope=acme" \
  -H "Authorization: Bearer $JWT"
# Returns: entities connected to Alice in the team graph
```

Callout--info : "graphiti_client is initialized in the FastAPI lifespan() context manager (not at module load time) to avoid event loop conflicts with graphiti-core."

**Introduction**
"The xbrain memory-api is a FastAPI application running on port 8000. All endpoints (except /v1/healthz) require authentication via Bearer token (Google ID token or GitHub OAuth token) and the X-Team-Scope header."

Base URL : `https://api.dejavu.cat` (ou votre domaine)

Auth header : `Authorization: Bearer {google_id_token_or_github_token}`
Team header : `X-Team-Scope: {team_scope}`

**Authentication**
"Obtain a token from Google Identity or GitHub OAuth. Bridge services use BRIDGE_SHARED_SECRET-signed JWTs."

---

**Health**

`GET /v1/healthz`
- Auth: None required
- Response: `{"status": "ok", "version": "..."}`
- Example: `curl https://api.dejavu.cat/v1/healthz`

---

**User Profile**

`GET /v1/me`
- Returns authenticated user info
- Response: `{"id": "uuid", "email": "...", "source_user_id": "google:...", "teams": [...]}`

`GET /v1/me/github`
- Returns GitHub profile if GitHub-authenticated
- Response: `{"github_username": "mrboups", "github_id": 12345, "is_org_member": true}`

---

**Memory**

`POST /v1/memory/upsert` → 201
- Body: `{"item": {7 required fields + content + metadata}}`
- Required fields: team_scope, project_scope, visibility, confidence, truth_level, source, validation_status
- Returns: `{"id": "mem_abc123..."}`
- Error: 422 if any required field missing; 400 if team_scope mismatch with header

Code example :
```bash
curl -X POST https://api.dejavu.cat/v1/memory/upsert \
  -H "Authorization: Bearer $JWT" \
  -H "X-Team-Scope: acme" \
  -H "Content-Type: application/json" \
  -d '{
    "item": {
      "content": "The Q2 target is 2M€",
      "team_scope": "acme",
      "project_scope": "fundraising",
      "visibility": "team",
      "confidence": 0.9,
      "truth_level": "WORKING",
      "source": "librechat:conv_abc",
      "validation_status": "pending"
    }
  }'
```

`GET /v1/memory/search`
- Query params: `q` (required), `project_scope`, `truth_level_min`, `limit` (default 10, max 100)
- Returns: `[{id, content, score, team_scope, truth_level, ...}]`

```bash
curl "https://api.dejavu.cat/v1/memory/search?q=fundraising+target&truth_level_min=WORKING&limit=5" \
  -H "Authorization: Bearer $JWT" -H "X-Team-Scope: acme"
```

`GET /v1/memory/{item_id}` — Get single item
`PATCH /v1/memory/{item_id}` — Update (truth_level cannot be patched → 405)
`DELETE /v1/memory/{item_id}` → 204
