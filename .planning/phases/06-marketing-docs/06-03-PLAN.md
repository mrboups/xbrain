**Data Flow — Chat Message**
Liste numérotée (comment un message de chat devient une memory item) :
1. User envoie un message dans LibreChat
2. LibreChat sauvegarde en MongoDB (message history)
3. librechat-bridge détecte le nouveau message
4. bridge POST /v1/messages à memory-api avec Bearer JWT
5. memory-api enforce le tagging contract (7 champs obligatoires)
6. message stocké dans PostgreSQL (event store) + Qdrant (vector)

9. Audit log écrit dans PostgreSQL

Contenu (sections h2) :

**What is the Memory System?**
"The memory system is xbrain's central invariant. Every piece of data — whether it comes from a chat, an agent, a Drive sync, or the Chrome extension — must pass through memory-api and carry exactly 7 mandatory tags. A write without any of these tags returns HTTP 422."

**The Tagging Contract (7 Fields)**
Table `.docs-table` :
| Field | Type | Description | Example |
|-------|------|-------------|---------|
| team_scope | string | Team identifier — hard wall between teams | "acme" |
| project_scope | string\|null | Sub-project within the team | "fundraising" |
| visibility | enum | team \| project \| private | "team" |
| confidence | float | 0.0–1.0, confidence in the data | 0.85 |
| truth_level | enum | EPHEMERAL → CANONICAL | "WORKING" |
| source | string | Who/what wrote this (pattern: prefix:id) | "librechat:conv_abc123" |
| validation_status | enum | pending \| approved \| rejected | "pending" |

Callout--warning : "Any POST to /v1/memory/upsert missing one of these 7 fields returns 422 Unprocessable Entity. This is enforced at the API level, not by convention."

**The 5 Truth Levels**
Description pour chaque level avec progression visuelle (div avec colored badges) :

EPHEMERAL (gris) — "Raw output: chat messages, web clips, draft notes. Unverified. Expires or gets promoted."

WORKING (bleu) — "In-progress knowledge: actively used but not yet validated. Most team knowledge lives here."

VALIDATED (vert) — "Peer-reviewed: at least one team member has explicitly approved this fact. Safe to reference in decisions."

CANONICAL (violet) — "Team truth: the definitive answer your team has agreed on. Injected automatically in LLM system prompts."

PUBLIC (or/gold) — "Published externally: shareable outside the team. Requires explicit promotion from CANONICAL."

Note : "truth_level can ONLY be promoted via the /v1/promotions workflow. A direct PATCH on truth_level returns HTTP 405."

Code example — Promoting a fact:
```bash
# Request promotion (any team member)
POST /v1/promotions
{
  "item_id": "mem_abc123",
  "target_level": "VALIDATED",
  "justification": "Confirmed with the client on 2026-05-01"
}

# Admin approves
PATCH /v1/promotions/{promotion_id}
{
  "decision": "approved",
  "note": "Verified against contract doc"
}
```

**Memory Upsert API**
Code example — Upserting a memory item:
```bash
curl -X POST https://api.dejavu.cat/v1/memory/upsert \
  -H "Authorization: Bearer $JWT" \
  -H "X-Team-Scope: acme" \
  -H "Content-Type: application/json" \
  -d '{
    "item": {
      "content": "The Q2 fundraising target is 2M€",
      "team_scope": "acme",
      "project_scope": "fundraising",
      "visibility": "team",
      "confidence": 0.9,
      "truth_level": "WORKING",
      "source": "librechat:conv_abc123",
      "validation_status": "pending"
    }
  }'

# Response
{"id": "mem_a8f3c2d1..."}
```

**Semantic Search**
Code example :
```bash
curl "https://api.dejavu.cat/v1/memory/search?q=fundraising+target&truth_level_min=WORKING&limit=5" \
  -H "Authorization: Bearer $JWT" \
  -H "X-Team-Scope: acme"
```

"Results are filtered by team_scope automatically — Team A can never see Team B's memories."

**Neo4j Graph Enrichment**
"When a memory item includes an 'entities' field in its metadata, memory-api asynchronously creates Entity nodes and MENTIONS edges in Neo4j:"

Code example :
```json
{
  "item": {
    "content": "Alice leads the fundraising project",
    "metadata": {
      "entities": [
        {"name": "Alice", "type": "person"},
        {"name": "fundraising", "type": "project"}
      ]
    }
  }
}
```

"Query relationships later via GET /v1/graph/neighbors?entity=Alice"

**Graphiti Enrichment**
"Every memory upsert triggers an async call to graphiti-service, which extracts temporal facts and updates the knowledge graph. This is fail-soft — if graphiti-service is down, the memory upsert still succeeds."
