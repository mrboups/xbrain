Breadcrumb : Docs > Drive Sync

Contenu (sections h2) :

**Overview**
"xbrain continuously synchronizes Google Drive folders to your team's memory. When a file is added or updated in a mapped folder, it's automatically processed and indexed in xbrain with full tagging — team_scope, project_scope, truth_level=WORKING."

**How It Works**

2 modes décrits :

Mode 1 — Push Webhooks (Primary, Phase 4)
"When a Drive file changes, Google sends a push notification to xbrain within seconds. This is the default for mapped folders."
```
Drive file updated
       │
       ▼
Google → POST /v1/drive/webhook (xbrain)
       │
       ▼
drive-sync processes the changed file
       │
       ▼
memory-api upsert (truth_level=WORKING)
```

Mode 2 — Polling Fallback (5-minute intervals)
"If webhooks are unavailable, drive-sync polls Drive every 5 minutes for changes. Only modified files are re-processed (incremental)."

**Setting Up Drive Sync**

Step 1 — OAuth authorization (admin only)
"An admin must authorize xbrain to access the team's Google Drive. This redirects to Google OAuth and stores the credentials encrypted in PostgreSQL."

```bash
# Admin initiates OAuth flow
GET https://api.dejavu.cat/v1/admin/drive/auth
# → Redirects to Google OAuth consent
# → After consent, credentials stored with Fernet encryption
```

Step 2 — Map a folder
```bash
curl -X POST https://api.dejavu.cat/v1/admin/drive/mappings \
  -H "Authorization: Bearer $ADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "team_scope": "acme",
    "project_scope": "fundraising",
    "folder_id": "1ABC...xyz",
    "folder_name": "Fundraising Docs"
  }'
# Returns: {"mapping_id": "uuid-...", "status": "active"}
```

Step 3 — Register webhook (auto)
"After mapping, drive-sync automatically registers a Drive push notification channel. Webhooks are renewed automatically before expiry (default: 7 days)."

Callout--info : "The webhook channel renewal is handled automatically by the drive-sync scheduler. No manual intervention required."

**Multi-Folder Mapping**
"Multiple Drive folders can be mapped to the same team, each with a distinct project_scope:"
```bash
# Map fundraising folder
POST /v1/admin/drive/mappings
{"team_scope": "acme", "project_scope": "fundraising", "folder_id": "1ABC..."}

# Map engineering folder (same team, different scope)
POST /v1/admin/drive/mappings
{"team_scope": "acme", "project_scope": "engineering", "folder_id": "2DEF..."}
```

"Files in the fundraising folder get project_scope='fundraising', and engineering files get project_scope='engineering'. They're searchable independently."

**List Current Mappings**
```bash
curl https://api.dejavu.cat/v1/admin/drive/mappings \
  -H "Authorization: Bearer $ADMIN_JWT"
# Returns list of all active folder mappings for the team
```

**Sync Status**
"Check what's been synced:"
```bash
curl "https://api.dejavu.cat/v1/memory/search?q=drive+sync&source=drive-sync" \
  -H "Authorization: Bearer $JWT" \
  -H "X-Team-Scope: acme"
```

Callout--warning : "Drive credentials are stored encrypted using Fernet encryption. Never commit OAuth tokens or service account keys to the repo."

**Supported File Types**
Table :
| File Type | Processing | Notes |
|-----------|-----------|-------|
| Google Docs | Text extraction | Exported as plain text |
| Google Sheets | Text extraction | First sheet only |
| PDF | Text extraction | Via PyMuPDF |
| Markdown (.md) | Direct | No conversion needed |
| Text (.txt) | Direct | No conversion needed |
| Images | Skipped | Not yet supported |

Breadcrumb : Docs > Chrome Extension

Contenu (sections h2) :

**What is the xbrain Web Clipper?**
"The xbrain Chrome Extension (Manifest V3) lets you send selected web content directly to your team's xbrain memory from any webpage. You choose the truth level before sending — making it easy to capture and classify information on the fly."

**Installation**

"The extension is not yet on the Chrome Web Store. Install it in developer mode:"

Steps numérotés :
1. Clone the xbrain repo: `git clone https://github.com/mrboups/xbrain.git`
2. Open Chrome → Settings → Extensions → Enable "Developer mode" (toggle top right)
3. Click "Load unpacked" → Select the `chrome-extension/` folder in the repo
4. The xbrain icon appears in your Chrome toolbar

Callout--info : "The extension requires a Google account that has been added to your xbrain team by an admin."

**Extension Manifest**
"The extension uses Manifest V3 with Google Identity API:"
```json
{
  "manifest_version": 3,
  "name": "xbrain Web Clipper",
  "version": "1.0.0",
  "permissions": ["identity", "activeTab", "storage"],
  "background": { "service_worker": "background.js" },
  "action": { "default_popup": "popup.html" },
  "content_scripts": [{ "matches": ["<all_urls>"], "js": ["content.js"] }],
  "oauth2": {
    "client_id": "YOUR_GOOGLE_CLIENT_ID.apps.googleusercontent.com",
    "scopes": ["openid", "email", "profile"]
  },
  "host_permissions": ["https://api.dejavu.cat/*"]
}
```

Callout--warning : "Replace host_permissions with your actual memory-api URL (e.g. https://api.yourdomain.com/*) before loading the extension."

**How to Use**

Step 1 — Authenticate
"Click the xbrain icon in your toolbar. On first use, click 'Sign in with Google'. The extension uses Chrome's launchWebAuthFlow to obtain a Google ID token — no popup blocker issues."

Step 2 — Select content
"On any webpage, select the text you want to save. Right-click → 'Send to xbrain' — or open the popup and the current page URL + title are pre-filled."

Step 3 — Choose truth level
"In the popup, select the truth level for the clipped content:"
- EPHEMERAL — Quick notes, unverified snippets
- WORKING — Actively useful, in progress
- VALIDATED — Verified information
- CANONICAL — Team-approved truth

Step 4 — Send
"Click 'Send to Brain'. The content is POSTed to memory-api with your team's scope. You'll see a success confirmation in the popup."

**Architecture**

```
Browser tab (content.js)
    │ selected text + URL + title
    ▼
popup.html (user selects truth level)
    │
    ▼
background.js (service worker)
    │ launchWebAuthFlow → Google ID token
    │
    ▼
POST https://api.dejavu.cat/v1/memory/upsert
Authorization: Bearer {google_id_token}
X-Team-Scope: {team_from_storage}
{
  "item": {
    "content": "selected text",
    "source": "chrome-extension:dejavu.cat",
    "truth_level": "WORKING",
    "team_scope": "acme",
    ...
  }
}
```

**CORS Configuration**
"The memory-api accepts requests from chrome-extension://* origins. This is configured in memory-api's CORS middleware:"

```python
# In memory-api/app/main.py
allow_origins=["chrome-extension://*", "https://api.dejavu.cat"]
```

"Authentication via Bearer token (Google ID token) is the real security control — the wide CORS origin is acceptable."

**Configuring for Your Deployment**
- `host_permissions` : update to your memory-api URL
- `oauth2.client_id` : use your Google OAuth client ID (same as GOOGLE_CLIENT_ID in .env)
- `storage` : team_scope saved in Chrome local storage after first login

Breadcrumb : Docs > GitHub Auth

Contenu (sections h2) :

**Overview**
"xbrain supports two authentication methods: Google OAuth (default) and GitHub OAuth. GitHub auth adds team membership verification via GitHub Organization membership — only members of your GitHub Org can access xbrain."

**Authentication Methods**

Table :
| Method | Provider | User ID format | Org restriction |
|--------|----------|----------------|-----------------|
| Google OAuth | Google SSO | google:{sub} | No |
| GitHub OAuth | GitHub | github:{login} | Yes (optional) |

"Both methods use the same session mechanism. A user authenticated with Google and the same user authenticated with GitHub are treated as different users unless account linking is set up."

**GitHub OAuth Setup**

Step 1 — Create GitHub OAuth App
"In your GitHub organization settings: Settings → Developer settings → OAuth Apps → New OAuth App"
- Application name: "xbrain"
- Homepage URL: https://your-domain
- Callback URL: https://your-domain/oauth/github/callback

Step 2 — Configure LibreChat
"Add to LibreChat's .env:"
```bash
GITHUB_CLIENT_ID=your_github_client_id
GITHUB_CLIENT_SECRET=your_github_client_secret
```

Step 3 — Configure Org verification in memory-api
```bash
# In infrastructure/.env
GITHUB_ORG=your-github-org-name    # e.g. "your-github-org"
GITHUB_API_PAT=ghp_...             # Personal Access Token with read:org scope
```

Callout--info : "Set GITHUB_ORG to restrict access. If empty, any GitHub user can authenticate. The GITHUB_API_PAT needs read:org permission to check org membership."

**How Org Membership Works**

"When a user authenticates with GitHub, memory-api verifies their org membership:"

Flow diagram :
```
User clicks "Sign in with GitHub" in LibreChat
       │
       ▼
GitHub OAuth → returns gho_ prefixed token
       │
       ▼
memory-api checks token prefix (gho_)
       │
       ▼
GET https://api.github.com/orgs/{GITHUB_ORG}/members/{login}
using GITHUB_API_PAT
       │
   ┌───┴───┐
   │ Yes   │ No
   ▼       ▼
 Allow   Return 403
  (github_is_org_member=True)
```

**Database Schema**
"GitHub user data is stored in the users table (migration 0007):"
```sql
-- Migration 0007 adds:
ALTER TABLE users ADD COLUMN github_username VARCHAR(255);
ALTER TABLE users ADD COLUMN github_id BIGINT;

-- github_is_org_member is NULL for Google users (not False)
-- This allows: if user.github_is_org_member is False: reject
-- Without blocking Google users
```

**User Identity**
"GitHub users have a source_user_id in the format github:{login}:"
```python
# Example
source_user_id = "github:mrboups"

# Note: GitHub email can be null (user may have hidden their email)
# xbrain uses github:{login} as the stable identifier, not email
```

**Account Linking**
"A user can sign in with both Google AND GitHub. Each creates a separate user record in xbrain. Account linking (merging the two identities) is currently manual:"

```bash
# Check if a GitHub user exists
curl "https://api.dejavu.cat/v1/me" \
  -H "Authorization: Bearer $GITHUB_JWT"
# Returns: {"source_user_id": "github:mrboups", "github_username": "mrboups"}
```

Callout--info : "Automatic account linking (merge Google + GitHub identities) is a future enhancement. For now, each auth method creates a separate user record."

**Security Notes**
- GitHub token detected by gho_ prefix — no additional API call required for token type detection
- GITHUB_API_PAT is stored as an env variable on the VM (not in the database)
- Org membership is checked at login time only — cached for the session duration
- github_is_org_member=None for Google users prevents accidental access restriction
