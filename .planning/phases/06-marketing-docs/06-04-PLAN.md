Contenu (sections h2) :

**Team Isolation**
"In xbrain, every piece of data belongs to exactly one team. The X-Team-Scope HTTP header is mandatory on every authenticated API call. Team A cannot read, write, or search Team B's data — enforced at the API layer, not just the UI."

**The team_scope Field**
"Every memory item carries a team_scope field. If the item's team_scope doesn't match the X-Team-Scope header, the write returns HTTP 400."

Code example :
```bash
# This works — team_scope matches header
curl -X POST https://api.dejavu.cat/v1/memory/upsert \
  -H "X-Team-Scope: acme" \
  -H "Authorization: Bearer $JWT" \
  -d '{"item": {"team_scope": "acme", ...}}'

# This fails — team_scope mismatch
curl -X POST https://api.dejavu.cat/v1/memory/upsert \
  -H "X-Team-Scope: acme" \
  -H "Authorization: Bearer $JWT" \
  -d '{"item": {"team_scope": "other-team", ...}}'
# → 400 Bad Request: item.team_scope must match X-Team-Scope header
```

**Project Scopes**
"Within a team, data can be further scoped by project (project_scope). This allows isolation of e.g. fundraising data from engineering data within the same team."

Table des visibility options :
| Visibility | Who can see it |
|------------|----------------|
| team | All authenticated members of the team |
| project | Only members with access to that project_scope |
| private | Only the owner |

**User Management**
- Users authenticate via Google OAuth (SSO) — same identity across LibreChat and Open WebUI
- source_user_id = OIDC sub claim (Google) or github:{login} (GitHub)
- Admin users can be configured via ADMIN_USER_SUBS env variable

**Creating Teams**
"Teams are created by an admin via the memory-api admin endpoints. Once created, a team has a team_scope string identifier that is used in all API calls and memory items."

Code example (admin creating a team) :
```bash
curl -X POST https://api.dejavu.cat/v1/admin/teams \
  -H "Authorization: Bearer $ADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{"name": "Engineering Team", "scope": "engineering"}'
```

**Drive Folder Mapping per Team**
"Each team can have one or more Google Drive folders mapped to it. When a file is updated in a mapped folder, it's automatically synced to xbrain and tagged with that team's scope."

Code example :
```bash
curl -X POST https://api.dejavu.cat/v1/admin/drive/mappings \
  -H "Authorization: Bearer $ADMIN_JWT" \
  -d '{
    "team_scope": "acme",
    "project_scope": "fundraising",
    "folder_id": "1ABC...xyz",
    "folder_name": "Fundraising Docs"
  }'
```

Callout--info : "Multiple Drive folders can be mapped to the same team with different project_scopes. See Drive Sync documentation for details."

Contenu (sections h2) :

**The MCP Gateway**
"xbrain includes a central MCP (Model Context Protocol) gateway that acts as a registry and proxy for all MCP tools. Every tool call passes through the gateway, which injects team_scope and user_id, and logs every call to the audit trail."

Architecture :
```
LibreChat ──► /mcp/aggregate (SSE) ──► mcp-gateway ──► mcp-scraper (8100)
                                                    ├──► mcp-drive-read (8101)
                                                    ├──► mcp-calendar (8102)
                                                    └──► mcp-deck (port 8200)

agent-runtime ──► mcp_gateway_client.py ──► mcp-gateway ──► [same tools]
```

"The gateway aggregates all tools into a single SSE endpoint (/mcp/aggregate) that LibreChat connects to. Each tool call is authenticated and team-scoped before being forwarded."

**Registering Tools**
"Tools are registered in the gateway at startup via register-mcp-tools.sh:"
```bash
# Register all MCP tools
bash infrastructure/scripts/register-mcp-tools.sh

# Each tool registration:
curl -X POST http://mcp-gateway:8080/v1/tools/register \
  -H "Authorization: Bearer $GATEWAY_JWT" \
  -d '{
    "name": "mcp-scraper",
    "url": "http://mcp-scraper:8100",
    "team_scope": "acme"
  }'
```
