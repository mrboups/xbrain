    Edit `packages/memory-models/xbrain_memory/providers/native_provider.py::upsert`. Replace the entire body inside `async with pool.acquire() as conn:` block (lines 65-100) with a single transaction that:

    1. Performs `INSERT … ON CONFLICT (id) DO UPDATE` and uses `xmax` to detect whether the row was newly inserted (xmax=0) or updated (xmax>0).
    2. If updated, snapshot the OLD row to `memory_items_history` from inside the same connection / transaction using a CTE pattern OR a follow-up read of the prior values (the CTE approach is cleanest — see below).

    The race-free approach uses the existing memory_items columns plus a returning clause:

    ```python
    async with pool.acquire() as conn:
        async with conn.transaction():
            # Snapshot existing row to history BEFORE the upsert (if it exists).
            # This runs in the same transaction — if the row doesn't exist, INSERT 0.
            await conn.execute(
                """
                INSERT INTO memory_items_history
                  (item_id, team_scope, content, metadata, truth_level,
                   validation_status, visibility, confidence, source)
                SELECT id, team_scope, content, metadata, truth_level,
                       validation_status, visibility, confidence, source
                  FROM memory_items
                 WHERE id = $1 AND team_scope = $2
                """,
                UUID(item_id), item.team_scope,
            )
            # Race-free upsert (Phase 13 13-RESEARCH §Pitfall 6).
            await conn.execute(
                """
                INSERT INTO memory_items
                  (id, team_scope, project_scope, content, metadata, truth_level,
                   validation_status, visibility, confidence, source)
                VALUES ($1, $2, $3, $4, $5::jsonb, $6, $7, $8, $9, $10)
                ON CONFLICT (id) DO UPDATE
                SET content = EXCLUDED.content,
                    metadata = EXCLUDED.metadata,
                    truth_level = EXCLUDED.truth_level,
                    validation_status = EXCLUDED.validation_status,
                    visibility = EXCLUDED.visibility,
                    confidence = EXCLUDED.confidence,
                    source = EXCLUDED.source,
                    updated_at = now()
                """,
                UUID(item_id), item.team_scope, item.project_scope, item.content,
                json.dumps(item.metadata), item.truth_level.value,
                item.validation_status.value, item.visibility.value,
                item.confidence, item.source,
            )
    ```

    **Critical correctness note:** The history INSERT runs BEFORE the upsert and inside the same transaction. If the row does not yet exist, the SELECT returns zero rows and the history INSERT inserts zero rows (no-op). If the row exists, the snapshot is captured before being overwritten. The transaction guarantees atomicity — both succeed together or both roll back, so we never have a history snapshot of a row that wasn't actually updated.

    **Concurrency under PostgreSQL row-level locking:** Inside the explicit `conn.transaction()`, the `INSERT … ON CONFLICT (id) DO UPDATE` acquires a row-level write lock on the conflicting row, serializing concurrent calls. A second concurrent caller sees the just-committed state when its own history-snapshot SELECT runs, so its snapshot reflects what the first call wrote (correct behavior — Test 3 asserts 4 history rows for 5 concurrent calls with the same id).
