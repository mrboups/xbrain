Wire the summon site to the per-team list and expose the two endpoints that make
the client and server share ONE source of truth.

detecting (so detection is team-scoped, closing the cross-team-leakage class).

`@claude` query-prefix in brain_ingest is aligned to the new agent vocabulary.

of truth), D-21-05 (no-restart effect), D-21-06 (validation + authZ).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → PATCH /agent-aliases | Untrusted admin-supplied alias strings cross into persistence + regex |
| client → GET /agent-aliases | Any authenticated member reads a team's effective list |
| team A detection ↔ team B | Per-team resolution must not leak across teams |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02-01 | Tampering | PATCH alias value | mitigate | `_validate_aliases`: charset `[A-Za-z0-9_-]`, len 1–32, ≤8, strip leading `@`, dedup, reject empty and reserved "claude" → 422 at the edge; `_build_mention_regex` re.escapes as defense in depth. |
| T-21-02-02 | Elevation of privilege | PATCH by non-admin | mitigate | `_require_team_admin(principal, team, session)` before any write → 403 for members and non-members (Test 3). |
| T-21-02-03 | Information disclosure / cross-tenant | per-team detection | mitigate | Summon resolves `effective_aliases(team.agent_aliases)` for THE loaded team only; GET returns only that team's list; Test 4 asserts team A's alias is absent from team B. |
| T-21-02-04 | Spoofing | `@claude` via a custom alias | mitigate | Validation rejects "claude" (case-insensitive) so `@claude` can never be a trigger on any team → SC#2 stays absolute. |
| T-21-02-05 | Repudiation | admin changes agent name | mitigate | PATCH writes an audit row (`team.agent_aliases.set`) with actor + payload before commit. |
</threat_model>
