## What Was Built

### github_catalog.py (apps/memory-api/app/services/github_catalog.py)

New service module providing:
- `build_catalog_item_id(team_scope, full_name)` — deterministic uuid5 keyed by `(team_scope, full_name)` using a fresh `GITHUB_CATALOG_NS` (never change — production idempotency key).
- `build_catalog_content(...)` — locked content shape: `"{full_name} — {summary}\nLanguage: {lang}. Topics: {topics}. Visibility: {vis}."`
- `build_catalog_item(repo_obj, team_scope, ...)` — builds a MemoryItem with the full 7-field tagging contract: `source='github:repo-catalog'`, `truth_level=WORKING`, `visibility=TEAM`, `validation_status=PENDING`, `confidence=0.6`, `project_scope` = short repo name (≤64 chars), `team_scope`, metadata with `full_name`/`html_url`/`default_branch`/`primary_language`/`topics`/`visibility`/`readme_summarized`/`installation_id`.
- `summarize_readme(readme_text, repo_full_name, team_scope)` — Haiku README summary (fail-soft: returns `None` on no-client / budget exhausted / any exception). Reuses `relevance_filter._check_budget`/`_record_tokens` to share the daily token cap.
- `fetch_readme(session, owner, name, installation_id)` — GET `/repos/{owner}/{name}/readme` (GitHub dedicated README endpoint); base64-decode; 404/403 → `None` (fail-soft).
- `enumerate_install_repos(installation_id)` — paginated GET `/installation/repositories?per_page=100` (handles 74+ repos across pages).
- `upsert_catalog_item(session, provider, repo_obj, team_scope, ...)` — fetch README → summarize → effective_summary → `build_catalog_item` → `provider.upsert`.
- `soft_delete_catalog_item(session, provider, team_scope, full_name)` — UPDATE `memory_items SET deleted_at=now()` (PG) + `provider.mark_deleted` (Qdrant). Idempotent.
- `index_team_catalog(team_scope, github_org, *, session_factory)` — enumerate install repos, `asyncio.Semaphore(GITHUB_CATALOG_CONCURRENCY)` cap, upsert each. Returns `{team_scope, indexed, skipped}`.
- `index_orgs_catalog(*, org_logins, user_id, session_factory)` — sign-in backfill entrypoint; resolves team(s) per org via `teams_repo.get_teams_with_github_org`; calls `index_team_catalog` per match; never raises.

Three new settings in `app/config.py` (safe defaults, no `.env` change required):
- `GITHUB_CATALOG_ENABLED: bool = True`
- `GITHUB_CATALOG_CONCURRENCY: int = 5`
- `GITHUB_CATALOG_README_CHARS: int = 8000`

### GET /v1/internal/github/catalog (apps/memory-api/app/routes/internal_github.py)

Source-freedom confirmation: `memory_items.source` is `VARCHAR(128)` with no CHECK constraint (migration 0002); `idx_memory_source_team_unique` was dropped (migration 0020). The literal `'github:repo-catalog'` (19 chars) is safe.

Endpoint behavior:
- Resolves team scope from `X-Team-Scope` header (preferred) or `team_scope` query param.
- Returns 400 if neither is provided.
- Direct asyncpg pool query: `SELECT ... FROM memory_items WHERE source = 'github:repo-catalog' AND team_scope = $1 AND deleted_at IS NULL ORDER BY updated_at DESC`.
- Returns `{team_scope, count, repos[]}` with flattened metadata (full_name, html_url, primary_language, topics, visibility, readme_summarized).
- Auth: `Depends(get_current_principal)`, kind='bridge' accepted.

### repository webhook branch (apps/memory-api/app/routes/webhooks_github.py)

New `_handle_repository_event(payload)` handler dispatched when `event == "repository"`:
- `created`, `edited`, `publicized` → `upsert_catalog_item`
- `privatized`, `deleted`, `archived` → `soft_delete_catalog_item`
- `renamed` → soft-delete OLD full_name FIRST (RESEARCH §Pitfall 4), then upsert new
- other actions → log and ignore

All catalog work runs in `asyncio.create_task` with a fresh `async_session_factory()` session (never the request session). Signature verification still precedes JSON parsing (CRITICAL contract preserved).

**mrboups webhook team-resolution choice (documented):** For User-type installs (`github_account_type='User'`), the `repository` webhook payload carries only `installation_id`, not a user identity. Resolution: query `team_members JOIN users WHERE users.github_username == install.account.login` (owner_login for personal repos == the account login, e.g. `mrboups`). If no team membership matches, log and no-op — sign-in trigger remains the primary backfill path for personal repos. This is a best-effort resolution; the key invariant is that the backfill runs on sign-in regardless.

## mrboups Personal-Repo Webhook Team Resolution (Documented Choice)

For User-type GitHub App installations (account_type='User', e.g. mrboups personal account with 60 repos), the `repository` webhook payload does NOT carry a user identity — only `installation_id` and `account.login` (the personal GitHub username, e.g. `mrboups`).

**Chosen approach:** resolve team scopes by querying `team_members JOIN users WHERE users.github_username == install.account.login`. If any user in the team_members table has `github_username` matching the installation's account login, catalog items are written to their teams. If no match is found, log and no-op.

**Rationale:** this covers the common case where mrboups is a member of a team (e.g. `aibrussels`) via GitHub org membership already established at sign-in. For pure personal repos with no team membership match, the sign-in trigger (which already runs on every GitHub sign-in and processes `org_logins`) remains the primary backfill path. The webhook is an incremental optimisation, not a precondition.

**Code location:** `webhooks_github.py::_handle_repository_event::_resolve_team_scopes` — account_type=='User' branch.
