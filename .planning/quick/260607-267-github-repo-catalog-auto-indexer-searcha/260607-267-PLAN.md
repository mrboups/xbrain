<objective>
Build a **GitHub repo-catalog auto-indexer** so the model can answer *"which repo handles X / list my org's repos"* via `memory_search` and a new exact-list tool, instead of guessing repo names.

For every repository a team can reach through the xbrain GitHub App installation, the system: (1) enumerates it via `GET /installation/repositories` (installation token, resolved per owner), (2) generates a **Claude Haiku summary of the repo's README** (fail-soft to the GitHub `description`), and (3) stores the repo as **one searchable brain `memory_item`** carrying the full 7-field tagging contract — `source='github:repo-catalog'`, `truth_level=WORKING`, `project_scope=<repo>`, `team_scope=<team>`. Storage is **BRAIN ONLY** — `provider.upsert(MemoryItem)`, deterministic `uuid5` id, **no new table**.

The catalog stays fresh on **three triggers**: team creation, GitHub user sign-in, and the GitHub `repository` webhook (created → add, renamed → soft-delete old + upsert new, deleted/privatized → soft-delete, publicized/edited → re-upsert). The initial ~74-README backfill is a **bounded fire-and-forget background job** (concurrency cap, README input capped, reuses the Haiku daily token cap) — sign-in and team-create NEVER await the LLM calls.

A **`github_list_repos` read path** (MCP tool on mcp-github + `GET /v1/internal/github/catalog` on memory-api) lists the catalog **exactly** (direct `memory_items` SELECT filtered by `source` + `team_scope` + `deleted_at IS NULL`), not just semantically. The catalog read path is **team-scoped from the start**.

Purpose: turn the App installation's repo reach into scoped, recallable team memory — the missing "what do we have / what handles X" layer over the existing per-file `github_sync`.
Output: one new service module (`github_catalog.py`), one new internal endpoint, a webhook `repository` branch, two trigger hooks (sign-in + team-create), one MCP tool, unit tests, and a documented (NOT executed) deploy + initial-backfill + operator runbook. No new DB migration (brain-only).

**PLAN-ONLY — DO NOT EXECUTE. For user review/approval first.**
</objective>
