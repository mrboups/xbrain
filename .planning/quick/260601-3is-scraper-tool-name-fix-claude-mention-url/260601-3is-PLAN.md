# Quick Task 260601-3is — Scraper tool-name fix + @claude URL pre-fetch

## Root cause (verified live)
Every MCP sidecar exposes tools whose names differ from the gateway registry id:
scraper→`scrape`, calendar→`list_events`, drive-read→`read_drive_file`/`write_drive_file`,
deck→`deck_create`/`deck_update`. The aggregate (LibreChat's MCP server) forwards the
registry id as the tool name → the sidecar replies `Unknown tool: scraper` (isError). The
old register-mcp-tools.sh "smoke test" false-passed by measuring the error JSON's length.

## Tasks

### Task 1 — gateway: resolve the real sidecar tool name
- **files:** `apps/mcp-gateway/app/main.py`
- **action:** in `call_tool`, inside the `ClientSession` block, AFTER `await session.initialize()` and BEFORE `session.call_tool(...)`, list the sidecar's tools and resolve the name:
  ```python
  try:
      listed = await session.list_tools()
      available = [t.name for t in listed.tools]
      if mcp_tool_name not in available and len(available) == 1:
          log.info("gateway.tool_name_resolved", requested=mcp_tool_name, actual=available[0], sidecar=tool_name)
          mcp_tool_name = available[0]
  except Exception as exc:  # noqa: BLE001
      log.warning("gateway.list_tools_failed", sidecar=tool_name, error=str(exc))
  result = await session.call_tool(mcp_tool_name, mcp_arguments)
  ```
  - Only resolves when the requested name is NOT exposed AND the sidecar has exactly one tool (single-tool sidecars: scraper, calendar). Multi-tool sidecars (drive-read, deck) are left unchanged — callers that pass the correct name (agent-runtime) keep working; the aggregate forwarding a bare registry id to a multi-tool sidecar still errors (out of scope, noted).
- **verify:** a gateway POST /tools/scraper/call with body name="scraper" now returns scraped text with isError=false (test on VM after deploy).
- **done:** single-tool sidecar names auto-resolve; existing correct-name callers unaffected.

### Task 2 — memory-api: @claude mention pre-fetches URLs
- **files:** `apps/memory-api/app/config.py`, `apps/memory-api/app/services/team_chat_agent.py`
- **action:**
  - config.py: add `MCP_GATEWAY_URL: str = "http://mcp-gateway:8080"`.
  - team_chat_agent.py: add helpers:
    - `_extract_urls(text: str) -> list[str]`: regex `https?://[^\s)>\]]+`, strip trailing punctuation, dedupe preserving order, cap at 3.
    - `async def _fetch_url_via_scraper(url: str, team_scope: str) -> str | None`: mint a bridge JWT (reuse `_sign_bridge_jwt_acting("team-chat-agent")` — it has no team_scope claim, so ALSO send header `X-Team-Scope: <team_scope>`; the gateway falls back to the header). POST `f"{settings.MCP_GATEWAY_URL}/tools/scraper/call"` with headers `Authorization: Bearer <jwt>`, `X-Team-Scope: <team_scope>`, `Content-Type: application/json` and JSON body `{"name": "scrape", "arguments": {"url": url}}` (use the REAL tool name "scrape" so it works regardless of Task 1). Timeout ~20s. Parse `resp.json()`: if `isError` is true → return None; else join the `content[*].text` strings, cap to ~6000 chars, return. Fail-soft: any exception → return None (log a warning).
    - `async def _build_fetched_web_block(text: str, team_scope: str) -> str`: extract URLs; for each, fetch; build `"\n\n## Fetched web content\n\n### <url>\n<content-or-'(could not fetch)'>\n"` sections; return "" if no URLs.
  - In `_do_handle`, AFTER `chat_history_block` is built (~line 155) and BEFORE routing: compute `web_block = await _build_fetched_web_block(triggering_message.content or "", team.slug)`; if `web_block`, set `chat_history_block = chat_history_block + web_block`. Log `team_chat_agent.web_prefetch` with the url count. This keeps the fetched content in the UNCACHED user turn (the cached block is `cached_memory_block`, untouched) so the Anthropic prompt cache is not polluted.
  - Do NOT change the `_stream_via_promax` / `_stream_via_anthropic_api` signatures — they already take `chat_history_block`.
- **verify:** sending "@claude summarize https://example.com" causes a gateway scraper call and the fetched text appears in the prompt (check logs `team_chat_agent.web_prefetch`).
- **done:** URLs in @claude messages are fetched + injected, fail-soft.
