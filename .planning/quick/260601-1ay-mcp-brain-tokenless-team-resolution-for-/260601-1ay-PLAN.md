# Quick Task 260601-1ay — Tokenless mcp-brain team resolution for LibreChat

## Why
Passive recall in LibreChat is structurally broken (injected Mongo messages are orphans
with sender=undefined, never in LibreChat's parentMessageId chain → never sent to the model).
The reliable path is the ACTIVE `memory_search` MCP tool, which the model already calls.
Today it fails because mcp-brain requires a per-user xbt_ token (`Authorization: Bearer {{XBRAIN_TOKEN}}`)
that the user must paste into MCP Settings, AND the only token they have is team_scope=''
(multi-team sentinel) which mcp-brain's `_resolve` rejects. Make memory tools work for any
logged-in LibreChat user with ZERO token setup, by resolving the team server-side from the
email LibreChat already forwards — without weakening the PUBLIC (mcp.example.com) token auth.

## Security model (critical — mcp-brain is publicly exposed)
- The new tokenless "email path" is gated by a shared secret: it activates ONLY when the
  request carries `X-Internal-Secret` equal to `BRIDGE_SHARED_SECRET` (constant-time compare,
  and only if the secret is non-empty). LibreChat injects this secret from its env via
  librechat.yaml `${BRIDGE_SHARED_SECRET}`. Public ChatGPT/Claude.ai callers come through nginx
  without the secret → they CANNOT use the email path; they must send a valid xbt_ token (unchanged).
- The user email comes from LibreChat's authenticated session via `{{LIBRECHAT_USER_EMAIL}}`
  (same mechanism the mcp-gateway aggregate already uses, librechat.yaml line ~167). LibreChat
  is the trust anchor (same pattern as the OpenWebUI pipeline acting-user JWT).

### Task 2 — mcp-brain: memory_client resolve helper
- **files:** `apps/mcp-brain/app/memory_client.py`
- **action:** add
  ```python
  async def resolve_team_scope_internal(bridge_jwt: str, sub: str) -> str | None:
      """Resolve a user's primary team slug via memory-api internal endpoint. None if unknown."""
      async with httpx.AsyncClient(timeout=10.0) as c:
          r = await c.get(f"{_BASE}/v1/internal/resolve-team-scope",
                          params={"sub": sub},
                          headers={"Authorization": f"Bearer {bridge_jwt}"})
          r.raise_for_status()
          return r.json().get("team_scope")
  ```
  (No X-Team-Scope header — the internal endpoint does not require one.)
- **done:** helper added; on HTTP error it raises (caller handles).

### Task 3 — mcp-brain: rewrite `_resolve(ctx)` with token path + gated email path
- **files:** `apps/mcp-brain/app/main.py`
- **action:** replace `_get_token` + `_resolve` with header-aware logic. Read headers case-insensitively from `ctx.request_context.request.headers`:
  - `authorization`, `x-librechat-user-email`, `x-internal-secret`.
  - Compute `raw = authorization.removeprefix("Bearer ").strip()` when it starts with "Bearer ", else "".
  - **Token path (unchanged, public):** `if raw.startswith("xbt_"):` → `me = await memory_client.get_me(raw)`; `team_scope = me.get("api_token_team_scope") or me.get("team_scope")`; if empty raise the existing "Token is not associated with a team..." error; return `(raw, team_scope)`.
  - **Email path (new, LibreChat only):** else:
    - `secret = settings.BRIDGE_SHARED_SECRET`
    - require `settings.INTERNAL_EMAIL_PATH_ENABLED and secret and x_internal_secret and hmac.compare_digest(x_internal_secret, secret) and email`, else raise `ValueError("Authentication required: set your xbt_ token, or call from an authorized frontend.")`. (Import `hmac`.)
    - `sub = f"email:{email}"` (matches memory-api source_user_id convention; the resolve endpoint also falls back to bare email).
    - mint a bridge JWT (team_scope="default" placeholder is fine for the resolve call) and call `resolve_team_scope_internal(jwt, sub)`; if the result is falsy, **retry once** with `sub=email` (bare) before giving up.
    - if no team → raise `ValueError("No team is associated with your account yet.")`.
    - mint a SECOND bridge JWT with `team_scope=<resolved>`, `sub=sub`, and return `(that_jwt, resolved_team_scope)`.
  - Keep the tuple contract `(token_or_jwt, team_scope)` so all existing tool bodies work unchanged — they pass it to `memory_client._headers` which sends `Authorization: Bearer <jwt>` + `X-Team-Scope: <team_scope>`; memory-api resolves the bridge JWT (kind=bridge) and `get_team_scope` matches team_scope to the header. NOTE: memory_add `source` stays "mcp-brain".
  - Add a `log.info("mcp_brain.resolve", mode="token"|"email", team=team_scope)` line (do not log the secret or full token).
- **verify:** import compiles; the token path returns unchanged; the email path is unreachable without the matching secret.
- **done:** dual-path resolve, secret-gated, fail-closed.
