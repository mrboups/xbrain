# Quick Task 260512-eo1: Extension onboarding + popup/LibreChat FR→EN migration

## Goal

Close the Phase 9 onboarding gap surfaced during 2026-05-12 UAT: the extension popup expects `xbt_token` + `user_sub` in `chrome.storage.session` but has **no UI to mint or store them**. Currently the user must paste a 3-step JS blob into the SW console to bootstrap the WS connection. Make this a single-click flow, persistent across browser restarts, and aligned with the new CLAUDE.md English-only product policy.

## Background

- Live UAT (2026-05-12) confirmed end-to-end routing works once the WS is up, but bootstrap required manual console gymnastics.
- `chrome.storage.session` is volatile — the manual setup must be redone on every browser restart.
- `popup.html`, `popup.js`, `background.js`, and `librechat.yaml` contain French user-facing strings that violate the language policy committed in `a19c613`.

## Scope

### In

1. **Popup UX:** "Connect" button when disconnected, "Disconnect" + email/last-seen when connected. State driven by presence of `xbt_token` in `chrome.storage.local`.
2. **Background handler:** New `MINT_AND_CONNECT` runtime message that:
   - Calls existing `getGoogleIdToken()`.
   - POSTs `/v1/me/api-token` with `{ team_scope: "default", name: "chrome-extension" }`.
   - GETs `/v1/me` and reads `source_user_id` (Phase 9 fix in `4781ac0` makes this the canonical field).
   - Writes `{xbt_token, user_sub}` to `chrome.storage.local`.
3. **Storage migration:** `openBridgeWS()` and the `storage.onChanged` listener read from `chrome.storage.local` first, fall back to `chrome.storage.session` (so existing in-memory sessions still work).
4. **Disconnect flow:** Popup button calls `DELETE /v1/me/api-token/{id}` then clears `chrome.storage.local`. WS auto-closes on storage change.
5. **FR→EN sweep (popup + LibreChat only):**
   - `popup.html`: every visible string + the `lang="fr"` attribute.
   - `popup.js`: error messages, status placeholders, alert strings.
   - `background.js`: user-visible error strings (comments can stay if non-blocking).
   - `manifest.json`: description field.
   - `librechat.yaml`: endpoint label `"Claude (mon abonnement)"` → `"Claude Pro/Max"`.
   - `verify-phase9.sh` test 7: update grep string to match new label.
6. **Test:** `chrome-extension/tests/run_onboarding_test.mjs` — a minimal node test that mocks `chrome.storage.local`/`session` + `fetch` and verifies the mint-and-store flow writes both keys correctly, plus storage fallback resolution.

### Out (deferred to a future quick task)

- French strings in `apps/*` (internal logs, comments, READMEs) — not user-facing through the popup/chat surfaces.
- Historical Phase 9 planning artifacts (`09-UAT.md`, `09-CAPTURE.md`) — touch only when modifying for other reasons.

## Decisions (locked)

| Decision | Choice | Why |
|----------|--------|-----|
| Storage tier | `chrome.storage.local` (persistent) | Avoid daily re-bootstrap; bearer-token-on-disk risk is equivalent to a session cookie. |
| Endpoint rename | `Claude Pro/Max` | Short, descriptive, English. Mirrors the routing target (a Pro or Max subscription on claude.ai). |
| Token revoke on disconnect | Yes — DELETE /v1/me/api-token/{id} | Otherwise tokens accumulate forever in `user_api_tokens`. Track the token `id` from the mint response. |
| Mint UI failure surface | Inline status in popup (red box) + console log | No alert() dialogs (poor UX in popup). |
| Storage migration shape | Read both `local` then `session`, write only `local` going forward | Lets existing manually-bootstrapped sessions keep working until restart. |

### Task 2 — Background message handler + storage abstraction

**files**: `chrome-extension/background.js`

**action**:
- Add helper `async function readStoredAuth()` that returns `{xbt_token, user_sub, api_token_id}` by reading `chrome.storage.local` first, falling back to `chrome.storage.session`. Returns nulls when neither is set.
- Modify `openBridgeWS()` to call `readStoredAuth()` instead of `chrome.storage.session.get(...)` directly.
- Modify the `chrome.storage.onChanged` listener to fire on changes in `local` OR `session` (use `areaName` argument).
- Add new message handler `MINT_AND_CONNECT`:
  1. Call `getGoogleIdToken()`.
  2. POST `https://api.grooveos.app/v1/me/api-token` body `{team_scope:"default", name:"chrome-extension"}` → capture `{id, token}`.
  3. GET `https://api.grooveos.app/v1/me` → capture `source_user_id`.
  4. `chrome.storage.local.set({xbt_token, user_sub, api_token_id})`.
  5. Reply `{ok: true, email: me.email, source_user_id}`.
  6. On any failure, reply `{ok: false, error: e.message}` — no throw.
- Add new message handler `DISCONNECT`:
  1. Read stored `xbt_token` + `api_token_id`.
  2. DELETE `https://api.grooveos.app/v1/me/api-token/{id}` (best-effort — ignore 404).
  3. `chrome.storage.local.remove(['xbt_token','user_sub','api_token_id'])`.
  4. Close `ws` if open (already idempotent via `storage.onChanged`).
  5. Reply `{ok: true}`.
- Keep all migrated French log/comment strings in English.

**verify**: open SW console, send `chrome.runtime.sendMessage({type:'MINT_AND_CONNECT'})` and confirm `{ok: true}` + storage populated.

**done**: New handlers exist, storage fallback works, no regression on existing `SEND_TO_BRAIN` / `GET_ID_TOKEN` / `ws_status_query`.
