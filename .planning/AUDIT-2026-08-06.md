## Tier 1 — act now, small, low risk

### Security — team-scope isolation is broken on two surfaces

The product's stated differentiator is `team_scope isolation (A≠B)`. It does not
hold on these routes: each reads `team_scope` from client input and uses it
without a membership check. Registration is **open in production** `[verified]`
(a probe account was created and deleted), so the only barrier — authentication
— is trivially passed; authentication IS enforced (junk token → 401), it is
**authorization** that is missing.

**memory-api (9 routes)** — ranked:

1. `[verified]` `routes/me.py:239` `POST /me/api-token` — writes `body.team_scope`
   into `user_api_tokens` with no membership check; `deps.py:426-430` then trusts
   that scope **forever** on a false premise ("minted by an admin path that
   validated it" — no such path exists). A durable, self-service token into any
   team. **Worst finding.**
2. `[reported]` `routes/agents.py:275` `POST /agents/{id}/invoke` — cross-team
   guard runs only for `kind=="bridge"`; a `kind=="user"` caller writes a
   memory_item into any `body.team_scope`.
3. `[reported]` `routes/team_chat.py:1207` `GET /teams/{id}/agent-context-bundle`
   — bridge-kind gate only; never compares the bridge JWT's own `team_scope`
   claim to the path `team_id`.
4. `[reported]` `routes/me.py:86` `POST /me/granola-key` — `body.team_scope`
   upserted with no check. Feeds #5.
5. `[reported]` `routes/granola_integration.py:209` `POST /integrations/granola/ingest`
   — the `if bridge_team and bridge_team != body.team_scope` guard is dead code
   (granola-sync's bridge JWT sets no `team_scope`), so the body value passes.
6. `[verified]` `routes/internal_github.py:128` `POST /internal/github/sync` —
   writes arbitrary GitHub content into any team's brain.
7. `[reported]` `routes/internal_github.py:195` `GET …/catalog` — reads
   `X-Team-Scope`/query raw, no membership check.
8. `[verified]` `routes/admin_projects.py:197` `GET /projects` — client query param
   bound straight into the WHERE; reads any team's project registry.
9. `[verified]` `routes/internal.py:26` `GET /internal/resolve-team-scope` —
   `principal` declared then never read; any user enumerates any other user's
   team slug + internal UUID.

**mcp-gateway (3 more)** `[reported]` — the isolation break is not only in
memory-api:

- `mcp-gateway/app/main.py:102` — on the Google OIDC path, `team_scope` comes
  from the unverified `X-Team-Scope` header; the "client cannot override scope"
  docstring holds only for bridge JWTs.
- `mcp-gateway/app/config.py:7` + `auth.py:48-54` — `BRIDGE_SHARED_SECRET`
  defaults to `""`; a missing var means the gateway accepts any token signed with
  the empty string (memory-api, correctly, refuses to boot without it).
- `granola_integration.py:233-237` — missing-claim path (same as #5).

**Fix shape:** `/internal/*` and the bundle require `kind=="bridge"` +
claim-vs-path comparison (`_require_bridge_principal` exists, used by
`boards.py`); user routes verify membership against `body.team_scope`;
`deps.py:426` stops trusting the xbt_ scope blindly; drop the `= ""` default on
`BRIDGE_SHARED_SECRET` across the six sidecars. Add an isolation test — a member
of team A can neither read nor write team B via each route. **No such test exists
today** (`test_team_isolation.py` covers only the bridge path; the xbt_ branch is
untested).

### Other Tier-1 (verified)

- `[verified]` **Realtime dies after 60 min, all users.** `packages/chat-core/realtime.js:287`
  builds Centrifuge with a static `token` and no `getToken`; the JWT `exp` is
  +3600s, so the socket drops at one hour and does not reconnect. The "reload the
  page" banner is this, not a transient. **Fix:** pass
  `getToken: () => api.centrifugoToken().then(t => t.token)`.
- `[verified]` **A verify script can delete production volumes.**
  `infrastructure/scripts/verify-phase16.sh:168` runs `down -v` from a
  `trap cleanup EXIT` (:173); the compose volumes are not `external: true`.
  `make verify-phase16/15/26` on the VM can wipe stopped volumes. **Fix:** mark
  volumes `external: true`, or drop `-v` from the three cleanup traps.
- `[reported]` **graphiti-service exposes port 8300 on 0.0.0.0 with both LLM keys.**
  `docker-compose.yml:1217`; every other service is `127.0.0.1:` or `expose:`.
  Docker's iptables bypass ufw. **Fix:** `127.0.0.1:8300:8300`.
- `[reported]` **`make sync` overwrites the VM `.env`.** `Makefile:14` RSYNC has no
  `--exclude='.env'`; the local `.env` (64 vars vs 166) is missing all five
  preflight-mandatory vars. This is the mechanism behind the "7 vars vanished"
  incident. **Fix:** `--exclude='.env'` in Makefile and `deploy-vm.sh`.

### Dependency ceilings — the crash-loop class

- `[verified, FIXED]` `mcp-github` carried unbounded `mcp>=1.27.0` — the sidecar
  the 2026-08-06 pin missed. Bounded in `d3b249e`.
- `[reported]` **`authlib>=1.3` unbounded in 10 services.** authlib 2.0 drops
  `authlib.jose`, imported by every bridge-JWT verify, the Centrifugo token mint,
  and `oauth_authorize.py`. Same crash class as mcp, but it takes the **whole
  auth layer** down at once on a rebuild. **Fix:** pin `authlib>=1.3,<2`
  everywhere now.
- `[reported]` `memory-api` `sqlalchemy`/`alembic`/`qdrant-client` unbounded
  (alembic runs migrations at boot); `brain-janitor` pins `qdrant-client==1.17.1`
  exactly while memory-api floats — two services, one Qdrant, independently
  resolved clients, on the library that already caused a silent-empty-recall bug.

## Tier 3 — real but plannable

- `[verified]` **`message_starred` is dead client-side.** `publication.js` handles
  `message`/`message_deleted` only; the server publishes `message_starred` (and my
  brain-tag work routes it to the owner channel) but no client renders it. Finish
  with the brain tag, or drop the type.
- `[reported]` **History/live render race.** `chat.js:632` subscribes, then awaits
  several sequential per-team unread calls before `loadInitialHistory` (which
  appends, never clears); a frame in that window pins above the whole thread.
  Same shape in `popup.js:910`. **Fix:** subscribe after history, or buffer+replay.
- `[reported]` **Inactive-team frames are dropped with no signal.** `realtime.js:334`
  discards non-active `team:` frames; rail badges refresh only on switch. On a
  multi-team product nothing tells you another team moved.
- `[reported]` **~25 bare `create_task` with no reference** (`team_chat.py:348,368,394,438`,
  `memory.py:384-392`, …) — CPython can GC a running task; symptom is "the agent
  didn't answer" with nothing logged. **Fix:** a module-level task set +
  `add_done_callback(discard)`.
- `[reported]` **The three red tests are stale tests, not broken code**, one-line
  fixes each: `test_team_context_cache.py` subscripts ORM objects (`team_a["slug"]`
  → `.slug`); `test_github_sync.py:379` expected uuid5 key missing the team_scope
  prefix; `test_admin_brain.py:428` lazy refresh outside greenlet (hoist
  `slug = team_a.slug` above the request). The `test_github_sync` one is also
  tracked in `27-.../deferred-items.md` as a uuid5 drift causing duplicate Qdrant

- `[reported]` **CI gates nothing client-side.** `ci-lockstep.yml` triggers on

- `[reported]` **Infra:** four MCP healthchecks are `|| exit 0` (never unhealthy);

  limit; declared `mem_limit` sums to 13 GiB on an 8 GB VM and `session-bridge`

## The brain-tag consistency question — owner decision needed

`[verified]` The private note is written to the team's brain as a `memory_item`
twin with full content (`brain_ingest` is deliberately ungated — the locked
decision is "the note lands in the team's brain"). But task 8's filter hid only
the `team_message` arm of the Brain Monitor feed, calling searchability "a worse
leak than the chat itself" — while the `memory_item` twin, same content, stays
searchable in that same feed (`LEFT(content,200)` preview, ILIKE). The copy and
the twin agree ("teammates can find the opening via search"); the task-8 filter
is the outlier.

- **(a)** the note is meant to be findable in the brain (matches the wording) →
  drop the task-8 `team_message` filter. **Orchestrator leans here.**
- **(b)** hide it from the member-facing feed, reachable only via the AI's
  `memory_search` → also filter the `memory_item` twin.
