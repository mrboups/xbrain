Authentication

Guide 5 min read Updated May 2026

GrooveOS uses GitHub as the primary identity. Signing in with GitHub gives you an xbrain personal API token (xbt_…), automatic membership in any team whose github_org matches one of your GitHub orgs, and your verified email attached to your user row so admins can invite you and notifications reach you.

Google sign-in remains available as a secondary option for legacy users and for users who only need Drive / Calendar sync. You can start with either, and link the other later — both identities resolve to the same user row.

Sign-in surfaces

Surface URL Notes
Web grooveos.app/account/teams/ "Sign in with GitHub" primary; "Sign in with Google" secondary.
Chrome extension extension popup "Sign in with GitHub" primary; silent on subsequent loads.
LibreChat chat.grooveos.app Google + GitHub buttons (Phase 5 SSO; independent from this flow).

Sign-in flow

  1. You click Sign in with GitHub. The app redirects you to github.com/login/oauth/authorize with scopes read:user, user:email, read:org.
  2. GitHub asks you to authorize GrooveOS (first time only) and redirects back with a one-time code.
  3. The browser sends the code to POST /v1/auth/github/signin. memory-api exchanges it for a GitHub access token, fetches your profile, your verified emails (/user/emails), and your orgs (/user/orgs).
  4. memory-api finds-or-creates your user row, runs the auto-grant pipeline against every team whose github_org matches one of your orgs, and returns an xbt_ personal API token.
  5. The browser / extension stores xbt_token, user_sub, api_token_id in local storage and reloads.

Org-driven team membership

Each xbrain team can declare a github_org field. When you sign in with GitHub, GrooveOS calls GitHub's /user/orgs API and adds you to every team whose github_org matches one of your orgs — no manual invite needed.

Admins of every team you auto-join receive an email titled "New member auto-joined <team>". If your sign-up is unexpected, they can block you (see below) and the membership is revoked.

SMTP is optional

If SMTP_HOST is empty on the deployment, the admin email is silently skipped (fail-soft) — the auto-grant itself still fires. Self-hosters can configure SMTP later without re-running migrations.

Blocking

Team admins can block a member at any time from the Settings card on the /account/teams/ page or from the Options tab of the Chrome extension. Blocked users receive HTTP 403 with body "Member blocked from team …" on every team-scoped API call, including requests authenticated with a pre-block-time xbt_ token.

Admins can also pre-block a GitHub login that hasn't signed up yet. Pre-blocks are stored in team_org_blocks and consulted by the auto-grant pipeline before any membership row is inserted — even if the GitHub user is in the team's github_org, a pre-blocked login is skipped.

Identity merge

GrooveOS treats GitHub identity and Google identity as two facets of the same user. The merge logic handles three scenarios:

Scenario Behavior
You signed in with Google first, then sign in with GitHub using the same verified email Your GitHub identity (github_id, github_username) attaches to your existing Google row. No duplicate user is created.
You signed in with GitHub-only (via the extension) first, then sign in with Google using the matching verified email The orphan GitHub-only row is auto-merged into your Google row. All team memberships, conversations, memory items, API tokens, and Drive sync state re-parent to the surviving row. The orphan row is soft-deleted (merged_into_user_id set).
Pre-merge xbt_ token: you saved an xbt_ in your extension before the merge happened The token keeps working. The auth layer follows merged_into_user_id and resolves to the surviving identity for every subsequent request — no need to re-sign-in.

The merge is atomic

If anything fails partway through (FK constraint, unique violation, network blip), the entire merge is rolled back. You'll either land on the merged survivor row or remain unchanged — never in a half-merged state.

Tokens

Every authenticated user surface in GrooveOS — Chrome extension, app-site, direct API calls — uses an xbt_ personal API token under the hood. The token is bound to a single user row and is automatically followed across identity merges via merged_into_user_id.

You can list, name, and revoke your tokens from the API reference (API Reference) under /v1/me/api-token. Tokens with team_scope set to a specific team enforce the per-team blocked-member check (HTTP 403 if you've been blocked from that team).
